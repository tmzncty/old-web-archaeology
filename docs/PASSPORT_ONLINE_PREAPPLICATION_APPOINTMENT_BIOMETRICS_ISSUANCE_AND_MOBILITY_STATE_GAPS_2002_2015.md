# Passport online pre-application, appointment, biometrics, issuance and mobility state gaps (China, 2002–2015)

## Scope

This note reconstructs a narrow old-Web transaction problem:

> when a 2002–2015 Chinese source says a passport could be “applied for online”, “reserved online”, or handled through an “online service hall”, what had actually happened in the transaction?

The main object remains the Chinese Web and hybrid e-government environment of roughly 2002–2015.

This is **not** a general history of Chinese passports, outbound tourism, visas, border control, or global passport systems. Earlier non-Web history appears only where needed to define what the Web did and did not replace. Later developments appear only as afterlife checks.

Life-course companion:

- <https://github.com/tmzncty/how-people-lived/blob/main/topics/passport-as-mobility-option-locality-online-appointment-and-outbound-future-china-1984-2026.zh-CN.md>

## 1. Core warning: “online passport application” is usually not one state

A historically defensible transaction model is:

```text
public guidance page exists
→ applicant reaches the correct jurisdiction/service
→ eligibility rules understood
→ form fields entered
→ pre-application submitted
→ backend identity / hukou / other eligibility checks run
→ pre-review result returned
→ appointment slot selected
→ appointment record stored
→ applicant physically appears
→ identity documents inspected
→ photograph captured / accepted
→ fingerprint + signature captured where required
→ formal case accepted
→ adjudication / approval
→ production
→ pickup or delivery chosen
→ document physically delivered
→ passport valid in holder's possession
→ visa / destination authorization obtained
→ trip actually occurs
```

The following equivalences are invalid unless separately proved:

```text
site visible ≠ transaction service live
online form visible ≠ online submission accepted
pre-application submitted ≠ pre-review passed
pre-review passed ≠ appointment stored
appointment stored ≠ applicant appeared
applicant appeared ≠ formal case accepted
formal case accepted ≠ passport approved
passport approved ≠ passport produced
passport produced ≠ document delivered
passport delivered ≠ visa granted
passport valid ≠ border crossing occurred
```

The central archaeological problem is that the **public page and locator are much more likely to survive than the transient backend states that actually determined whether a person got a passport.**

## 2. Boundary before the Web: passport simplification did not begin online

### 2.1 2002 Shanghai “on-demand” reform was a legal/administrative change, not proof of Web self-service

A 2002 Xinhua report preserved by Sina described Shanghai's expansion of “按需申领护照”: residents generally could apply with identity card and household-registration material, without the previous package of overseas invitation and work-unit/local-police approval material.

Source:

- Xinhua, 2002-08-29: <https://news.sina.com.cn/c/2002-08-29/1826697371.html>

This source establishes a **transaction-rule change**.

It does **not** establish that a Shanghai resident in September 2002 could:

- submit the passport application through a household Web browser;
- reserve a slot online;
- upload a legally sufficient photo online;
- complete identity verification remotely;
- receive a digitally issued passport.

Therefore:

> **policy simplification ≠ Web self-service.**

This boundary matters because later histories often collapse “on-demand issuance”, “electronic government”, and “online application” into one modernization story.

## 3. 2002–2007: identity and locality remain mostly off-page

The Passport Law and ordinary-passport administrative rules eventually standardized issuance deadlines and application authority, while the ordinary application still fundamentally referred the applicant to the exit-entry authority associated with the place of household registration and required the person to apply with identity materials.

Institutional source:

- Ministry of Justice republication of ordinary-passport issuance rules: <https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/200804/t20080402_144481.html>

For old-Web reconstruction, this creates a critical distinction:

```text
Web page says “passport service available”
    ↓
Which population?
    ↓
local hukou resident?
nonlocal worker?
student?
registered state employee?
minor?
first-time applicant?
replacement applicant?
```

A generic “passport” menu item cannot be treated as evidence that every visitor to the website could execute the same route.

### State gap: website jurisdiction / applicant jurisdiction

A page may be nationally reachable while the underlying transaction remains locally jurisdiction-bound.

Therefore:

> **publicly reachable URL ≠ geographically portable administrative authority.**

## 4. 2012 electronic ordinary passport: a digital document creates a new physical capture state

### 4.1 Electronic passport launch

China began issuing electronic ordinary passports nationwide on 15 May 2012. Contemporary reports describe an embedded electronic chip and the collection of biometric/identity data.

Contemporary sources:

- 2012-05-16, Xinjiang first e-passport: <https://news.sina.com.cn/c/2012-05-16/014024421282.shtml>
- 2012-05-04, Shanghai rollout notice preserved by the Internet Society of China: <https://www.isc.org.cn/article/20288.html>

For applicants aged 16 or older, fingerprint collection became an in-person application-stage event.

This creates a key anti-linear finding:

> **more digital document infrastructure did not mean fewer bodily identity steps at every stage.**

A Web reconstruction must therefore distinguish:

```text
photo known to the system
≠ live identity confirmed
≠ fingerprint captured
≠ signature captured
≠ biometric data successfully written into the passport-production workflow
```

### State gap: online identity fields / embodied identity verification

A user can type a name, ID number, address, and contact details into a browser while the state still requires the person's body at a counter before formal acceptance.

This is one of the clearest examples in the repo of:

> **backend digitization + embodied verification coexisting.**

## 5. Beijing 2012–2013: “online application” is better reconstructed as pre-application + verification + appointment

### 5.1 Non-Beijing applicants: online pre-application was already part of an eligibility-check pipeline

Contemporary 2013 reporting states that before Beijing opened the appointment route to local-hukou residents in June 2013, some non-Beijing workers and enrolled university students had already been using an online pre-application route.

For nonlocal applicants, the online stage could involve backend checks against household-registration and social-insurance/eligibility information before a field appointment.

Contemporary source:

- New Beijing News, 2013-05-28, preserved by People.com.cn: <https://www.people.com.cn/24hour/n/2013/0528/c25408-21636069.html>

This is not merely an appointment calendar.

The transaction may be modeled as:

```text
applicant enters identity / eligibility data
→ backend compares records
→ eligibility/pre-review result
→ appointment becomes available
→ applicant attends in person
→ biometric + documentary checks
→ formal case acceptance
```

Therefore:

> **online pre-application ≠ already accepted passport application.**

### 5.2 Beijing local residents from 1 June 2013

Contemporary reporting states that Beijing-hukou residents could use the Beijing Public Security Bureau website, enter the exit-entry online service hall, fill in the application data, receive backend comparison/review, and reserve a time and place.

Contemporary historical locator:

```text
www.bjgaj.gov.cn
```

The contemporary article explicitly identifies the site as “首都之窗——北京市公安局网站（www.bjgaj.gov.cn）” and the service as “出入境管理办事大厅”.

Sources:

- Beijing Daily, 2013-05-28: <https://news.sina.com.cn/c/2013-05-28/025927240568.shtml>
- Jinghua Times, 2013-05-28, preserved by People.com.cn: <https://politics.people.com.cn/n/2013/0528/c1001-21634859.html>
- New Beijing News, 2013-05-28, preserved by People.com.cn: <https://www.people.com.cn/24hour/n/2013/0528/c25408-21636069.html>

Reports described the backend identity comparison as capable of returning very quickly—sometimes around ten seconds for basic data.

That speed must not be confused with passport issuance speed.

### State model

```text
browser session starts
→ applicant enters basic data
→ server-side comparison
→ pre-review success/failure
→ date/location choices rendered
→ appointment request submitted
→ appointment stored
→ user receives confirmation
→ user later appears at service point
→ identity/biometric capture
→ formal acceptance
→ document-production workflow
```

A screenshot at any one stage cannot prove the next stage.

## 6. “预约成功” is a particularly dangerous historical artifact

### 6.1 An appointment is a reserved future opportunity, not a completed administrative act

Contemporary follow-up reporting on Beijing's expansion of appointment service points noted that not every appointment became a formally accepted case. Some people changed their travel plans; some application information was inaccurate.

This means the system preserved a category that old-Web research should explicitly recognize:

> **abandoned future transaction / 被放弃的未来事务**

Possible states include:

```text
appointment created
appointment still active
appointment cancelled by user
appointment expired/no-show
applicant appeared but documents/data failed
applicant appeared and formal case accepted
```

A web archive is structurally more likely to retain a generic “预约成功” template than the later status change of one real appointment.

### 6.2 Negative states are historically under-preserved

The most socially informative cases may be:

- “I filled it out but did not go.”
- “My trip was cancelled.”
- “The backend said my social-insurance condition could not be verified.”
- “The form contained a data error.”
- “I arrived, but the field office would not accept the case.”

These often produce transient authenticated screens rather than public pages.

This is the same preservation bias seen elsewhere in this repository:

> **published interface survives better than failed execution.**

## 7. Physical routing after online appointment: transaction stages can be distributed across locations

Contemporary Beijing reports in 2013 describe appointment-only service at additional police stations and later pickup/delivery arrangements.

This means one passport case could be spatially distributed:

```text
home/work PC
→ online pre-review
→ chosen police station / exit-entry counter
→ central adjudication/production
→ pickup point or EMS delivery address
```

Old-Web interpretation must not assume:

> the server host, field office, adjudicating office, and document-production site were one institution in one building.

A public website can coordinate several administrative locations without exposing their backend topology.

## 8. Shanghai 2013: official evidence for an exit-entry e-government platform, but not an original page capture

Shanghai Public Security Bureau's 2013 government-information annual report records operation of the police website:

```text
www.police.sh.cn
```

and describes continued development of online public-service functions, including an upgraded exit-entry e-government platform and self-service appointment functions for exit-entry documents.

A-level institutional source:

- Shanghai Municipal Government, 2013 Shanghai Public Security Bureau information-disclosure annual report: <https://www.shanghai.gov.cn/nw31917/20200820/0001-31917_38323.html>

This source can establish:

- the host name as a historically named official public website;
- institutional existence of an exit-entry e-government platform;
- official recognition of online appointment/self-service functions.

It cannot establish, without a historical capture:

- the exact 2013 DOM;
- the response charset;
- HTML `form` actions;
- frame structure;
- JavaScript dependencies;
- session timeout;
- browser sniffing;
- ActiveX requirements, if any;
- exact form field names;
- exact validation messages;
- backend endpoint paths;
- cookie behavior;
- whether every route named in the annual report was publicly accessible from an unauthenticated browser.

### State gap: modern-CMS-preserved annual report / historical application

The annual report now resides on a modern Shanghai government host.

Therefore:

> **a modern CMS preserving a 2013 institutional statement ≠ the 2013 service application itself surviving.**

## 9. What online appointment changed—and what it did not

### 9.1 It moved queue ownership into a database

Before appointment systems, an applicant might spend physical time holding a place in a hall.

With online reservation:

```text
physical waiting before service day
→ partly becomes
future time-slot reservation in a database
```

This is a real change in ordinary life even when final issuance remains offline.

### 9.2 It did not make the passport an online-only artifact

The user still interacted with:

- a physical identity card or household-registration record;
- a staffed public-security office;
- a camera/photo process;
- fingerprint capture for e-passports;
- a physical booklet;
- pickup or postal delivery.

So the correct model is **hybrid transaction**, not “Web replaces office”.

### 9.3 It created new failure classes

Web-based pre-application introduced failure modes that a simple walk-in queue did not have in the same form:

- data mismatch;
- eligibility-database mismatch;
- server or session failure;
- appointment inventory exhausted;
- applicant cannot retrieve confirmation;
- browser/client incompatibility;
- appointment stored but later abandoned.

The existence of these classes is analytically defensible. Their exact 2013 implementation details remain unknown until historical runtime/capture evidence is recovered.

## 14. Privacy boundary

Passport systems involve highly sensitive personal data.

Even if a future archive, screenshot, cache, forum attachment, or leaked historical page contains real applicant data, this project should not republish:

- identity-card numbers;
- passport numbers;
- home addresses;
- phone numbers;
- birth dates when person-identifying;
- fingerprint/biometric templates;
- application serial numbers tied to identifiable people;
- appointment tokens;
- authentication cookies;
- session parameters;
- full query strings containing personal fields.

Preferred evidence:

- blank forms;
- official help pages;
- anonymous screenshots;
- field schema;
- status labels;
- generic error messages;
- public institutional descriptions;
- redacted transaction examples where necessary.

The archaeological objective is to recover the transaction model, not to re-expose an ordinary person's identity trail.

## 15. Afterlife boundary: why 2019 and 2024 matter only as interpretive checks

The main research scope ends at 2015, but later reforms clarify what older systems did not yet provide.

### 2019 national portability

From 1 April 2019, ordinary passport applications became nationally portable across exit-entry service windows, removing the earlier household-registration/locality constraint for ordinary residents.

Official source:

- National Immigration Administration, 2019-03-26: <https://www.nia.gov.cn/n741440/n741577/c1015032/content.html>

This later reform is evidence that a 2013 online service reachable from anywhere should **not** be assumed to have possessed nationwide administrative portability.

### 2024 full-online replacement/reissue

From May 2024, selected cities began piloting full-online replacement/reissue for eligible applicants with prior passport/fingerprint records.

Contemporary source:

- People.com.cn Sichuan, 2024-05-08: <https://sc.people.com.cn/n2/2024/0508/c345509-40836145.html>

This later reform is evidence that 2013 “网上申请/预约” should **not** be back-described as modern full-online issuance.

Afterlife evidence is used only to sharpen state boundaries; it is not allowed to rewrite the 2002–2015 object in later terminology.

## 16. What survives vs what disappears

### Likely to survive

- policy notices;
- annual reports;
- service names;
- public host names;
- media screenshots;
- instructions;
- office addresses;
- generic application flow diagrams;
- press descriptions of response time.

### Likely to disappear

- live slot inventory;
- pre-review rejection states;
- authenticated user dashboards;
- failed validation messages;
- social-insurance/hukou cross-check results;
- cancelled appointments;
- no-shows;
- production queues;
- temporary download/print pages;
- cookies and sessions;
- backend interface contracts;
- actual time between stages for ordinary users.

This produces a strong historical-visibility bias:

> **the Web preserves what a service promised more easily than what happened to a specific transaction.**

## 17. Claims that are safe now

### Established

- Shanghai's 2002 passport simplification was an administrative-policy change and should not be equated with online completion.
- China introduced electronic ordinary passports nationwide in May 2012, adding biometric capture including fingerprint collection for adult applicants.
- Beijing in 2013 used a Web-based pre-application/appointment workflow for passport and related exit-entry documents.
- Contemporary sources identify `www.bjgaj.gov.cn` as the relevant Beijing Public Security Bureau public locator and refer to an exit-entry online service hall.
- Applicant data could be compared against backend records before field service.
- Applicants still needed a physical field-office stage.
- Shanghai's official 2013 annual report records `www.police.sh.cn` and an exit-entry e-government/self-service appointment platform.
- A historical locator or modern-preserved annual report is not a verified historical application capture.

### Probable but not yet runtime-verified

- the Beijing/Shanghai applications used session-bound dynamic form state;
- appointment inventory was dynamically generated from backend capacity;
- authenticated/transient failure states were substantially under-archived.

These are reasonable engineering expectations but remain `probable`, not `proven`.

### Unknown

- exact historical HTML/JS implementation;
- browser/plugin requirements;
- original response encoding;
- internal service topology;
- exact error/retry semantics;
- historical archive replay completeness;
- user-level conversion rate from online pre-application to issued passport.

## 18. Why this matters to old-Web archaeology

The passport case exposes a recurring error in histories of Chinese e-government:

> a journalist says “网上申请” and a later researcher rewrites it as “the transaction moved online”.

But the actual change was usually narrower and more interesting:

```text
information lookup moved online
then
form preparation moved online
then
eligibility pre-check moved online
then
queue reservation moved online
then
status query / delivery selection moved online
while
identity, biometrics and formal acceptance remained physical
```

The Web did not simply replace a window.

It **repartitioned the window into states**.

That is precisely the kind of object this repository should preserve: not a nostalgic screenshot of a 2013 government page, but a defensible account of which parts of an ordinary person's transaction were actually inside the browser, which remained in databases invisible to the user, and which still required a body to appear at a counter.
