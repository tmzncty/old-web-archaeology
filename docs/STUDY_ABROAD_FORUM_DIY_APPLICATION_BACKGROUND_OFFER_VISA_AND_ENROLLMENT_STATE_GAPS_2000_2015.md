# Study-abroad forum / DIY application / background / offer / visa / enrollment state gaps（2000—2015）

## 0. Scope

本 note 研究约 2000—2015 年中文 Web 中与出国留学相关的论坛、申请攻略、背景帖、offer/ad 汇报、签证讨论和 peer-produced admissions infrastructure。

研究重点不是写“中国留学史”，也不是把 `old-web-archaeology` 改造成全球招生网站考古仓库，而是回答：

> **当中文互联网开始帮助普通申请者理解国外大学、考试和签证系统时，历史网页究竟能证明一次跨国教育事务的哪一段？哪些关键状态发生在外国学校、考试机构、银行、邮政、邮箱、电话、QQ/MSN、使领馆和现实移动中，天然不会被中文 Web archive 完整保存？**

1980s 的自费留学政策、纸质申请、邮政/电话前史，以及 2016—2026 的移动端留学服务、多国联申和疫情后风险配置，主要写入交叉专题：

- `how-people-lived/topics/from-mailed-applications-to-diy-forums-and-multi-country-portfolios-study-abroad-executability-overseas-future-addressability-and-geographic-optionality-china-1981-2026.zh-CN.md`

本文件主范围保持在 2000—2015 中文互联网，并只保留理解该 Web 生态所需的前史/后史边界。

---

## 1. Research unit：不能把“论坛上说拿到 offer”直接写成“已赴该校留学”

至少拆开以下对象：

1. **physical applicant**：现实中的申请者；
2. **forum account / nickname**：寄托、ChaseDream、太傻等平台账号；
3. **self-reported background**：用户自报 GPA、G/T、学校、科研、工作经验；
4. **discussion thread / post**：攻略、求助、签经、飞跃感想等具体页面；
5. **school/program target**：现实中的国外学校与项目；
6. **test registration account**：TOEFL/GRE/IELTS 等考试账户/报名记录；
7. **test seat / registration state**：真实考位与报名状态；
8. **application account**：外国大学/申请系统中的正式申请账户；
9. **application package**：成绩单、推荐信、文书、语言/GRE 成绩等；
10. **application submission**：申请系统或纸件提交；
11. **application fee state**：申请费是否支付/到账；
12. **materials-complete state**：学校是否把材料匹配并认定完整；
13. **admission decision**：正式录取/拒绝/候补；
14. **funding state**：奖学金、RA/TA/Fellowship、学费减免等；
15. **self-reported AD/OFFER**：论坛用户对结果的社区化分类；
16. **visa application / decision**：签证申请与结果；
17. **travel / border state**：机票、边境、实际入境；
18. **physical enrollment**：学生真正到校注册；
19. **later transfer / dropout / completion**：转学、退学、毕业等后续状态。

最低状态链：

`forum account exists` ≠ `self-reported background verified` ≠ `school/program actually applied` ≠ `application submitted` ≠ `fee received` ≠ `materials complete` ≠ `admitted` ≠ `funded` ≠ `visa issued` ≠ `travel occurred` ≠ `student enrolled` ≠ `degree completed`。

对中文论坛还必须再拆一条：

`historical post text/date survives on current site` ≠ `historical page capture verified` ≠ `current DOM/layout equals historical DOM/layout`。

## 2. Evidence baseline

沿用 `docs/METHOD.md`：

- **A**：历史 capture、同时代官方页面/手册/原始技术资料；
- **B**：同期新闻、教程、用户操作说明、论坛讨论；
- **C**：后来回忆或平台自述历史；
- **D**：研究者复原/推断。

本轮有一批非常有价值的**平台当前仍保存的历史帖子**。它们与 Wayback capture 不同：

- 发帖时间、帖子文字、楼层关系可能由平台数据库长期保存；
- 但页面现在呈现的模板、CSS、头像、UID 模块、链接重写、分页、字符编码和 JavaScript 很可能是后来的平台状态；
- 因此可以用来研究“当时用户写了什么”，但不能把当前截图标成“2003 年网页原貌”。

本轮把这类材料标作 **A-/B+ platform-preserved historical record**，并单独保留 rendering uncertainty。

### 当前得到的 historical original hosts / URL locators

至少包括：

- `http://www.gter.net/`
- `http://bbs.gter.net/`
- `http://www.chasedream.com/`
- `http://forum.chasedream.com/dispbbs.asp?boardID=13&ID=...`
- `http://www.taisha.org/`
- `http://www.bj262toefl.com.cn/`
- 2003 TOEFL 帖中的 `http://www.sirenisland.com/` 及历史 BBS 路径

这些是由同期帖子/页面或后来站点谱系材料支持的 locator，**不等于本轮已经核验 archive capture**。

## 3. 2000—2004：中文论坛首先成为国外制度的“翻译层”

### 3.1 寄托/ChaseDream 的历史意义不只是“有论坛”

寄托当前的站点介绍把 `gter.net` 创办时间写为 2000 年 4 月，并把 GRE、TOEFL、申请、海外生活与 DIY 作为长期核心主题。

来源：
- https://about.gter.net/about.html

**证据等级：C/平台自述。** 可作站点谱系线索，不能替代 2000 年同时代 capture。

ChaseDream 2004-10-29 的站内介绍则更接近同期，称网站于 2003 年 3 月建立，围绕 GMAT、商学院申请、录取者经验、offer 信息与线下活动组织社区。

来源：
- https://www.chasedream.com/article/NReNo

**证据等级：A-。** 同期平台自述。

从 old-Web 角度看，关键变化不是“网上出现一个留学栏目”，而是形成了一种 **Chinese shadow admissions infrastructure**：

`foreign university / ETS / visa rules`

→ `Chinese forum translation/explanation`

→ `applicant questions`

→ `peer correction / examples`

→ `self-reported outcomes`

→ `later applicants reuse the corpus`。

论坛本身没有招生权，却可能变成申请人日常决策中非常重要的导航层。

### 3.2 “DIY”不能被理解成“一个人单独做完”

很多 2000s 论坛文化把 DIY 与中介路线对举。但技术上更准确的是：

`DIY applicant != solitary applicant`。

一个用户即使没有付费把全流程外包，也可能依赖：

- 前辈整理的学校清单；
- 考试报名攻略；
- SOP/CV/推荐信讨论；
- offer/ad 背景帖；
- 签证经验；
- QQ 群/论坛私信；
- 校友帮忙解释学校内部流程；
- 同学替收/寄材料。

因此论坛应被研究为**分布式、非官方、以免费/互助为主的申请劳动基础设施**，而不只是一类“内容网站”。

## 4. 2003 TOEFL 报名攻略：Web 只是跨媒介 transaction 中的一段

寄托当前仍保留一篇标注 2003-11-29 的《TOEFL 报名攻略》。页面正文列出多场考试的 `Mail Registration Deadline` 与 `Online Registration Deadline`。

对北京以外考点，帖子描述的流程包括：

1. 决定考期；
2. 电话联系考点确认领表时间；
3. 带报名费、照片、身份证去排队领表；
4. 用 HB/2B 铅笔填写机器可读纸质报名表；
5. 现场交表，或连同汇款/介绍信挂号寄回；
6. 等待后续成绩与寄送。

北京部分则留下历史入口 `http://www.bj262toefl.com.cn`，流程包括先在网页预约、等待确认，再去银行缴费、领取/接收纸表、提交材料，并通过网络或电话查询。

来源：
- https://bbs.gter.net/thread-152151-1-1.html

**证据等级：A-/B+。** 历史帖子当前仍由平台保存；当前渲染不是已验证 2003 capture。

### 4.1 必须拆出的状态

`test date exists` ≠ `seat exists` ≠ `online reservation submitted` ≠ `reservation retained` ≠ `bank payment completed` ≠ `paper form obtained` ≠ `paper form correctly filled` ≠ `materials delivered` ≠ `registration accepted` ≠ `candidate attended exam`。

### 4.2 关键 archive gap：guidance survives / transaction state disappears

未来即使这篇攻略永久存活，也无法从它重建某一个申请者：

- 当天是否抢到考位；
- 银行是否成功入账；
- 纸表是否寄失；
- 考试中心是否认定填写有效；
- 最终是否到考场。

这类动态事务状态主要存在于考试机构后台、银行、邮政、电话和个人纸件中。

### 4.3 关键 rendering gap：current thread != 2003 page

当前 `bbs.gter.net` 页面能够显示 2003 年正文和历史时间戳，但页面同时展示今天的平台导航、用户资料模块、当前图床/脚本等信息。除非取得实际历史 capture，否则不能据当前 DOM 推断：

- 2003 年使用何种 Discuz!/其他论坛版本；
- charset 是 GB2312、GBK 还是其他；
- 当时是否存在相同 CSS/分页；
- 链接当时是否已经是当前形式；
- 旧浏览器下实际呈现如何。

以上全部保持 **UNKNOWN**。

## 5. 2004—2006 ChaseDream：申请知识开始被主动做成代际传递

ChaseDream 2006 年的一篇站内文章说明，从 2003 年起站点会采访成功申请者，要求他们把经验分享给后来者；页面保留了一组旧论坛 URL pattern，例如：

- `forum.chasedream.com/dispbbs.asp?boardid=13&id=22170`
- `forum.chasedream.com/dispbbs.asp?boardID=13&ID=76763`
- `forum.chasedream.com/dispbbs.asp?boardID=13&ID=149079`
- feedback 所在 `boardID=28...`

来源：
- https://www.chasedream.com/article/jPlxj

**证据等级：A-。** 2006 同期站内文章，可证明当时站点如何组织分享，以及历史 URL pattern 的存在。

这类内容意味着论坛已经不只是随机问答，而是在主动生产“上一届 → 下一届”的申请记忆。

### 5.1 archive 意义：旧 URL pattern 比今天导航更有价值

当前 ChaseDream 页面可能已经迁移到新的 URL、模板和论坛系统；而同期文章嵌入的 `dispbbs.asp?boardID=...&ID=...` 提供了一个非常具体的 old-Web locator。

下一步 M1 应优先用这些 exact pattern 去检查：

- original URL；
- capture datetime；
- HTTP/replay；
- Content-Type/charset；
- ASP 页面参数是否参与内容选择；
- 图片/样式/脚本子资源；
- 至少第二历史时点。

在此之前，不能把当前迁移后的文章页当成 2006 原貌。

## 6. 2008—2009 offer/ad “龙虎榜”：同伴开始自己制造一份准数据库

寄托 2008-11-20 发布的“2009 美国留学版龙虎榜”要求申请者拿到结果后汇报：

- 时间；
- 学校；
- 专业；
- Offer / AD；
- MS / PhD；
- 奖学金种类；
- 本人学历、GPA、GRE/TOEFL、科研经历、是否套磁。

版主再按 AD、OFFER 和专业整理。

来源：
- https://bbs.gter.net/thread-894763-1-1.html

**证据等级：A-/B+。** 当前平台保存的历史帖子。

这是一种非常值得旧网考古的页面形态：**用户自报 → 版主人工结构化 → 后来者比较**。

它既不是学校官方数据库，也不是今天意义上的结构化招生数据平台，却承担了类似“结果样本库”的功能。

### 6.1 `self-reported background != verified credential`

一条“本科 211 / GPA 3.3 / T 101 / 两篇 paper”的论坛记录只能证明发帖者如此声称，不能自动验证：

- 成绩单真实数值；
- 考试官方分数；
- 论文身份；
- 申请材料是否与帖子一致。

除非有独立官方证据，否则应该保留 **self-reported** 标签。

### 6.2 `AD / OFFER` 是社区语义，不是跨学校统一 schema

龙虎榜自己还需要定义：达到一定奖学金/减免条件者归入 offer，其他录取归入 AD。这已经证明 `AD` / `OFFER` 在论坛中具有社区化分类规则。

因此 old-Web 研究不能把 2009 寄托的 `OFFER` 机械翻译成所有学校官方文书中的 “offer of admission”。

### 6.3 success-board survivorship bias

结果榜天然更容易留下：

- 有结果的人；
- 愿意汇报的人；
- 较好结果和奖学金；
- 仍活跃于社区的人。

更容易缺失：

- 全拒；
- 申请中途停止；
- 因经济原因不去；
- 没有拿到签证；
- 只潜水从不发帖的人。

所以：

`offer board composition != applicant outcome distribution`。

## 7. 2009：一个论坛帖子可以证明计划如何变化，却仍不能证明最终现实状态

寄托一名用户在 2009-12-20 发布“SFU CS 春季 英国申加学生签成功 申请+签经”。他自述：本科在北邮，2008 年去伦敦读一年硕士；女友去温哥华 SFU 读两年硕士。去温哥华探访后，因为两人暂时都不想回国且希望在一起，他决定申请 SFU CS；最初考虑 2009 秋季，但回伦敦时已经接近 2 月 1 日截止日，后来改申 2010 春季，并利用英国硕士成绩。

来源：
- https://bbs.gter.net/thread-1043339-1-1.html

**证据等级：A-/B+，同时性第一人称。**

这条帖子能够支持：

- 发帖者当时如此描述自己的教育/关系/申请计划；
- deadline 与成绩可用时间确实进入其选择；
- 论坛承担“把曲折申请流程写给后来者”的功能。

它不能单独证明：

- 北邮/英国大学/SFU 的正式学籍记录；
- 女友现实身份；
- 最终是否按计划入读、毕业；
- 后来是否与女友继续关系；
- 其签证文书每一步的官方后台状态。

因此：

`contemporaneous self-report is rich life-history evidence`，但仍然 `!= verified administrative record`。

## 8. 2008 签证/转学讨论：论坛特别适合暴露“一个学生其实有多套身份状态”

2008 年寄托一条 F1 返签讨论中，发帖者称自己已有仍在有效期内的 F1 签证，但后来转校、转专业并更新 I-20，因此询问寒假回国后是否需要重新签证、SEVIS 状态会不会影响入境。

来源：
- https://bbs.gter.net/thread-880007-1-198.html

**证据等级：A-/B+，同期自述与论坛回答。** 回答本身不能自动视为法律权威。

这条材料非常适合建立身份状态拆分：

`visa sticker valid` ≠ `school unchanged` ≠ `program unchanged` ≠ `I-20 unchanged` ≠ `SEVIS state unchanged` ≠ `re-entry guaranteed`。

也因此，旧论坛里的“签证成功帖”并不是一个单状态 artifact。它往往只是整个国际学生身份机的一部分。

## 9. Chinese shadow infrastructure / foreign transaction split

这是本轮最重要的 old-Web 结构发现之一。

中文留学论坛最容易保存的是：

- 选校讨论；
- 背景；
- deadline；
- 文书经验；
- 签证问答；
- offer/ad 汇报；
- 飞跃感想。

但正式 transaction 常常发生在另一个网络空间：

- ETS / IELTS 等考试系统；
- 国外大学官网/申请 portal；
- 推荐人邮箱/推荐系统；
- 信用卡/银行；
- FedEx/邮政；
- 美国/加拿大/英国等签证系统；
- 使领馆现场；
- 航空公司；
- 国外学校注册系统。

因此，中文旧网考古即使保存非常完整，也可能只恢复“导航层”，而不是事务本体。

### 9.1 `Chinese guidance page survives / foreign target disappears`

一篇 2003 攻略可能完整保存当时的外部链接，但：

- foreign target URL 已迁移；
- application endpoint 需要 session；
- 第三方站点 robots/登录限制；
- 支付页面不会被 archive；
- 用户个人 application dashboard 从未公开。

结果是：**我们可以知道当时的人被告知“点击这里”，却未必还能看到点击以后发生了什么。**

### 9.2 中文 archive 不能代表整个 application transaction

必须抵制一种“Web 中心主义”：

> 因为论坛帖子保存下来了，所以申请流程已经被互联网完整记录。

实际上，它更像一个 shadow infrastructure：高度影响行动，但不是权威状态源。

## 10. Off-platform continuity loss：最关键的协作常常离开公开论坛

2000s 申请社区很容易从公开帖转到：

- QQ 群；
- QQ 私聊；
- MSN；
- Email；
- 电话；
- 附件；
- 线下讲座/聚会。

ChaseDream 2004 的站内介绍和后续文章已经显示，它不只运营 Web 论坛，也组织线下 workshop / 聚会，并通过成功申请者继续回馈社区。

因此 archive 应增加：

## `public-thread survival / coordination-channel loss asymmetry`

一个 BBS thread 也许留下“请私信我”“QQ群见”“邮件发模板”，但真正被交换的：

- SOP 文档；
- 推荐信模板；
- 录取信附件；
- 面试问题；
- 私人背景；
- 临时 deadline 提醒；

可能完全不在公开 Web 里。

不能因为公开页面没留下，就断言这些协作不存在。

---

## 11. User migration / platform migration：历史帖子活着，历史 Web 仍然可能已经死了

寄托的 2003/2008/2009 帖今天仍然可以访问，这是极有价值的保存结果。但必须区分：

`database record survived` 与 `historical web presentation survived`。

平台可能经历：

- 论坛软件升级；
- URL rewrite；
- HTTP → HTTPS；
- 编码迁移；
- 图片域名迁移；
- 用户资料字段变化；
- 旧附件丢失；
- 编辑时间更新；
- 分页算法改变；
- 搜索引擎重新索引。

当前页面“看起来像论坛”不能证明 2003 用户看见的就是这个页面。

### 11.1 当前渲染的可用范围

当前保存的历史帖子可以支持：

- 文本内容；
- 平台当前声称/展示的历史时间戳；
- thread ID；
- 当前可见楼层关系；
- 文本中留下的 old URL locator。

除非有历史 capture，否则不能支持：

- 当年页面截图；
- 当年 charset；
- IE/Netscape 兼容性；
- 当年 CSS；
- 当年广告/导航；
- 当年附件是否真正可下载；
- 当前 UID/用户字段是否完整等同当年。

## 12. “第一人称未来想象”为什么在论坛 archive 中既宝贵又危险

留学论坛留下了非常多“我明年想去哪里”“这个 offer 值不值得去”“我想留下还是回国”的同时性未来想象。与多年后成功者访谈相比，这类帖子有一个巨大优势：**它记录的是决定尚未发生时的不确定性。**

但它同样有强选择偏差：

- 愿意公开发帖的人更可见；
- 高教育、较强英语与 Internet access 是前置筛选；
- 论坛版块往往按美国/加拿大/商学院/研究生等群体分层；
- 失败结果可能更少回报；
- 删除号、匿名号、迁移失败账户会进一步改变样本。

因此后续若做大规模“未来想象”样本，不应把论坛帖子简单计数成民意调查，而应做**情境化 qualitative sample**。

## 14. 新增 archive bias / state-gap vocabulary

本轮新增以下可复用概念：

### `platform-record survival / historical-rendering loss`

平台数据库可能保住老帖正文和时间，而历史 HTML/CSS/编码/客户端环境已经丢失。

### `guidance survival / transaction-state loss`

攻略活着，不代表当年的考位、付款、材料匹配、录取或签证后台状态可恢复。

### `Chinese shadow infrastructure / foreign transaction split`

中文站点保存申请导航和同伴知识，正式事务却在国外系统、邮件、银行和线下完成。

### `offer-board survivorship bias`

成功/愿意汇报的人被版主结构化，失败、放弃和沉默者系统性缺失。

### `background self-report / credential-verification gap`

论坛背景字段可分析社区语言与比较逻辑，但不能视为已验证学历成绩数据库。

### `off-platform continuity loss`

论坛正文存活时，QQ/MSN/Email/电话/附件和线下协作可能已经完全不可见。

### `dead-target / surviving-guidance asymmetry`

中文攻略保存了历史链接，但真正的外部申请 endpoint、支付页或学校 portal 已迁移/消失。

### `application-page / enrollment-outcome gap`

即使一个申请者自报拿到录取，也不能从中文 Web 直接推断后来实际入学、转学、退学或毕业。

## 15. 与其他 old-Web 专题的交叉边界

本 note 与若干既有专题相邻，但不重复：

- **高考/志愿填报**专题研究国内招生信息、志愿确认与录取状态；这里研究跨国制度之间的导航层。
- **在线支付/网银**专题研究支付与清算；这里仅记录申请费/考试费是留学事务链中的一环。
- **公共终端/网吧**专题研究设备可及；这里不假定每位申请者家中拥有电脑。
- **教育凭证验证**专题研究学历证明可查询；这里主要看申请者如何把学历/成绩提交给国外系统。
- **航空/酒店**专题研究旅行执行；这里把机票/出行作为“录取之后仍未完成”的边界，不扩写交易细节。

这次真正新增的是：**一个中文社区如何成为外国制度的解释器，而 archive 又为何更容易保存解释器、保存不了正式 transaction。**

## 16. Privacy / ethics

留学论坛大量帖子包含：

- GPA / 考试分数；
- 本科学校；
- 专业；
- 录取结果；
- 签证情况；
- 伴侣位置；
- 邮箱/QQ/旧联系方式；
- 有时还有真实姓名或录取信片段。

本仓只保留支持平台结构和历史流程 claim 所需的最小信息，不批量搬运普通用户的完整背景表、联系方式、录取信或私人关系细节。

历史帖子仍公开可访问，也不意味着应该在仓库里重新聚合成可搜索个人档案。

## 17. 本轮改变了什么

以前讨论旧中文 Web，容易把留学论坛写成“很热门的教育论坛”。本轮更准确的结论是：

**它们是一种没有招生权、却真实参与招生事务执行的影子基础设施。**

它们把国外学校、ETS、签证规则、银行支付、邮寄材料和个人经验翻译成中文可操作知识；又把上一届申请者的结果重新做成下一届的经验数据。

但正因为它们处在 transaction 外围，Web archive 会产生一种很强的错觉：

> 我们能完整看到“大家当时怎么讨论申请”，于是误以为“我们也完整看见了申请本身”。

实际上最重要的正式状态——材料是否真的到达、资金是否足够、签证是否签发、身体是否入境、学生是否最后注册——往往都在中文公开 Web 之外。

这也是本 note 最核心的考古结论：

**中文旧网可以非常清楚地保存一代人如何学习“把远方变成选项”，却未必能保存那个选项最后有没有真的变成他们的生活。**

## 18. 下一步

优先级最高的下一步不是继续找更多成功经验帖，而是：

3. 尝试确认 `bj262toefl.com.cn` 的 2003—2004 capture 与其动态预约边界；
4. 寻找同时代“全拒/放弃/没钱去/签证失败”的论坛材料，以纠正成功榜的 archive bias；
5. 若能取得历史论坛页面，再测试 IE5/IE6 与现代 Chromium 的 rendering 差异。

在这些证据到位以前，本文件保持 **state-gap research note**，不升级为 M1 完整 case。
