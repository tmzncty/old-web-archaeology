# 骑行论坛、路线、游记与俱乐部：从网页计划到真实道路的状态缺口（2002—2015）

> Scope：只研究约 2002—2015 年中文 Web 中，自行车垂直站、论坛、路线帖、骑行游记、俱乐部页面与活动页怎样表示“我要去哪、和谁去、怎样去、骑过没有”，以及网页状态与真实道路、身体移动、活动到场之间的缺口。
>
> 不把本文件扩成中国自行车产业史，也不把 1980s 工具性自行车、1970s 美国 Bikecentennial、1990s Usenet 主线写进本仓。这些进入 companion：[`tmzncty/how-people-lived/topics/from-bicycle-utility-to-cycling-hobby-route-executability-and-self-authored-mobility-china-1979-2026.zh-CN.md`](https://github.com/tmzncty/how-people-lived/blob/main/topics/from-bicycle-utility-to-cycling-hobby-route-executability-and-self-authored-mobility-china-1979-2026.zh-CN.md)。
>
> 证据合同：遵循 [`METHOD.md`](METHOD.md)。尤其固定：**current legacy page ≠ historical capture；旧 URL 被今天页面引用 ≠ 该 URL 的历史响应已经验证。**

## 1. 研究单位：路线帖不是路线，游记也不是完整骑行日志

至少区分：

- platform / portal：自行车垂直站或社区品牌；
- host：`www.biketo.com`、历史 `www1` / `www2` 等 host；
- board / subforum；
- thread / post / reply；
- ride plan / 计划帖；
- route description / 路线说明；
- ride report / 游记；
- club page / club profile；
- event announcement / 活动公告；
- signup / RSVP；
- participant list；
- map / GPS / track object；
- attachment / photo / external image；
- QQ / phone / email / PM handoff；
- actual departure；
- actual route ridden；
- withdrawal / crash / detour；
- finish / return；
- later editorial republication；
- current live legacy page；
- historical archive capture。

最小状态机：

```text
产生骑行意图
→ 搜路线 / 游记 / 装备 / 俱乐部
→ 找到帖子或活动页
→ 判断时间、距离、道路、天气、装备
→ 发帖 / 回复 / 报名
→ 可能转 QQ / 电话 / 短信 / email 私下协调
→ 约定集合点
→ 实际出门
→ 到达集合点
→ 实际开始骑行
→ 路况 / 天气 / 身体 / 机械状态持续变化
→ 完成 / 改线 / 退出 / 事故
→ 回家
→ 可能写游记、上传图片、轨迹或结果
→ 以后被搜索 / 引用 / 编辑重新索引
```

因此固定：

```text
thread exists ≠ ride happened
route text exists ≠ road was rideable
plan published ≠ departure
signup ≠ attendance
attendance ≠ completion
ride report ≠ complete route history
photo exists ≠ full participant list
GPS link exists ≠ GPS object survives
club page exists ≠ club still active
forum username ≠ verified real-world rider identity
article republishes a thread title ≠ original thread preserved
current old article ≠ historical whole-page representation
```

## 2. 为什么骑行特别适合研究“屏幕—现实”缺口

很多论坛研究的现实链只需要到：

```text
发帖 → 回复
```

骑行却必须让网页最终离开屏幕，接到道路：

```text
网页描述路线
→ 人和车进入物理空间
→ 公路、施工、天气、补给、坡度、机械故障和身体状态开始决定结果
```

因此本题增加一个核心层：**route execution state / 路线执行状态**。

一份保存完整的 HTML 最多可以证明当时有人怎样描述或计划某条路线；它不能自己证明：

- 路真的按帖中描述走完；
- 中途没有绕行、弃骑或搭车；
- 页面写的时间、速度、距离经过独立验证；
- 几年后该路线仍相同；
- 发帖者和照片中的人一一对应；
- 活动报名者都到场。

特别是“中国第一家自行车 BBS”属于平台自己的优先权叙事，本仓不能直接升级成已证实结论。

固定：

```text

≠
historical capture
≠
independent proof of precedence / popularity
```

## 4. 2009 “躺车网址大全”：一页正文保存了一张已经部分失效的兴趣 Web 图谱

BIKETO 当前仍可访问一篇日期为 **2009-12-07** 的 legacy article：“躺车网址大全-大家共享的收藏,及时更新中”。正文把以下资源压到一页：

- BikeForest CAD / wheel / suspension tools；
- 多个站内“图纸”线程；
- 国际人力动力协会和各国组织；
- 外部技术站点；
- 多种车辆设计资料。

当前 legacy page：<https://www.biketo.com/racing/70.html>

更重要的是，正文保留了多种历史站内 URL 形态：

```text
http://www2.biketo.com/bbs/thread-79424-1-2.html
http://www2.biketo.com/bbs/thread-80020-1-1.html
http://www.biketo.com/bbs/viewthread.php?tid=70092&extra=&page=1
http://www.biketo.com/bbs/thread-83199-2-1.html
```

这是一条很有价值的 **host / URL-pattern genealogy lead**。

但当前页面只能支持：

> 今天的 BIKETO legacy renderer 保存了一篇标注 2009 日期、其中列出这些 URL 的文章。

它不能单独支持：

- 2009 年文章当日就在当前 URL 上以当前 DOM 展示；
- `www2.biketo.com` 的历史 thread 当时使用什么软件版本；
- `thread-*` 与 `viewthread.php?tid=*` 是否表示迁移、rewrite、不同论坛版本或并行 URL；
- 历史帖子正文、图片、附件今天还存在；
- 外部 CAD 页面在 2009 年的具体响应与今天一致。

因此增加：**forum-URL migration gap / 论坛 URL 迁移缺口**。

## 5. 2010 “101 篇游记”：编辑再索引保存了 locator，但不是原 thread archive

2010 年 5 月，BIKETO 编辑发布“值得收藏的 101 篇自行车旅行游记”，当前页面仍能看到大量精确旧 thread locator。例如第 2 页保留：

```text
08 新疆骑情
http://www.biketo.com/bbs/viewthread.php?tid=65737...

2009 单骑新藏线
http://www.biketo.com/bbs/viewthread.php?tid=82105...

08年4月川藏线骑行记
http://www.biketo.com/bbs/viewthread.php?tid=58214...
```

当前 legacy page：<https://www.biketo.com/tour/1528_2.html>

这里出现 **republication survival chain / 再发布存活链**：

```text
原论坛游记
→ 被编辑挑选
→ 标题 + locator 进入资讯文章
→ 原 thread 以后可能迁移 / 丢失
→ 编辑文章仍然让我们知道原对象曾经如何被索引
```

这种 survival 是“有损保存”。它可能保留：

- 标题；
- URL；
- 编辑当时认为它值得收藏的事实；
- 大致主题与年代。

却可能丢失：

- 完整正文；
- 回复；
- 编辑/删帖历史；
- 用户签名与注册状态；
- 图片与附件；
- 原分页；
- 私信/QQ 讨论；
- 真实路线的修改和退出状态。

固定：

> **editorial index survives ≠ original transaction survives**。

## 6. 2010 中法骑游活动：活动公告把 Web 接到签证、旅行与现实到场

2010 年 BIKETO 的“第72届国际联合自行车旅游周”页面保留了活动日期、地点、路线距离范围和论坛置顶帖 locator：

```text
http://www2.biketo.com/bbs/thread-92806-1-1.html
```

页面还说明此前“中国区 10 名骑友”已经完成签证准备。

当前 legacy page：<https://www.biketo.com/news/1220.html>

这类对象不能只用论坛 state machine。现实至少还包括：

```text
看到活动
→ 表达意向
→ 报名 / 选拔
→ 护照 / 签证 / 费用 / 假期
→ 机票 / 车辆运输
→ 抵达目的地
→ 实际每天出发
→ 完成某段路线
```

所以新增 **announcement-to-travel gap / 活动公告—真实旅行缺口**。

即使页面写“10 名骑友已经顺利出签”，也不能自动推导这 10 人最后都在所有骑行日实际到场或完成全部路线，除非有结果材料继续支持。

## 7. 旧骑行 Web 的核心 transaction 常发生在 Web 外

论坛通常可以公开看到：

- 发起人；
- 路线；
- 日期；
- 预计里程；
- 装备建议；
- 回复；
- 可能的参与者昵称。

但最后的协调非常可能转到：

```text
QQ
电话
短信
email
线下车店
集合点
```

因此增加 **public-thread / private-coordination gap / 公开帖—私下协调缺口**。

一个 thread 即使保存完整，也不能保证我们知道：

- 最终集合时间是否临时改变；
- 谁迟到 / 爽约；
- 路线是否因天气改变；
- 谁在 QQ 里退出；
- 领队是否电话通知改集合点。

这与本仓此前活动页、家政、二手交易等专题共享一种更一般的规律：

> Web 经常保存“公开可发现层”，却把决定 transaction 是否完成的最后一公里留在不可归档的私下通信里。

## 8. 路线帖具有特殊的“陈旧风险”

普通教程页面过时，可能只是软件版本不同；骑行路线过时，可能直接改变现实安全。

路线可执行性随时间变化：

- 道路新建 / 废弃；
- 高速化、机动车流量增加；
- 隧道、桥梁、施工；
- 山体滑坡；
- 补给点、旅店、修车店关闭；
- 管理规则变化；
- 季节 / 天气；
- 手机信号与救援条件。

因此：

```text
2008 ride report is preserved
≠
2015 reader can safely repeat the ride
```

增加 **route-freshness gap / 路线新鲜度缺口**。

旧网考古在引用路线时，应尽量标明：

- `route described at`；
- `ride date`；
- `publication date`；
- 是否为事前计划还是事后游记；
- 是否有后来修订；
- 当前是否仍可执行：默认 **unknown unless separately verified**。

## 9. 图片、地图、轨迹和附件比正文更脆弱

骑行游记的关键信息往往不只在文字：

- 路线图；
- 海拔图；
- GPS track；
- 路口照片；
- 住宿/补给照片；
- 车辆损坏照片；
- 外链相册；
- 论坛附件。

因此增加 **ride-report media survival gap / 骑行游记媒体存活缺口**。

至少拆：

```text
thread HTML survives?
→ inline image tag survives?
→ image bytes survive?
→ external host survives?
→ thumbnail only or original?
→ GPS/track link survives?
→ backend account/login required?
→ track metadata still available?
```

一篇只剩文字“见下图”的川藏游记，在 archive 意义上已经不是完整的骑行记录。

## 10. 动态路线与 GPS 服务会制造新的 backend gap

到 2010 年，中文骑行媒体已经开始报道带 GPS、并可通过 Internet 做数据分析的自行车设备。以后路线库、码表、运动 App 会进一步把：

```text
骑行身体行动
→ GPS points
→ 账户
→ 后台计算
→ 地图瓦片
→ 速度 / 距离 / 海拔
→ 分享页面
```

连接起来。

old-Web 只要涉及 2010—2015 早期动态路线/设备页，就必须警惕：一份静态 HTML 可能完全不包含真正的 track data。

增加：**dynamic-map/backend gap / 动态地图—后台数据缺口**。

## 11. 当前 legacy renderer 会把多个年代压成一页

今天打开 BIKETO 的 2009/2010 页面，可以同时看到：

```text
历史日期的文章正文
+ 当前站点导航
+ 当前评论/点赞/推荐组件
+ 当前 HTTPS / CDN / 图片路径
+ 后来重构的栏目结构
```

如果直接截整页并标“2010 年 BIKETO 页面”，会造成 **legacy-render temporal collapse / 遗留渲染的时间塌缩**。

因此任何 current legacy page 都要至少分：

- `content timestamp shown by current page`；
- `current access date`；
- `current host/path`；
- `historical original URL if known`；
- `historical capture verified? yes/no`；
- `current-only shell elements`；
- `unknown mutable elements`。

## 12. 俱乐部页面还存在，不等于这个俱乐部还活着

自行车网站会长期残留：

- 俱乐部介绍；
- 会员帖；
- 活动照片；
- 旧联系人；
- 一次性活动页。

但 organization state 至少要拆：

```text
page exists
→ club once claimed to exist
→ members actually active at that time?
→ ride calendar updated?
→ organizer reachable?
→ rides actually held?
→ club dissolved / renamed / migrated?
```

增加 **club-page / active-organization gap**。

这也涉及隐私：历史手机号、QQ、普通成员真实姓名即使仍可被 archive 读取，也不应因为考古而批量重新公开。优先只保存支持组织结构 claim 所需的最小信息。

## 13. 2002—2015 中文骑行 Web 的最小形态谱系（暂定）

根据当前可见材料，可以提出一个待验证而非已经封闭的谱系：

```text
个人/小型自行车论坛
→ 垂直 BBS 累积路线、游记、维修和装备知识
→ 编辑把论坛精华再索引成门户文章
→ 活动页把论坛连接到俱乐部、报名和现实骑行
→ GPS / 路线库 / 移动端逐渐把轨迹和数据放入账户型 backend
```

这里不是线性替代。

论坛在门户化以后仍可继续存在；线下车店、电话、QQ群和实体俱乐部也没有因为 Web 出现而消失。

## 15. M1 状态：本轮明确没有达成 verified capture 门槛

本轮虽然已经有：

- 精确历史 thread locators；
- 多个历史 host/path pattern；
- 当前仍在线、承载 2009/2010 日期内容的 legacy pages；
- 同一平台对 forum → portal 的后来历史叙述；

但**没有实际取得并检查一份 2002—2010 中文骑行论坛的 verified Wayback/WARC capture**。

因此以下全部继续标为 `unknown`：

- historical response body；
- historical headers / Content-Type；
- charset（GB2312 / GBK / UTF-8 等）；
- forum software/version；
- cookie/session requirements；
- attachment URL schema；
- historical image hosting；
- historical pagination；
- login-only member state；
- `www` / `www1` / `www2` 的精确迁移时间与机制；
- current URL 是否由后台迁移映射到旧内容。

所以写法必须是：

> **M1 NOT ACHIEVED IN THIS SLICE. Historical locators and current retained pages are leads, not verified mementos.**

不得写：

> “2009 BIKETO 网站就是今天这个样子。”

也不得写：

> “Wayback 没有这些帖子。”

因为本轮没有完成足够范围的 archive negative search。

## 16. 后见之明与解释风险

### 不要把 portal 化写成线性“进步”

编辑重排论坛精华确实提高发现性，但也会抹掉原楼层、争论和失败经验。

### 不要把幸存游记当成所有骑行

成功长途游记最容易被收藏和再发布，临时取消、摔车退出、普通周末短骑更容易消失。

### 不要把页面热度当成现实参与度

点击数、评论数、注册会员、论坛核心用户都是平台状态，和真实骑行人数不是同一个分母。

### 不要把当前链接可开当作 archive 成功

长期运营平台可能在数据库迁移后继续渲染旧内容；这反而要求我们更谨慎地区分正文时间和 renderer 时间。

## 18. 这一题对旧网考古的新增意义

骑行 Web 把旧网站考古从“页面上发生了什么”再向现实推进了一层：

> **网页不是目的地。**

一个旧论坛可以保存“明天早上 7 点集合，骑 120 公里”的计划；历史真正发生在第二天的道路上。Web archive 擅长保存计划、路线文本和后来写下的游记，却天然不擅长保存：谁真的来了、哪里临时封路、谁爆胎、谁中途回家、最后群里怎么说。

因此骑行专题最值得留下的核心边界是：

```text
Web-visible route state
≠
physical ride state
```
