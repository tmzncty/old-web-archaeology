# 校友录 / 同学录的班级成员、信任、跨渠道联系与记忆状态缺口（1999–2012）

> Scope：1999–2012 中文旧网中的校友录、同学录与校园实名社交中的“学校—年级—班级—成员”关系结构，重点观察 ChinaRen、5460、QQ 校友录、校内网/人人网等公开可验证的功能与其不可见执行状态。
>
> 本文不是全球 alumni-service 通史，也不把 2012 年以后平台兴衰扩成无限 SNS 史。纸质通讯录、海外服务和 2024 年平台失效只作为必要前史/afterlife comparison；生活史解释写入 `tmzncty/how-people-lived`。

交叉生活史笔记：

- `tmzncty/how-people-lived/topics/classmate-alumni-networks-peer-calendars-and-relationship-continuity-china-1990-2024.zh-CN.md`

本切片研究的问题不是“ChinaRen 首页长什么样”，而是：

> **一个旧网页声称某人属于某学校、某年级、某班以后，经过多少个今天看不见的状态，这个账号才真正变成可长期信任、可重新激活的同学关系？**

---

## 1. 为什么校友录是旧网考古的高价值对象

公开 Web 很容易留下：

- 校友录首页；
- 学校搜索入口；
- 注册/登录框；
- 产品功能介绍；
- 班级创建教程；
- 平台并购、改版、WAP 化公告；
- 后来的怀旧报道。

真正决定“这个人是不是我的老同学、今天还能不能找到他”的状态却经常在公开 Web 之外：

```text
学校条目是否指向正确实体
→ 年级/班级是否重复创建
→ 用户是否真的注册
→ 用户是否被加入正确班级
→ 班级是否需要管理员批准
→ 实名/昵称是否与现实身份一致
→ 资料里的邮箱/电话是否仍有效
→ 留言/相册是否对该用户可见
→ 对方是否收到通知
→ 是否登录、阅读、回复
→ 是否把关系转去电话/短信/QQ/微信
→ 数年后账号是否仍由同一个人控制
→ 平台衰退时关系和资料是否迁走
```

因此校友录也是典型的 **public shell / private social graph（公开壳—私人关系图）**。

必须固定：

- `school searchable ≠ correct class exists`
- `class page exists ≠ membership verified`
- `member count ≠ active members`
- `profile name ≠ current identity controller`
- `message posted ≠ classmate read`
- `read ≠ trusted`
- `trusted ≠ relationship remains active`
- `human tie migrated ≠ platform memory migrated`

## 2. 前史边界：纸质通讯录证明需求早于 Web

1990 年已有公开书目可核验的《武汉大学校友通讯录》，共 188 页。[1]

它不属于本仓主 Web scope，只用于证明：

> “毕业后如何继续找到同学”不是 Internet 创造的新需求。

Web 改变的是地址更新、检索和班级内容的可交互性。

2005 年南京大学 81 经管毕业二十年聚会的校友网记录很有代表性：组织者重修通讯录，多次联系仍找不到一名同学，最后通过学校档案取得线索，再用电话重新联系。[2]

这条混合链提示以后不要把“网上找人”写成纸媒之后的单线替代：

```text
旧通讯录
+ 学校档案
+ 电话
+ 后来的 Web/QQ
```

可能长期并存。

## 3. 2004 同期教程：能确认的是功能与入口，不是班级后台状态

2004-06-22《中国电脑教育报》/新浪科技的一篇同期教程给出了一组很好的 B 级操作证据。[3]

它记录：

- 作者此前已经使用 5460 中国同学录；
- ChinaRen 校友录入口为 `alumni.chinaren.com`；
- Sohu / ChinaRen 邮件用户可复用账号密码进入；
- 用户可按大学、中学、小学搜索或创建班级；
- 班级共享可上传小于 500KB 的文件；
- 班级管理员可发布班级宣言，教程甚至给出图片/MP3 的 HTML 嵌入写法；
- QQ 校友录入口为 `school.qq.com`，使用 QQ 号码进入；
- 已有 QQ 同学群可以转化为校友录；
- 文中同时列出网易、古城、友联、DUDU 等同学录入口。

这条证据能支持：

> **2004 年中文旧网已经存在多个以学校/班级为索引的关系平台，且账户体系、群组体系和班级内容功能并不相同。**

它不能支持：

- 某个学校当时到底有几个重复班级；
- 创建班级是否一定需要管理员批准；
- 某个具体成员是否真是该班同学；
- 上传文件后来是否一直保存；
- HTML/MP3 在所有浏览器、所有历史时点都能正常播放；
- 页面今天如果还能打开就等于当年的 DOM/CSS/脚本仍完整。

### 3.1 `shared login ≠ shared identity model`

教程记录 Sohu/ChinaRen 邮箱账户可复用，而 QQ 校友录直接使用 QQ 号码。[3]

这说明“一个班级成员”背后已经可能由门户统一账号或即时通信账号承载。

但：

```text
邮箱账号有效
≠ 校友录班级资格自动正确

QQ号仍有效
≠ 该号今天仍由当年的学生控制
```

因此要增加 **account-to-cohort binding gap（账号—同届绑定缺口）**。

### 3.2 `QQ group → alumni directory` 是一个很重要的跨服务迁移点

2004 教程说，既有 QQ 同学群可以转化为 QQ 校友录。[3]

对旧网考古来说，这意味着 social graph 可能经历：

```text
QQ 群成员关系
→ 平台转换操作
→ 校友录班级关系
```

但旧页面 capture 通常无法证明：

- 当时到底导入了哪些人；
- 谁没有加入；
- 群昵称与校友录姓名怎样对应；
- 转换后原群是否继续活跃；
- 两个图是否长期保持同步。

这属于 **cross-service graph migration gap（跨服务关系图迁移缺口）**。

## 4. 2005：班级关系开始跨到 WAP，但不能从产品页推成移动端普及

2005-12-21 搜狐同期报道称，新版手机搜狐网把 ChinaRen 校友录等产品做成手机版，GPRS 手机用户可通过 `wap.sohu.com` 使用相关服务。[4]

这条材料是 B/A-adjacent：搜狐站内同期产品报道，可证明厂商当时这样提供/宣传产品；不能证明全国普通用户实际使用率。

旧网执行层必须继续拆：

```text
WAP 产品存在
→ 手机支持 GPRS
→ 用户开通数据业务
→ WAP 页面能在该机型正常显示
→ 用户能登录
→ 目标班级功能在 WAP 端可用
→ 用户实际用手机进入班级
```

所以：

> **desktop service has WAP version ≠ class relationship is already ambient/mobile for ordinary users。**

还需要记录 **client-capability gap、operator/data-plan gap、WAP-feature parity gap**。

## 5. 2008：从班级目录到毕业后持续搜索

2008 年 IT 时报同期报道记录，校内网准备向刚毕业的白领扩展，并现场演示按工作单位与毕业院校筛选关系；记者几分钟内找到一名大学同班同学。[5]

这是 B 级媒体观察 + 厂商现场演示，不等于平台上所有工作单位资料都真实、完整、更新及时。

它标志着关系索引发生了一次结构扩展：

```text
学校 / 年级 / 班级
+
毕业后的工作单位 / 城市 / 社会身份
```

于是新增 **post-graduation attribute staleness gap（毕业后属性陈旧缺口）**：

- 用户可能毕业后不再更新工作单位；
- 工作单位名称会变；
- 同一个机构可能有多个写法；
- 离职后旧单位仍留在资料里；
- 搜索结果“找到这个账号”不代表现实身份状态正确。

## 6. 2009 同期生活材料：平台活跃度、关系活跃度与信任已经开始分叉

《中国青年报》2009-02-03 的同期文章《变了味的校友录》不能替代平台日志，但它非常适合观察公开页面之外的使用结果。[6]

### 6.1 `login frequency` 会随着真实生活圈变化而衰减

文章中的小杨毕业时和同学建立校友录，刚毕业时几乎每天刷新，教师同学分享公开课、教学成绩、教案和试题；几年后，她访问频率降到每月甚至更久，同学也越来越少更新，过年群发短信成为更常见的联系。[6]

这说明必须拆开：

```text
account still exists
≠ class page still technically exists
≠ user still logs in
≠ class still posts
≠ relationship still continues there
```

可以增加 **cohort-activity decay gap（同届活跃衰减缺口）**。

如果 archive 只保存一个“班级有 45 名成员”的页面，不应该推导 45 人在 capture 时仍共同使用该平台。

### 6.2 身份字符串存在，不等于消息可信

同一文章后来记录，小杨为了学生家庭募捐，把信息从 QQ 群扩到旧校友录；一些同学看到后没有立即相信，反而担心账号被盗，并试图通过现实单位/电话确认本人。[6]

这条材料尤其重要，因为它击穿了一个常见的旧网假设：

> **real-name-looking profile ≠ trusted human authorship。**

校友录的信任执行链至少是：

```text
熟悉姓名/班级身份
→ 账号发布消息
→ 收件人看到
→ 判断账号是否可能被盗
→ 通过电话/单位/其他渠道交叉确认
→ 才决定是否采取现实行动
```

新增：

- `account-control gap`
- `authorship-trust gap`
- `cross-channel verification gap`

### 6.3 投诉/诈骗新闻会反过来改变旧平台可执行性

小杨的消息并不是因为页面打不开而失败，而是**页面能够工作、账号也能登录，但旧平台的信任环境已经变化**。[6]

因此旧网功能研究不能只停在“按钮还能不能点”。一个平台可能：

```text
technical availability = yes
social trust = degraded
operational effectiveness = low
```

这是 **social-runtime gap（社会运行时缺口）**：服务器运行状态与用户愿不愿相信平台上的身份/消息不是一回事。

## 7. classmate-directory execution state machine

以后遇到校友录/班级页，应至少按这条状态机审查：

```text
平台/域名存在
→ 学校索引存在
→ 学校实体匹配正确
→ 年级/班级存在且未重复混淆
→ 用户发现该班级
→ 用户注册/登录
→ 账号真实控制者可确认
→ 用户申请加入/被导入
→ 必要的管理员审核完成
→ 成员资料写入
→ 可见范围符合当时权限
→ 班级留言/相册/文件可访问
→ 用户发布消息
→ 目标成员得到通知或主动登录
→ 目标成员阅读
→ 目标成员信任身份与内容
→ 站内回复 / 电话 / Email / QQ 等跨渠道联系
→ 现实关系或行动发生
```

长期状态继续：

```text
毕业后属性更新/陈旧
→ 登录频率降低
→ 关系迁移至其他渠道
→ 账号忘密/更换邮箱/手机号
→ 平台改版/并购/迁移
→ 内容导出或未导出
→ 服务衰退/不可访问
→ 人际关系与平台记忆分别存续或死亡
```

## 8. 新增 archive / execution gaps

### 8.1 school-entity gap

同名学校、改名、合并、校区变化可能让历史学校索引产生歧义。

### 8.2 class-duplication gap

同一届同一专业可能被不同用户重复创建多个班级。搜索页存在不能证明所有同学进入同一个 canonical group。

### 8.3 membership-approval gap

公开班级页或教程常看不到加入是否自动、管理员批准还是邀请码。

### 8.4 account-to-cohort binding gap

账号控制权与现实同学身份并非天然同一。

### 8.5 contact-state staleness gap

Email、手机号、工作单位、城市可能多年未更新。

### 8.6 visibility/privacy gap

同一个班级可能对游客、已登录用户、成员、管理员显示不同内容；公开 archive 往往只保存最外层。

### 8.7 notification/read gap

留言存在不证明目标同学得到通知，更不证明阅读。

### 8.8 authorship-trust gap

实名字段或熟悉账号不能证明这次发言由本人控制并发布。

### 8.9 cross-channel handoff gap

站内关系经常转到电话、短信、Email、QQ；archive 通常在跳出站点后失去观察能力。

### 8.10 relationship-persistence gap

一次成功联系不证明此后多年持续联系。

### 8.11 cohort-activity decay gap

班级成员数、留言总数、相册数与目标年份的活跃人口不是同一个指标。

### 8.12 cross-service graph migration gap

QQ 群转校友录、校友录转 SNS、SNS 再转微信群时，哪些边被保留通常不可见。

### 8.13 client / WAP parity gap

桌面端、WAP、移动客户端的功能范围和页面结构可能明显不同。

### 8.14 data-export / platform-retirement gap

平台后来不可访问时，关系可能已迁走，但历史内容是否导出往往无法从公开 Web 判断。

## 9. Archive bias：校友录尤其容易留下“壳”，丢掉真正的班级生活

### 9.1 public-shell bias

archive 最容易保存：

- 首页；
- 学校目录；
- 注册帮助；
- 产品公告。

最难保存：

- 登录后班级；
- 成员通讯录；
- 私有相册；
- 留言回复链；
- 谁读过；
- 谁把关系迁去了 QQ/电话。

因此：

> **archive density of public pages ≠ density of actual social use。**

### 9.2 quiet-migration bias

一个班如果顺利从旧校友录迁到 QQ/微信，通常不会在原平台写一篇“我们迁走了”的公开公告。

结果是：

- archive 可能只看到旧站逐渐沉默；
- 研究者却容易误判关系整体死亡。

### 9.3 nostalgia/outage visibility bias

平台故障、回归和关闭时会产生大量新闻与怀旧文本；普通时期“大家已经在微信群安静联系”反而很少形成公开材料。

因此后来的“平台死亡”报道适合研究记忆，不应反推早年每天的真实活跃程度。

## 10. 2019 / 2024 afterlife：账号可恢复、人际可迁移、平台记忆仍可能分叉

这部分超出主研究时段，只作为旧网对象的 afterlife evidence。

2019 年人人 App 回归时，人民网转载的同期报道指出，一些老用户还能尝试恢复旧账号，但也有老用户已经不愿重新面对旧内容；另一个同期报道特别把账号密码找回作为产品重点。[7][8]

这说明：

```text
historical account recoverable
≠ user wants to reactivate old social graph
```

2024 年南方都市报报道人人网无法正常登录/找回、资料显示不全时，一名老用户回忆大学阶段的同学互动大量记录在人人网；另一方面，一名前员工仍与很多旧同事通过微信群保持联系。[9]

所以：

> **human relationship continuity ≠ platform archive continuity。**

这条边界应成为以后所有旧 SNS 考古的默认检查项。

## 11. 浏览器、页面形态与当前可复原边界

2004 同期教程给出了 `alumni.chinaren.com`、`school.qq.com` 等历史入口，还描述了班级共享、HTML 宣言和 MP3 嵌入。[3]

但本轮**没有取得并实际验证一个 1999–2002 ChinaRen 普通班级页面的 A 级 WARC/Wayback capture**，也没有完整复原：

- 原始 DOM/CSS；
- 字符集；
- 登录 cookie/session；
- 班级成员权限；
- 文件上传 backend；
- MP3/图片子资源；
- 管理员审批界面；
- 历史 WAP 页面在具体机型上的呈现。

后来研究中的截图可以作为 candidate / secondary visual evidence，但未核验 capture provenance 时不能升级成 A，也不能据此精确声明某年月的浏览器体验。

因此本轮不写：

> “2001 年 ChinaRen 某班级在 IE5 + GB2312 下必然呈现为某个布局。”

这是明确的负结果，不用常识填空。

## 12. Privacy stop condition

校友录比普通门户首页更容易包含：

- 真实姓名；
- 学校、专业、班级、毕业年份；
- 手机/座机；
- Email；
- 工作单位；
- 家庭照片；
- 婚姻、生育等生活事件；
- 旧账号安全线索。

本仓不应为了“恢复社交图”而：

- 批量重建普通人的班级成员名单；
- 重新发布旧电话/邮箱；
- 尝试登录、找回或验证私人旧账号；
- 把删掉的相册/留言重新公开；
- 用真实姓名跨平台拼接一个普通人的二十年身份轨迹。

研究平台结构时，优先保留 URL pattern、字段类型、权限结构和匿名化状态机。

## 13. 已证实 / 高概率 / 不知道

### 已证实

- 2004 年多个中文同学录同时存在，ChinaRen 和 QQ 校友录有可操作的班级搜索/创建与共享功能；
- QQ 群可被教程记录为能转换到 QQ 校友录；
- 2005 年 ChinaRen 校友录进入搜狐 WAP 产品矩阵；
- 2008 年校内网把毕业后的工作单位/学校关系纳入查找演示；
- 2009 年同期材料存在从“每天刷新”到低频访问、从校友录迁移到短信/QQ 的使用衰减案例；
- 同期材料还证明旧实名/熟人账号上的现实行动可能需要电话/单位等跨渠道再验证。

### 高概率但仍需更强原始证据

- 1999–2002 普通班级页面已经存在复杂成员权限、留言/相册与管理员状态；
- 不同同学录之间存在显著的班级重复、资料陈旧和用户迁移；
- 关系迁到即时通信后，是校友录衰减的重要机制之一。

### 不知道

- 1999–2002 某个典型 ChinaRen 班级页面的完整历史运行栈；
- 普通班级在多个平台重复创建的真实比例；
- 一个具体班级的“成员数”中多少人当时仍活跃；
- 一次旧平台帖子最终在电话/QQ/线下形成了什么关系结果，除非有额外证据；
- 平台衰退时多少普通用户真正导出并保存了自己的班级历史。

## 14. 对后续研究最有用的检查表

遇到一个旧校友录/班级页时，先问：

1. 这是学校索引、班级页、个人资料页还是一次 archive capture？
2. 页面是否登录后才可见？
3. 学校/班级实体有没有重复或改名？
4. 成员加入是否需要审核？
5. 姓名来自用户自填、邮箱账号还是校方身份系统？
6. 联系方式在目标年份是否仍有效？
7. 成员数是累计还是活跃？
8. 留言是否有通知机制？
9. 对方是否真的读/回？
10. 现实联系是否已经转到电话、短信、QQ？
11. 账号被盗/易主的风险是否改变信任？
12. 平台消失以后，人际关系与历史资料分别去了哪里？

如果这些问题无法回答，应该把缺口保留下来，而不是把“一个漂亮的班级页截图”写成完整的同学关系史。
