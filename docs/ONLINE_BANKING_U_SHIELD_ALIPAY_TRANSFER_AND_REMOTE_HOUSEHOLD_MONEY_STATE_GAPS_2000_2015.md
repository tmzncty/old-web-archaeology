# 网上银行、U 盾、支付宝转账与远程家庭资金的旧 Web 状态缺口（中国，2000—2015）

> scope：本文件只研究约 2000—2015 中文 Web 与个人远程资金转移的交界：个人网上银行、转账汇款、USB 数字证书/U 盾、银行—支付宝绑定、第三方账户转账，以及 PC→移动端迁移对事务可执行性的影响。1980s—1990s 邮政汇兑与 2005 年农民工银行卡特色服务只作为理解“Web 没有发明远距离汇钱”的必要前史；2016 以后的微信/支付宝成熟移动支付、工资实名制与数字人民币只作为后来边界，不把本仓扩成现行支付史。

生活史主线另见：

- `tmzncty/how-people-lived/topics/remittance-infrastructure-intergenerational-cashflow-and-dispersed-households-china-1980-2026.zh-CN.md`

本文件遵守 `docs/METHOD.md`：

- 不把今天仍由工商银行服务器提供的“2006 年页面”自动当成已经验证的 2006 capture；
- 不把一个 historical locator 当作已经实际检查过的 Wayback/WARC；
- 不把“网页显示转账功能”写成“银行清算已经完成”；
- 不把“支付成功”截图写成“收款家庭已经取现并完成现实支出”；
- 不批量重新公开普通人的银行卡号、支付宝账号、转账记录、身份证号码和家庭财务细节。

## 1. 为什么远程汇款特别适合 old-Web archaeology

个人转账网站不是纯内容页。浏览器只显示整个事务的一部分。

一个家庭资金动作可能跨越：

```text
工资/现金来源
→ 银行账户余额
→ 网上银行账号
→ 登录验证
→ 支付权限
→ U盾/口令卡/证书
→ 转账表单
→ 收款账号校验
→ 银行受理
→ 本行/跨行清算
→ 收款账户入账
→ 第三方支付账户（若有）
→ 提现/再转账
→ 收款人实际使用
```

因此保存一张“转账汇款”页面，不能证明：

- 用户当时已经开通网银；
- 用户具备足够支付权限；
- U 盾驱动和证书工作正常；
- 银行真的接受了交易；
- 付款端扣账与收款端入账已经一致；
- 支付宝余额已经成功提现到银行卡；
- 家庭成员最后拿到了可以消费的资金。

这类系统天然具有：

> **cross-system transaction dark matter（跨系统事务暗物质）**。

Web archive 最容易保存帮助页和表单外壳，最难保存银行核心账务、数字证书验证、跨行清算、风控、支付回调和私人账户状态。

## 2. 必要前史边界：家庭远程汇款远早于 Web

本仓主 scope 不向 1980s 扩张，但理解 2000s 网银必须保留一条前史边界：

- 1980 年规范性文件已经明确由邮局/银行办理个人汇款，并取消邮局每笔 500 元最高限额；
- 2001 年中国邮政开始电子汇款，首批业务可在 24 小时内兑付；
- 2002 年邮政汇兑网点约 4.5 万个，农村网点约 3.2 万个；
- 2005 年央行调查仍显示，农民工把钱带回家、邮政汇款和邮政绿卡远比银行卡汇款常见。

来源定位：

- 1980 规范性文件公开整理本：<https://zh.wikisource.org/zh-hans/中国人民银行、邮电部关于银行与邮局办理汇兑业务分工办法的补充通知>
- 《中国青年报》2001-06-29：<https://zqb.cyol.com/content/2001-06/29/content_250595.htm>
- 2002 业务量同期报道：<https://news.sina.com.cn/c/2003-10-10/1046890772s.shtml>
- 央行 2005 区域金融运行报告公开转载：<https://finance.sina.cn/sa/2006-05-26/detail-ikknscsi3403282.d.html>

这里的边界结论只有一句：

> **Web 转账改变的是旧有远程汇款事务的前端与速度，不是创造“远方家庭之间可以送钱”这件事。**

## 4. 状态缺口一：`bank account / Web-bank account`

银行卡或存折存在，并不等于这个人可以在 Web 上操作资金。

至少要拆开：

```text
有银行账户
→ 账户可正常使用
→ 已开通个人网上银行
→ 有登录凭证
→ 登录成功
→ 可以查询
→ 可以对外转移资金
```

这里新增：

> **bank-account / Web-authority gap（银行账户—Web 操作权限缺口）**。

早期电子银行最容易被后见之明误写成“只要有卡就能在电脑上汇钱”。实际事务往往还要去柜台开通、登记身份、选择认证工具，并受到金额上限限制。

## 5. A2 — 2003—2006：U 盾证明 Web 事务依赖一件真正插在 USB 口里的物理物件

工商银行官方材料记录，U 盾的前身是 2003 年推出的 USBKey 数字证书；2006 年官方通告称，U 盾用于网络环境中的客户身份识别，可以支持 24 小时大额转账、汇款等服务。

2006 年 2 月起的官方价格按型号约为：

- 60 元；
- 68 元；
- 76 元。

来源：

- 工商银行，2006-01-24《调整 U 盾价格的通告》：<https://www.icbc.com.cn/icbc/html/gonggao/2006nian/0124/sy_pop_udunjgtzgg0601241.html>
- 2007 年工行 U 盾降价说明（回溯 2003 推出）：<https://www.icbc.com.cn/page/721857327270756355.html>

等级：**A**。

这使早期网银出现一个非常明确的状态链：

```text
网银账号存在
→ 申请安全工具
→ 取得实体 USB Key
→ 电脑有可用 USB 接口
→ 驱动安装成功
→ 证书被写入/下载成功
→ U盾密码正确
→ 银行完成签名验证
→ 资金操作才可继续
```

新增：

> **online-interface / physical-token gap（在线界面—实体令牌缺口）**。

一个页面完全保存下来，也不能告诉我们历史用户手边是否真的有那个 USB Key。

## 6. A3 — 2006 工行—支付宝绑定：最干净的“查询能做、钱却动不了”证据

工商银行 2006 年官方 U 盾—支付宝绑定说明保存了非常具体的操作逻辑：

1. 用户如果还没有 U 盾，需要携本人有效证件到工行网点开个人网上银行并申请 U 盾；
2. 在电脑上安装系统补丁和 U 盾驱动；
3. 可以自己下载证书，也可委托柜台把证书下载到 U 盾；
4. 如果下载不成功，需要回柜台办理；
5. 把 U 盾与支付宝账户绑定后，插入 U 盾并通过密码验证，才能使用支付、提现、充值等资金功能；
6. 不插 U 盾或密码验证失败时，只能进行查询类操作。

来源：

- 工商银行 2006 年官方页面：<https://www.icbc.com.cn/icbc/html/guanggao/2006nian/0523/sy_button_zfbbaq060523.html>

等级：**A**。

这条证据可以直接固定：

> **query-access / money-movement-authority gap（查询权限—资金移动权限缺口）**。

也就是说：

```text
登录成功
≠ 能看到余额之外的操作
≠ 能把钱转出去
```

对 old-Web archaeology 特别重要，因为 archive replay 往往最容易到达的正是“不登录/不带令牌”的公共页面。

## 7. 2006 页面还暴露了 **offline recovery path（离线恢复路径）**

同一份工行操作说明明确说：

- U 盾要到营业网点申请；
- 证书可以由柜台代理下载；
- 自助下载失败时回柜台办理。

因此早期 Web 事务不是：

```text
线下 → Web → 线下消失
```

而更像：

```text
柜台开户注册
→ Web 登录
→ 本机驱动/证书
→ Web 交易
→ 失败时回柜台恢复
```

新增：

> **online-failure / offline-recovery gap（线上失败—线下恢复缺口）**。

历史复原如果只盯着 Web，会把这个系统最关键的恢复机制删掉。

## 8. A4 — 2008：转账权限、签名工具、费率和查询范围都被拆成不同产品状态

工行 2008 年官方说明记录：

- 转账汇款时，U 盾或口令卡用于交易签名；
- U 盾用户的大额转账限制更少；
- 未申领 U 盾的网银客户转账金额受到限制；
- 同城与异地业务费率不同；
- 网上银行“转账汇款查询”只能查询在网银渠道办理的相关交易，不能自动查询其他渠道完成的转账。

来源：

- 工商银行 2008 年官方说明：<https://www.icbc.com.cn/icbc/html/guanggao/2008nian/0122dzyhXPHC/detail_01.htm>

等级：**A**。

同期活动页给出异地/跨行个人网银汇款 0.9%、最低 0.9 元、最高 45 元的优惠费率。

来源：

- <https://www.icbc.com.cn/icbc/html/guanggao/2008nian/0410jrajzqhkHLSBTgrwyyx/sy_jrajzqhkHLSBTgrwyyx_080410.html>

等级：**A**。

由此增加两个 gap：

### `channel-record / global-account-record gap`

网银查询页里看不到其他渠道的转账，并不意味着账户没有那些交易。

### `transfer-feature / amount-authority gap`

页面上有“转账汇款”按钮，并不意味着这个账号可以执行任意金额。

## 9. 2005—2008 生活侧反例：网银已经存在，但农民工汇款主流仍可能是邮政与现金

2005 年央行调查显示，农民工利用银行卡汇款到家的比例在部分调查省份只有约 11%，更多人仍使用邮政汇款/邮政绿卡，另有相当部分直接携带现金返乡。

来源：

- 央行 2005 区域金融运行报告公开全文：<https://finance.sina.cn/sa/2006-05-26/detail-ikknscsi3403282.d.html>

等级：**A/B**。

这条反例对 old-Web 尤其重要：

> **网页功能史不能冒充采用史。**

2000 年个人网银存在；2006 年 U 盾很成熟；但这并不能推出 2006 年一个低收入、低学历、家乡只有邮储/农信网点的外出劳动者会把 Web 作为首选汇款工具。

必须长期区分：

- `exists`：银行提供个人网银；
- `available`：某个具体人能否开通、获得设备和网络；
- `used`：有无使用证据；
- `popular`：有无代表性采用数据。

## 10. B1 — 2009 支付宝：账户内“我要付款/收款/AA”已经成为独立资金事务

2009 年公开的支付宝服务协议变更说明列出：

- “我要收款”；
- “我要付款”；
- “生活助手”；
- “AA 收款”；

等站内资金功能，并按认证/非认证用户提供不同免费额度；即时到账支付的每日限额也区分证书用户和非证书用户。

来源：

- 2009 年协议变更同期转载：<https://www.cnbeta.com.tw/articles/tech/87050.htm>

等级：**B（同期转载；本轮没有取得支付宝原始页面 capture）**。

这时支付状态至少要再拆：

```text
支付宝账号存在
→ 是否实名/认证
→ 是否持证书
→ 免费额度是否耗尽
→ 当日限额是否足够
→ 付款请求提交
→ 支付宝内部记账
→ 对方支付宝余额入账
→ 对方是否提现到银行
```

新增：

> **platform-balance / bank-cash gap（平台余额—银行/现金缺口）**。

一个家庭成员在支付宝里“收到钱”，不一定等于他已经把钱变成当时生活场景所需要的银行卡余额或现金。

## 11. B2 — 2013：同一种转账在 PC 收费、手机免费，说明平台可以用费率推动界面迁移

2013 年 12 月，支付宝电脑端转账开始全面收费，而手机支付宝钱包转账继续免费。同期《人民日报》采访太原居民魏秀萍，她过去每月通过支付宝给在湖南读书的女儿转 1000 元生活费，因为可以避免去银行排队和部分异地转账费用。

来源：

- 《人民日报》，2013-12-04：<https://finance.people.com.cn/n/2013/1204/c1004-23735303.html>

等级：**B（同期报刊）**。

这说明一个旧 Web 功能走向衰退时，不一定先出现“功能不存在”。它可能先出现：

```text
PC 仍可用
→ PC 成本上升
→ 手机成本更低
→ 用户把同一动作迁走
→ PC 页面仍然活着，但生活行为已经转移
```

新增：

> **channel-price steering（渠道价格引导）**。

这对 old-Web 的存档偏差非常重要：

> **页面存活时间可以晚于行为重心迁移时间。**

一个 2014 年仍能打开的 PC 转账页，不应自动被解释为“2014 年普通用户仍主要在 PC 上做这件事”。

## 12. 从“网站”到“事务”应使用的状态机

研究 2000—2015 个人远程转账时，建议至少使用以下状态：

```text
[0] 有可转出的真实资金
[1] 银行/平台账户存在
[2] 账户可正常使用
[3] Web/客户端入口可访问
[4] 用户登录成功
[5] 身份认证满足要求
[6] 支付工具/证书/U盾/口令卡可用
[7] 收款人/账号已录入并校验
[8] 金额在限额内
[9] 费率被接受
[10] 交易提交
[11] 付款端受理
[12] 付款端扣账
[13] 本行/跨行/平台清算
[14] 收款端入账
[15] 收款人看到状态
[16] 收款人可提现/可消费
[17] 现实家庭支出完成
```

任何研究证据都只能证明其中一部分。

例如：

- 帮助页只能证明某些状态**被平台设计为可达**；
- U 盾说明可以证明身份/签名的条件；
- 一张“交易提交成功”截图可能只到 [10]/[11]；
- 付款银行卡扣账可能到 [12]；
- 收款人短信才更接近 [14]/[15]；
- 家庭是否交了学费/房租通常已经不在 Web 可观察范围内。

## 13. 必须保留的状态缺口

### 13.1 `website-exists / account-opened gap`

银行有网银，不代表这个用户已开通。

### 13.2 `account-opened / client-executable gap`

开了网银，不代表当前电脑、USB、驱动、证书和密码都工作。

### 13.3 `login / money-movement-authority gap`

能登录/查询，不代表能转钱。

### 13.4 `feature-visible / amount-authorized gap`

看到转账功能，不代表金额在账号权限或当日限额内。

### 13.5 `transfer-submitted / bank-accepted gap`

表单提交不等于核心银行系统已受理。

### 13.6 `source-debited / recipient-credited gap`

付款端扣账不等于收款端已经入账。

### 13.7 `platform-credited / bank-available gap`

支付宝余额到账不等于银行卡现金立即可用。

### 13.8 `recipient-credited / household-use gap`

钱进账户不等于现实支出已经解决。

### 13.9 `PC-service / mobile-service gap`

同一品牌的 PC 端和手机端可以有不同费率、限额和用户行为。

### 13.10 `current-official-page / historical-capture gap`

今天工行网站仍提供带“2006 年”目录的老页面，不代表我们已经观察到 2006 年服务器返回的同一字节流或浏览器呈现。

## 14. Browser / client archaeology：本轮能确认什么

### 已确认

从 2006 工行官方 U 盾—支付宝说明可以确认：

- 资金事务依赖一件 USB 设备；
- 首次使用需要安装驱动/系统组件；
- 证书需要下载到 U 盾；
- 自助下载失败时可以回柜台；
- U 盾密码参与交易/账户功能授权。

这些都是**历史客户端环境**的重要组成部分。

### 本轮仍未知

没有 verified historical capture 或完整历史安装包/手册，因此本轮不声称：

- 精确支持哪些 Windows 版本；
- 是否必须 IE、精确支持哪些 IE 版本；
- 是否使用 ActiveX 控件、具体 CLSID 是什么；
- HTTPS/TLS/证书链精确配置；
- 驱动下载安装 URL 是否随年份变化；
- 32 位/64 位兼容范围；
- 防火墙/代理/NAT 对操作有什么已证实影响；
- 支付宝页面与工行控件之间的具体浏览器调用链。

如果以后拿到原始安装介质、帮助 HTML 或 WARC，再升级这些 claim。

> **candidate/known historical locator ≠ verified archive capture**。

不写“Wayback 没有保存”，只写“本轮尚未验证到可检查的 capture”。

## 16. 为什么 U 盾特别容易被后来的浏览器回放误解

假设未来 archive 保存了一张 2006 工行转账页。

现代 Chromium 也许能显示：

- 标题；
- 表格；
- 按钮；
- 说明文字。

但历史用户真正完成交易时还需要：

- 操作系统环境；
- USB 驱动；
- 私有证书/密钥；
- 银行端认证服务；
- 活账户；
- U 盾密码；
- 核心账务系统；
- 收款银行/支付平台。

所以这个案例尤其适合提醒：

> **renderable page ≠ executable historical application**。

旧 Web 的“可看”与“可做”必须分开。

## 17. 家庭汇款怎样暴露 archive 的结构性盲区

### Web archive 容易保存

- 网银产品首页；
- 费率页；
- U 盾广告；

## 18. 从 PC 到移动：不要把“old Web 退出中心”写成“互联网退出生活”

2013 年支付宝的 PC 收费/手机免费说明，一个动作可以从：

```text
银行柜台
→ 家庭/办公室 PC 网银
→ PC 第三方支付
→ 手机支付
```

连续迁移。

对 old-web-archaeology 来说，重要的不是追到 2026，而是正确记录 2010s 初的边界：

> **旧 Web 页面可以在平台整体仍增长时失去生活事务的中心地位。**

因此需要区分：

- `feature death`：功能不存在；
- `channel displacement`：功能还在，但用户迁到另一端；
- `backend continuity`：PC/手机可能共享同一账户与账务；
- `brand continuity`：品牌相同不等于前端实现相同。

## 19. 与 ordinary-life history 的交叉：为什么“转账页”不是纯金融史

2008 年天涯重庆版讨论经媒体保存下来：应届毕业生会直接讨论“毕业后每月寄多少钱回家”；其中刘涛月薪不足以覆盖城市租房、交通、通讯和吃饭，反而继续从父母处拿钱。

同期材料：

- CCTV.com，2008-08-28：<https://finance.cctv.com/20080828/101574.shtml>

这说明一个网银/支付平台页面真正进入生活史时，研究问题应该是：

```text
谁有钱可转？
→ 谁被认为应该给谁？
→ 一个月/一年转几次？
→ 转账发生在发薪日、春节、学期初还是突发医疗日？
→ 技术摩擦是否改变家庭的转账频率？
→ 转账记录会不会让家庭责任变得更即时？
```

而不是只写：

> “某银行 2000 年推出网上银行。”

## 20. 海外对照：菲律宾提醒我们，真正的技术问题是“资金走廊”，而不只是 Web 页面

菲律宾大学 1984 年的同期研究已经把海外合同工与家人之间的汇款当成重要经济问题；到 2006 年，菲律宾商业银行已成为海外汇款主要正式渠道，而农村银行更晚才进入大规模兑付/国内转移网络，一个重要原因就是清算互联基础设施成本。

来源：

- UP School of Economics, 1984：<https://pre.econ.upd.edu.ph/upsedp/index.php/dp/article/view/297>
- *The Philippine Star*, 2006-05-20：<https://www.philstar.com/business/2006/05/20/337544/comm146l-banks-still-main-conduit-ofw-inflows>

这不是 old-web 仓库的全球扩展对象，仅作为边界比较：

> **先存在跨地/跨国家庭资金需求，再出现不同年代的柜台、电话、ATM、Web 与手机入口。**

所以中国 2000s 网银的特殊性不在“人类第一次可以远程送钱”，而在它怎样嵌入中国已有的邮政、银行、银联、农村网点和第三方支付体系。

## 22. 已证实 / 高概率 / 不知道

### 已证实

- 工行 2000 年开始个人网银试点，后来官方版本史明确列转账汇款等能力；
- 2003 后 USBKey/U盾成为个人网银安全工具之一；
- 2006 工行—支付宝绑定明确需要线下申请、驱动、证书与实体 U 盾；
- 没有正确 U 盾验证时可以出现“只能查询、不能动钱”的权限差异；
- 2008 转账手续费、U 盾/口令卡和金额权限存在明确区分；
- 2009 支付宝个人资金功能已有认证/证书/额度差异；
- 2013 同一支付宝转账功能在 PC 与手机端出现不同费率；
- 2005—2008 网银存在并不意味着农民工汇款已经以 Web 为主。

### 高概率但本轮不升级

- 早期 U 盾/网银的具体浏览器环境很可能比现代 Web 更依赖特定 Windows/浏览器组件；
- 银行、支付宝与跨行支付之间存在大量 archive 无法捕获的动态回调/账务状态；
- PC 端费率变化会推动部分用户迁移到移动端。

这些需要更多原始 capture、安装手册、历史客户端或代表性用户数据才能升级。

### 不知道

- 2000 年个人网银原始首页/登录页的精确 HTML、charset、HTTP headers；
- 2003—2008 U 盾控件的精确浏览器/ActiveX/驱动版本矩阵；
- 历史 TLS/证书链；
- 2006 支付宝绑定页当年是否与当前服务器保存内容字节一致；
- 历史跨行转账 backend 的具体实时/批处理边界；
- 支付宝 2009 原始协议页面是否有可验证 WARC；
- 私人转账失败、冲正、冻结、退款的真实概率；
- 用户从 PC 转到手机的采用曲线与不同年龄/职业/城乡差异。

## 25. 本轮改变了什么理解

旧 Web 考古很容易把“支付史”写成一串发布日：

```text
2000 网银
→ 2003 U盾
→ 2004/2005 支付宝
→ 2010s 手机支付
```

但普通用户真正经历的是另一条线：

```text
我有一张卡
→ 我去柜台开了网银
→ 我买/领了一只 U 盾
→ 我给电脑装驱动
→ 证书终于下载成功
→ 我登录支付宝
→ 我插入 U 盾
→ 系统允许我动钱
→ 我填了父母/孩子的账户
→ 银行扣款
→ 对方真正收到
→ 对方最后把这笔钱变成学费、房租、医药费
```

所以这次最值得留下的 old-Web 结论是：

> **一张历史转账页面最多只是家庭资金流的一块控制面。真正的事务跨过硬件、身份、银行后台、支付平台、清算网络和另一个人的现实生活。**

页面可以被完整保存，而那笔钱为什么必须在今晚到家，依然可能永远留在 archive 之外。
