# 社保查询、关系转移与记录可携带性的旧 Web 状态缺口（中国，2003—2015）

> scope：本文件只研究约 2003—2015 中文 Web 与社会保险事务的交界：地方劳动保障网站、12333 电话/网页、单位网上申报、个人查询、跨地养老保险关系转移，以及这些页面与真实社保后台之间的状态缺口。1997—1999 只作为理解记录/社保卡的必要前史；2018 以后电子社保卡和全国统一平台仅用于说明后来发生了什么，不把本仓扩成现行政务平台史。

生活史主线另见：

- `tmzncty/how-people-lived/topics/social-insurance-portability-record-continuity-job-mobility-and-retirement-futures-china-1997-2026.zh-CN.md`

本文件遵守 `docs/METHOD.md`：

- 不把今天能打开的政府历史文章冒充当年的页面 capture；
- 不把一个 historical locator 当作已经验证的 Wayback/WARC；
- 不把“页面上有这个功能”直接写成“个人账户事务已完成”；
- 不收集或重新公开普通人的真实社保账号、身份证号、缴费明细和医疗记录。

## 1. 为什么社会保险适合做 old-Web archaeology

社保网站有一个与普通内容站不同的结构：

> **浏览器里看到的页面，通常只是一个长期行政数据库的控制面。**

真实事务可能同时跨越：

```text
用人单位工资/劳动关系
→ 单位申报
→ 地方社保经办后台
→ 个人账户记录
→ 电话/Web 查询
→ 离职/跨地就业
→ 原参保地凭证
→ 两地经办机构传递信息和资金
→ 新参保地归集
→ 多年后退休待遇核定
```

因此，保存了一张“社会保险网上办事”首页并不能证明：

- 某个具体职工已经成功参保；
- 单位真的足额申报；
- 转出记录已经传到新城市；
- 资金已经到达；
- 个人能够在查询页看见最终状态；
- 几十年后待遇核定使用的就是今天浏览器看到的数据。

这类站点天然存在大量 **transaction-backend dark matter（事务后台暗物质）**。

## 2. 证据清单与等级

### A1 — 2005 上海：劳动保障 Web 已经承载社会保险网上事务

上海市劳动和社会保障局 2005 年政府信息公开年报记录：

- “上海劳动保障服务网”经过改版；
- 设有“信息服务台”“办事大厅”“互动社区”；
- “社会保险网上办事”频道提供网上办理、缴费查询、资料下载；
- 有 15 项城保和镇保网上办事项目；
- 用人单位可以在线办理职工转入申报、转出申报、封存申报、启封申报等。

来源：

- 上海市人力资源和社会保障局保存的 2005 年政府信息公开年报：<https://rsj.sh.gov.cn/txxgknb_17198/20200617/t0035_1372757.html>

等级：**A（同时代政府机构年报）**。

限制：它证明网站当年被官方描述为具备这些能力，**不等于原始 HTML/表单/登录页已经被本轮取得和检查**。

---

### A2 — 2006 上海：同一个网站与电话、公共查阅室、社区服务长期并行

上海市劳动和社会保障局 2006 年年报说明：

- 官方网站为 `http://www.12333.gov.cn`；
- “上海劳动保障服务网”当年形成“办事大厅 / 新闻中心 / 资讯服务 / 互动社区”；
- 办事大厅含人员招聘、培训、开业、招退工登记备案、社会保险等；
- 12333 电话每天提供人工接听、文件传真等服务，并增加社会保险查询、网上信访等项目；
- 政府信息公共查阅室放置电脑、打印机和电话，并安排人员服务；
- 社区就业援助员和宣传园地也承担信息传递。

来源：

- 上海市人力资源和社会保障局保存的 2006 年政府信息公开年报：<https://rsj.sh.gov.cn/txxgknb_17198/20200617/t0035_1372758.html>

等级：**A**。

这一证据直接阻止一种错误叙事：

> `Web 上线` ≠ `窗口/电话/社区渠道死亡`。

更准确的是 **channel layering（渠道叠层）**。

---

### B1 — 2006 北京：个人账户查询在 Web 普及前仍需要区县社保中心，12333 正在接入集中数据库

2006 年 12 月同期报道记录，北京正在整合全市个人社保信息数据库，计划让市民以后通过 12333 输入账号和密码查询养老保险等个人信息；在此之前，个人查询仍需要到区县劳动部门社保中心。

来源：

- 《新京报》/新浪，2006-12-17：<https://news.sina.com.cn/c/2006-12-17/014710790591s.shtml>
- 北京娱乐信报 / 搜狐，2006-12-17：<https://news.sohu.com/20061217/n247086854.shtml>

等级：**B（同期媒体）**。

注意：两篇都围绕同一官方咨询活动，不能机械算成两个完全独立 evidence family。

---

### B2 — 2006 湖北：12333 自动语音已经可以成为个人账户查询前端

2006 年 12 月，湖北 12333 系统允许部分参保人员用固定电话或小灵通输入养老保险账号，由自动语音播报账户余额和每月缴费金额；忘记账号时可以转人工，根据姓名和身份证号码查询。

来源：

- 长江商报 / 新浪，2006-12-26：<https://news.sina.com.cn/o/2006-12-26/074710864781s.shtml>

等级：**B**。

这里的技术结构不是 Web：

```text
电话网络
→ IVR/人工座席
→ 社保信息数据库
```

它与浏览器站点共享后台数据问题，却属于完全不同的用户终端。

---

### A3/B3 — 2006 上海：下载表格以后，真实事务仍回到纸与线下

上海官方 2006 年关于社保缴费争议仲裁的说明写得非常清楚：仲裁申诉书可以从 `www.12333.gov.cn` 下载打印，也可以到线下接待点领取；申请仍需提交书面材料。

来源：

- 上海市人力资源和社会保障局，2006-08-30：<https://rsj.sh.gov.cn/tsj_17090/20200616/t0035_1366387.html>
- 同期新闻晨报 / 新浪，2006-08-26：<https://news.sina.com.cn/o/2006-08-26/08309852797s.shtml>

等级：**A + B**。

因此新增：

> **downloadable-form / legal-submission gap（可下载表格—法律提交缺口）**。

页面把空白纸搬到屏幕上，并不意味着最终申诉已经电子化。

---

### B4 — 2006 北京：地方劳动保障网站已经承担名单查询、举报和信息导航

同期北京材料给出历史 host：`www.bjld.gov.cn`（北京劳动保障网）。例如 2006 年医保定点机构名单可通过该网站或 12333 查询；同年社会保险漏缴举报也可以通过该站发邮件。

来源：

- 法制晚报 / 新浪，2006-10-19：<https://news.sina.com.cn/c/h/2006-10-19/123511280616.shtml>
- 新京报 / 新浪，2006-03-01：<https://news.sina.com.cn/o/2006-03-01/02318325966s.shtml>

等级：**B**。

这说明 2000s 中期“劳动保障 Web”并非一个全国统一 UI，而是大量地方 host 与地方经办后台并存。

---

### A4 — 2009/2010：养老关系跨省转移是经办机构之间的长事务，不是一个网页按钮

2009 年 12 月出台的《城镇企业职工基本养老保险关系转移接续暂行办法》明确：跨省流动就业时，原参保地开具参保缴费凭证，养老关系随人转移；缴费年限合并、个人账户累计。

来源：

- 北京市政府保存的国办发〔2009〕66号全文：<https://www.beijing.gov.cn/zhengce/gwywj/201001/t20100101_781119.html>
- 人社部保存版本：<https://www.mohrss.gov.cn/SYrlzyhshbzb/zhuanti/syhexieminshengxing/zcfg/bxfzoujinnongcun/201007/t20100702_91130.html>

等级：**A**。

配套经办规程保留了《参保缴费凭证》《转移接续申请表》《联系函》《信息表》等不同事务文书，并要求经办机构在规定时限内完成信息和资金接续。

来源：

- 人社部关于贯彻落实暂行办法的经办规程：<https://www.mohrss.gov.cn/yanglaobxs/YLBXSzhengcewenjian/201610/t20161017_257400.html>

等级：**A（人社部保存制度文本；网页发布时间为后来归档时间，但文本为原规程）**。

这意味着 old-Web 研究不能把“网上可以查转移政策”误写成“转移本身发生在这一页”。

## 3. 一个特别重要的域名考古问题：`www.12333.gov.cn` 的机构含义发生了变化

2005—2007 的上海官方年报和同期报道把：

```text
www.12333.gov.cn
```

明确称为**上海劳动保障服务网**。

而今天，同一个域名是**全国人力资源社会保障政务服务平台**的网上办事大厅入口之一，当前用户协议也明确写明平台运营管理权属于人力资源和社会保障部。

当前来源：

- 全国人力资源社会保障政务服务平台用户协议：<https://www.12333.gov.cn/ggfwstatic/page/user.html>

这产生一个非常典型的：

> **same-domain / different-institutional-scope gap（同域名—不同机构范围缺口）**。

如果未来研究者只看今天 DNS/页面主体，很容易把 2006 年材料里的 `www.12333.gov.cn` 误读成“当时已经存在全国统一人社政务服务平台”。

正确写法必须按历史时点拆：

```text
2005–2007 证据中的 www.12333.gov.cn
= 上海劳动保障服务网的历史 locator

今天的 www.12333.gov.cn
= 全国人力资源社会保障政务服务平台
```

是否经历了怎样的域名移交、解析切换、历史 URL 迁移，本轮**尚未取得足够 DNS/WHOIS/capture 证据**，不能进一步猜测。

这个例子非常适合进入本仓今后的 `platform/site/host` 方法训练：

> **同一个域名不等于同一个历史站点。**

## 4. 社保 Web 的核心状态机

对一个跨城市换工作的普通人，可以先用以下状态机避免“查询页 = 权益”的错误：

```text
现实工作发生
→ 单位确认劳动/工资状态
→ 单位申报参保
→ 地方经办后台生成/更新记录
→ 当期缴费到账
→ 个人可通过窗口/电话/Web看到记录
→ 离职
→ 原参保地生成缴费凭证
→ 新参保地建立新参保状态
→ 个人/单位提出转移申请
→ 新地审核
→ 新地向原地发联系函
→ 原地生成信息表
→ 原地转移资金/记录
→ 新地接收
→ 缴费年限与账户归集
→ 个人查询到合并结果
→ 多年后退休待遇核定
```

每一条箭头都可能失败、延迟或要求线下恢复。

## 5. 本轮新增的状态缺口

### 5.1 `worked / employer-reported gap`

这个人真的工作了，不等于单位已经把他正确申报进社保系统。

历史 Web 最容易保存政策和单位申报界面，最难保存未申报劳动。

### 5.2 `employer-reported / backend-recorded gap`

单位提交成功，不等于经办后台最终写入无误。

需要区分浏览器提交页、服务端受理状态和最终个人账户。

### 5.3 `backend-record / person-visible gap`

后台有记录，不等于个人已经能看见。

2006 北京材料显示，集中数据库建设和个人电话查询能力本身就有不同上线时点。

### 5.4 `telephone-query / Web-query gap`

同一个后台可以先由 12333 IVR/人工座席访问，再由 Web 访问。

不能把“远程查询”都写成 Internet adoption。

### 5.5 `physical-card / database-record gap`

社保卡是身份和服务载体，不等于全部权益只存在卡片芯片上。

一张历史卡片照片不能单独证明某项缴费状态。

### 5.6 `policy-eligible / transfer-requested gap`

法律允许跨省转移，不等于个人已经发起。

### 5.7 `voucher-issued / receiving-agency-accepted gap`

原地出具参保缴费凭证，仍然不等于新地已经受理并完成接续。

### 5.8 `agency-message / fund-settlement gap`

联系函、信息表、资金转移属于不同后台状态。

一个“已发函”截图不能证明基金已经到新地。

### 5.9 `transfer-complete / person-visible gap`

两地后台可能已经完成，个人查询页仍可能存在同步延迟，反之亦然。

### 5.10 `legal-portability / workflow-executability gap`

制度可以规定转移，但姓名/身份证信息、历史记录、原单位漏缴、重复账户和地方系统接口仍可能让个人无法顺利完成。

### 5.11 `downloadable-form / legal-submission gap`

Web 能下载一张表，真实事务仍可能要求打印、签字、盖章和窗口递交。

### 5.12 `same-domain / same-institution gap`

`www.12333.gov.cn` 是本轮最强反例：同一 host 在不同时代可以对应不同机构范围。

### 5.13 `historical-page / live-backend gap`

Wayback 即使完整保存查询首页，也极可能无法重放：

- 登录；
- 账号/密码验证；
- 个人数据 API；
- 社保经办数据库；
- 转移事务进度；
- 历史缴费记录。

因此可回放的 UI 和真实历史事务之间天然存在巨大空洞。

## 6. 浏览器、编码与客户端：本轮已知与未知

### 已知

- 2005—2006 上海官方材料证明“上海劳动保障服务网”存在并承担网上办事；
- 历史 locator 包括 `www.12333.gov.cn`；
- 北京同期劳动保障网 locator 为 `www.bjld.gov.cn`；
- 社保服务长期同时存在电话、Web、下载打印、线下窗口和公共查阅电脑。

### 尚不知道

本轮**没有实际打开并检查 2003—2010 的历史 archive replay**，所以以下全部保持 `unknown`：

- `www.12333.gov.cn` 2005/2006 主页面的真实 HTTP headers；
- charset 是 GB2312、GBK 还是其他；
- 是否使用 frameset/table layout；
- 是否存在 IE-only JS、ActiveX、浏览器嗅探；
- 登录页面的 session/cookie 机制；
- 单位网上申报是否要求证书、控件或特定 Windows/IE 版本；
- 缴费查询的真实 URL pattern；
- 个人账户数据由何种接口返回；
- 页面与后端数据库的同步频率；
- 超时、账号错误、数据不同步时的历史错误页面；
- `www.12333.gov.cn` 从上海站点到全国平台的精确域名控制权/解析变迁。

这些不能用 2026 年当前页面逆推。

## 7. Archive 与历史可见性

社会保险是一个特别容易产生“保存偏差反转”的对象。

### 很可能保存得较好

- 政策通知；
- 政府信息公开年报；
- 帮助页；
- 空白表格；
- 办事指南；
- 新闻稿；
- 网站栏目名称；
- historical host。

### 很可能保存得很差

- 登录后的个人缴费记录；
- 单位真实申报数据；
- 转移失败的中间事务状态；
- 人工经办备注；
- 姓名/身份证匹配修复；
- 两地经办系统之间传输的联系函/信息表；
- 某个普通人为什么退保或没有继续缴；
- 电话 IVR 的真实语音树和人工座席处理记录。

因此：

> **public-document survival ≠ personal-rights survival in the archive（公共文件存活 ≠ 个人权益状态在档案中存活）**。

未来历史研究者可能拥有极其完整的制度说明，却看不到真正决定一个人养老年限是否接上的那条后台记录。

## 8. 个人数据与隐私边界

这一研究对象必须比普通旧站更严格。

不要为了证明“查询功能存在”而重新公开：

- 身份证号；
- 社会保障号码；
- 社保账号；
- 医疗/生育/工伤记录；
- 个人缴费工资和单位；
- 真实账户截图中的姓名、余额和待遇。

优先保存：

- 表单字段 schema；
- 登录/查询帮助文档；
- URL pattern；
- 同期操作报道；
- 脱敏后的错误类型；
- 政策状态机；
- archive metadata。

即使历史页面技术上可以访问，个人社会保障记录也不应因“考古完整性”而重新暴露。

## 9. 与 2018—2019 后续平台的边界说明

2018 年全国统一电子社保卡启动，2019 年国家社会保险公共服务平台上线并提供“多地参保、集中展现”等服务：

- <https://society.people.com.cn/n1/2018/0422/c1008-29941992.html>
- <https://app.www.gov.cn/govdata/gov/201909/16/448437/article.html>

这两项只用于确认旧网之后的方向：

```text
地方劳动保障后台/Web/电话
→ 社保卡
→ 跨地转移制度
→ 电子社保卡
→ 国家统一公共服务入口
```

本仓主研究对象仍停在约 1995—2015 中文旧网，不把后来的移动政务平台当成新的主 scope。

## 10. 海外提醒：统一数字身份也不会自动修复旧记录

生活史 companion 采用日本 1997—2007 养老金记录危机作为海外对照。1997 年日本引入统一 Basic Pension Number 后，大量此前因换工作、制度转换等形成的旧编号记录没有被正确归并；2007 年同期新闻报道约 5000 万条记录无法确认归属。

来源：

- *The Japan Times*, 2007-05-26: <https://www.japantimes.co.jp/news/2007/05/26/national/abe-says-help-on-way-in-pension-fiasco/>

对 old-Web 的启发不是做日本站点考古，而是：

> **如果研究中国历史社保页面，不能默认“统一号码/统一入口出现后，旧地方记录已经自动整洁地迁过去”。**

历史数据清洗、身份合并和失败修复本身就是需要证据的技术过程。

## 11. 已证实 / 高概率 / 不知道

### 已证实

1. 2005 年上海劳动保障服务网已经提供社会保险网上办事、缴费查询和资料下载，并允许单位在线进行职工转入/转出/封存/启封等申报。
2. 2006 年 `www.12333.gov.cn` 被上海官方材料明确称作上海劳动保障服务网。
3. 2006 年 12333 电话、Web、公共查阅室和社区渠道长期并行。
4. 2006 年北京劳动保障网 historical host 为 `www.bjld.gov.cn`，用于劳动保障信息查询/部分投诉入口。
5. 2009/2010 跨省养老关系转移制度包含参保缴费凭证、经办机构之间的信息和资金传递，而不是一个纯 Web transaction。
6. 今天 `www.12333.gov.cn` 的机构范围已经不同于 2006 上海材料中的同域名含义。

### 高概率，但本轮没有 archive 原件验证

1. 2005—2010 地方社保网上申报系统很可能存在特定登录/session/单位身份认证机制；
2. 部分系统很可能受到当时 Windows/IE/证书/控件环境影响；
3. 个人查询页的历史可回放性很可能远低于公开政策页，因为后端数据和认证不可由 archive 重放。

这些都不能升级成具体技术 claim，直到取得历史 capture 或软件/手册证据。

## 14. 这一轮对 old-Web 的核心修正

社保网站提醒我们：

> **旧网页不是只有“页面长什么样”的问题，还有“页面后面哪一段人生状态真的已经提交成功”的问题。**

2006 年，一个人可能已经能打 12333 听到自己的养老账户余额；单位可能已经能在网页上做职工转出申报；仲裁表格也可以在网站上下载。

可是当这个人真正离开上海、北京或东莞时，他过去几年工作的权益能不能进入下一座城市，仍然要经过纸质凭证、地方后台、经办机构和资金转移。

更有意思的是，`www.12333.gov.cn` 这个今天看起来天然属于“全国平台”的域名，在 2006 年的官方证据里却是上海劳动保障服务网。

因此这类考古必须同时保存两件事：

> **网页的历史状态，和制度后台的历史状态。**

只保存其中一个，我们都会误解普通人当时到底能够做什么。
