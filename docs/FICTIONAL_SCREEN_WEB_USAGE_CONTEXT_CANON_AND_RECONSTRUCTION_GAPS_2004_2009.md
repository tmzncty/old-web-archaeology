# FICTIONAL_SCREEN_WEB_USAGE_CONTEXT_CANON_AND_RECONSTRUCTION_GAPS_2004_2009.md

Status: methodology / research note  
Scope: Chinese screen fiction produced roughly within the repository's 1995–2015 scope; pilot examples use 《家有儿女》.  

This note defines how **fictional depictions of Internet use** can assist old-Web archaeology without being mistaken for historical Web artifacts.

The repository normally begins from pages, accounts, captures and software. Screen fiction provides a different kind of evidence: **usage context**. It can show what writers expected audiences to understand about computers, Internet cafés, chat logs, websites, online friendship or household access.

It cannot, by itself, reconstruct a historical browser, DOM, platform backend or adoption rate.

---

## 1. Research units must stay separate

For a fictional screen sequence, distinguish at least:

- **work** — the television series / film / animation;
- **episode / scene** — the specific narrative unit;
- **diegetic computer / terminal** — the computer that exists inside the fictional world;
- **diegetic website / IM service** — a fictional or referenced network service inside the story;
- **on-screen UI** — what the production actually shows;
- **production prop / software** — the real hardware/software used to create the shot, if known;
- **broadcaster VOD page** — a later page that hosts or describes the episode;
- **historical Web artifact** — an actual contemporary page/capture from the Internet outside the fiction;
- **claim** — the narrow conclusion being drawn.

Never collapse these levels.

---

## 2. Evidence roles

The repository's A/B/C/D evidence grades still apply. Add a **screen-fiction role** label to prevent overclaiming.

### SF-context

The scene demonstrates that a technical/social practice was culturally intelligible enough to be used as a plot device.

Examples:

- Internet café as a place a child can go;
- checking chat history;
- household computer gaming;
- starting a shopping website;
- online stranger becoming an offline acquaintance.

### SF-interface

The shot visibly depicts a UI, browser, desktop or network service.

This can support narrow observations such as visible layout, windowing or interaction **only if the screen image is clear and the production date is known**.

It does not prove that the UI is an authentic production build rather than a prop, mock-up or edited image.

### SF-production

A production interview, script, prop inventory, set photograph or behind-the-scenes source establishes what actual hardware/software was used.

This is the strongest way to connect fiction to technical history.

### SF-reception

Contemporary viewers discuss whether a depiction felt familiar, unrealistic, fashionable or technically wrong.

Useful for reconstructing ordinary expectations, not for backend architecture.

---

## 3. Hard rules

- `fictional website ≠ historical website`
- `on-screen webpage ≠ verified live URL`
- `visible browser chrome ≠ proven normal user environment`
- `plot uses chat ≠ chat service was universally used`
- `character uses Internet café ≠ household lacked Internet`
- `screen timestamp ≠ production timestamp`
- `later broadcaster VOD page ≠ first-broadcast Web artifact`
- `later fan screenshot ≠ original broadcast frame`
- `fan reconstruction ≠ canon`
- `fictional hack ≠ historical vulnerability evidence`
- `fictional online purchase ≠ working e-commerce backend`

If the claim needed is about an actual historical website, browser or protocol, obtain normal old-Web evidence.

# Pilot: 《家有儿女》 as usage-context evidence

## 4. Why this series is useful

Production began in 2004, and the series became widely broadcast from 2005 onward. Contemporary production material described it as a family comedy designed around current Chinese family life and education conflict.  
CCTV/Xinhua production notice: <https://www.cctv.com/performance/20040430/100145.shtml>  
Sina contemporary character/premise document: <https://ent.sina.com.cn/v/2004-05-25/1403399635.html>

That makes the first season potentially useful as **contemporary representation evidence** for how Internet use could be inserted into a mainstream family sitcom.

The currently surviving CCTV episode pages are later VOD/broadcaster pages. They are evidence for canonical episode content, but they are **not 2004/2005 Web captures of the original broadcast environment**.

---

## 5. Episode 36 — household computer connectivity

CCTV's surviving description says Liu Xing obtains game software and wants to connect with Xia Donghai's computer in order to play.  
<https://tv.cctv.com/2010/06/11/VIDE1354275581115842.shtml>

### Narrow claim allowed

A household-computer/network-gaming premise was culturally legible enough to support a family-comedy episode.

### Claims not allowed from this evidence alone

- exact PC count in the fictional household;
- LAN topology;
- Ethernet vs modem vs other connection;
- operating system;
- browser;
- game protocol;
- historical prevalence of home networking.

The scene may motivate a separate hardware/software investigation, but it is not that investigation.

---

## 6. Episode 61 — "雪儿网站"

CCTV's surviving description says Xia Xue borrows 3,000 yuan from her parents to create a money-making shopping website; the site fails to attract buyers and is later hacked, after which an acquaintance repairs it.  
<https://tv.cctv.com/2010/06/11/VIDE1354275076963801.shtml>

### SF-context value

The plot assumes that viewers can understand:

- a teenager creating a website;
- a shopping website as a possible business;
- advertising / traffic as a problem;
- absence of buyers despite site existence;
- a website being "hacked";
- someone with greater technical expertise repairing it.

This is strong **representation evidence** for what Internet concepts had entered mainstream narrative vocabulary.

### Old-Web boundaries

It does **not** establish:

- a real URL;
- an actual shopping-cart system;
- payment implementation;
- hosting provider;
- browser support;
- real attack method;
- normality of teen e-commerce entrepreneurship.

If an on-screen site exists, it should be catalogued as a **diegetic site**, not inserted into datasets of historical public Web domains.

---

## 7. Episode 93 — Internet café, online friend, chat records

CCTV's surviving episode description says Liu Xing spends time in an Internet café, communicates closely with an online friend, and Liu Mei later opens his computer and examines chat records. The online acquaintance later enters the family's offline social world.  
<https://tv.cctv.com/v/v1/VIDE1354275368551463.html>

This episode is especially useful for **usage-context archaeology** because it connects several levels:

```text
public-access venue
→ online account/relationship
→ local household computer
→ local chat-history residue
→ parental inspection
→ offline meeting
```

### What this may support

- public and household access are represented as coexisting;
- "online friend" is intelligible without technical explanation;
- chat history is represented as locally inspectable;
- network relationships can cross into offline life;
- Internet use has become a family-governance issue.

### What it cannot support

- the historical retention policy of a particular IM client;
- whether chat history was client-side or server-side for a real platform;
- which real platform, unless explicitly established in the episode;
- Internet-café prevalence;
- percentage of teenagers with online friends.

---

## 8. Episode 78 — online celebrity / identity investigation

A surviving CCTV description says Xia Xue admires a "network writer" and that Xia Donghai investigates personal information about online cultural figures.  
<https://tv.cctv.com/2024/01/01/VIDE14SumO4Lvb5DnaDTEtDS240101.shtml>

This is useful only at the **cultural-legibility** level unless the actual interfaces are separately recovered. It shows that "network writer" and looking up a person's online information were comprehensible narrative acts.

The hosting page was updated in 2024; it must not be used as evidence for a 2004/2005 page design.

# 9. Fiction can preserve the human side of Web use that Web archives miss

Web archives are good at URLs and public resources. They are weak at the ordinary room around the screen.

Screen fiction may preserve representations of:

- where the computer sits in the home;
- whether multiple family members compete for access;
- whether parents inspect children's digital activity;
- whether a child leaves home for an Internet café;
- whether online activity interrupts school or family routine;
- how much technical language requires explanation;
- whether online friends are treated as normal, suspect, comic or dangerous;
- what offline action follows an online event.

These should be coded as **usage-context clues**, then checked against manuals, surveys, contemporary journalism, household adoption data and real captures.

---

# 10. Production design can create false technical confidence

A fictional UI can look extremely specific while still being historically unreliable.

Possible production mechanisms include:

- a real live website;
- a locally hosted mock page;
- a static screenshot;
- a composited image added in post-production;
- a generic browser shell with fictional content;
- a real service visually altered to avoid trademark/licensing issues;
- a prop client created only for filming.

Therefore:

> **visual specificity ≠ software authenticity**

Before treating a screen UI as an actual historical interface, seek at least one independent technical or production source.

---

# 11. Canon vs later fan inference: the 《大耳朵图图》 / 牛爷爷 example

Later Internet discussion has produced elaborate theories about 牛爷爷's former institutional status, including whether he was a senior military cadre. Recent Bilibili analysis videos explicitly ask this question.  
Example locator: <https://www.bilibili.com/video/BV1gG4zepEJT/>

At present this is useful as a **methodological counterexample**, not as a historical claim.

The correct evidence ladder is:

1. explicit line/credit/script in the original work;
2. repeated canonical clues across episodes;
3. contemporary production/creator explanation;
4. contemporary audience discussion;
5. later fan synthesis;
6. researcher inference.

Do not promote level 5 or 6 to level 1.

For old-Web archaeology specifically, a 2024/2025 fan-theory video lies outside the repository's main 1995–2015 old-Chinese-Web object period. It can only be used to illustrate **retrospective reinterpretation**, not to establish the original 2004 canon.

---

# 12. Later fan recirculation creates a provenance trap

A common modern path is:

```text
original episode
→ television rebroadcast
→ later VOD host
→ fan clip
→ subtitled/remixed clip
→ meme / analysis video
→ search-engine result
```

The last item may be the easiest to find but the weakest for exact historical reconstruction.

Record separately:

- original production/broadcast date;
- episode identity;
- current host date;
- clip uploader;
- edit/remix status;
- whether original sound/image is complete;
- whether captions are original or user-added;
- whether the claim is canon or fan interpretation.

# 14. Relationship to normal A/B/C/D evidence

Examples:

### Case 1

A 2004 episode visibly shows a browser window but the footage is hosted on a current VOD page.

- episode content: potentially strong canonical evidence;
- current VOD page design: current artifact, not 2004 artifact;
- historical browser inference: D unless independently verified.

### Case 2

A 2005 newspaper review says a sitcom depicted children using Internet cafés.

- B for the review's observation;
- not a capture of the Internet café or service itself.

### Case 3

A later fan video claims a character used QQ but the original episode cannot be checked.

- C/D lead only;
- not enough to enter a platform history claim.

---

# 15. Copyright and privacy

Do not solve evidence gaps by committing copyrighted episode video, large frame sequences or ripped screenshots.

Prefer:

- official episode locator;
- episode number/title;
- narrow scene description;
- timecode when legally observable;
- analysis;
- small quotations only when necessary.

If a scene displays a fictional or real person's private-looking contact details, do not reproduce them unless genuinely necessary to the research claim.

---

# 16. What this adds to old-Web archaeology

This method introduces a new evidence class without weakening the repository's technical standard.

Screen fiction can help answer:

- **where** Internet use was imagined to happen;
- **who** in a household was expected to understand it;
- **what offline routines** surrounded it;
- which Internet concepts had become culturally legible;
- how old-Web use entered family, school and neighbourhood narratives.

It cannot answer, by itself:

- exact software version;
- historical DOM/CSS;
- backend state;
- real user adoption;
- network protocol;
- server-side retention;
- archive capture completeness.

The correct synthesis is:

> **screen fiction provides usage-context evidence; Web archaeology still requires Web evidence.**

## Current negative results

- No claim is made here that the fictional websites in 《家有儿女》 were live public URLs.
- No historical UI reconstruction has been attempted from memory or fan clips.
- No original 2004/2005 browser/client build has yet been verified from production records.
- The "牛爷爷 was a senior military cadre" interpretation remains **unverified** in the sources checked for this slice.

These limits are part of the result, not missing polish.
