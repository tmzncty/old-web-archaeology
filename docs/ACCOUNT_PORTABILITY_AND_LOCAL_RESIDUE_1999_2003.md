# 1999—2003 账号可携带性与本地残留：旧网考古不能把“人、账号、电脑”当成同一个对象

本文件补充：

- `docs/DIALUP_ACCESS_CONTEXT_1995_1998.md`；
- `docs/PUBLIC_ACCESS_CONTEXT_1996_2003.md`；
- `docs/METHOD.md`。

主研究对象仍然是约 1995—2015 年中文互联网。

这里不写完整 QQ 产品史，而是处理一个旧网考古里很容易误判的问题：

> **一个账号可以跟着人跨电脑移动，但同一台电脑又会留下多个不同人的本地痕迹。**

因此：

```text
person ≠ account ≠ terminal ≠ local files ≠ server state
```

这几个层级必须分开。

---

## 1. 为什么公共终端时代特别需要这条规则

家庭电脑场景容易让研究者产生一种错觉：

```text
这台电脑的聊天记录
≈ 电脑主人的聊天记录
≈ 这个账号的完整历史
```

在网吧、学校机房、单位公共电脑里，这个推断经常不成立。

同一终端可能在一天内依次被：

- 学生 A；
- 学生 B；
- 外来访客 C；
- 网管；
- 下一班顾客；

使用。

每个人又可能登录：

- Email；
- OICQ/QQ；
- BBS；
- 聊天室；
- 游戏账号；
- 门户会员账号。

所以旧硬盘、软件目录、浏览器历史、Cookie 和聊天日志首先证明的是：

> **某个账号或行为曾在这台终端上发生。**

它不自动证明：

> **这台终端属于这个人，或所有残留都来自同一个人。**

---

## 2. OICQ 的数字号码：账号已经是独立于机器的研究单位

《软件世界》2000 年 4 月的 OICQ 介绍记录：

- 安装客户端后可选择“申请新的 OICQ 号码”；
- 填写资料与网络设置；
- 联网后由服务器指定一个 OICQ 号码；
- 该号码成为后续网络通信的标识。

来源：

- 朱俊彬，《中文网络寻呼机--OICQ》，《软件世界》，2000-04-14，经新浪科技保存：<https://tech.sina.com.cn/soft/2000-04-14/133.html>

证据等级：**B，同期软件教程；对操作行为接近 A。**

### 旧网考古含义

以后遇到页面或论坛签名里的：

```text
OICQ: 1234567
QQ: 1234567
```

不要只把它当成页面文字。

它是一种可能跨：

- 网吧；
- 校园机房；
- 家庭电脑；
- 工作单位；
- 城市；

继续使用的网络标识符。

但这仍然**不是实名身份证明**。

---

## 3. 同时代用户安全资料证明：账号可携带，并不代表数据都在服务器

2001 年一篇 OICQ 安全教程警告：

- 公共电脑是密码被盗的高风险场景；
- 网吧 OICQ 安装目录可能出现以号码命名的目录；
- 未清理时可能暴露个人资料；
- 还可能留下好友信息与谈话记录。

来源：

- 赵凯，《OICQ攻防小全》，2001-05-03，目前可访问版本：<https://www.epochtimes.com/gb/1/5/3/n83937.htm>

证据等级：**B，同期用户技术教程；来源权威性一般，因此只支持窄结论。**

### 可以安全说什么

> 2001 年 OICQ 客户端在公共电脑上会留下足以引发隐私与密码安全担忧的本地用户痕迹。

### 不可以仅凭此说什么

- 所有版本目录结构完全相同；
- 所有好友数据只存本地；
- 所有聊天历史只存本地；
- 某个发现的号码目录必然对应电脑所有者。

---

## 4. “服务端身份 + 本地残留”应当成为默认模型

旧网研究经常陷入一个二选一：

```text
数据在服务器
vs
数据在本地
```

实际客户端系统经常是：

```text
服务端
├── account identifier
├── authentication state
├── 某些用户资料/关系状态
└── 某些离线/在线服务状态

本地终端
├── client executable
├── config
├── cache
├── user directory
├── chat log
├── downloads
└── password/session residue
```

二者叠加。

因此对一个 2001 年 QQ/OICQ artifact，至少要问：

1. 这个字段是客户端生成还是服务器返回？
2. 重装客户端以后是否还存在？
3. 换机器登录以后是否会重新出现？
4. 退出登录后本地是否残留？
5. 网吧重启/还原系统后是否消失？

没有这些证据时，不要擅自写“云端保存”或“仅本地保存”。

## 5. 2001 年现场采访：网吧用户不是绑定在一台机器上的

《北京青年报》2001 年 11 月的网吧现场采访记录，一名大学生即使宿舍已有电脑，也会因为：

- 宿舍 23:00 断电；
- 校内机房机位不足；
- 网吧可以多人联机；
- 可以大声交流、围观、支招；

转移到公共网吧使用网络。

这名学生还描述自己刚开始上网时会申请多个邮箱，后来聊天，再转向网络游戏。

来源：

- 张旭、祖薇，《活在虚拟现实间 夜12点谁在网上玩游戏？》，《北京青年报》，2001-11-23，经新浪科技保存：<https://tech.sina.com.cn/i/c/2001-11-23/93015.shtml>

证据等级：**B，且包含同期第一人称现场自述。**

### 旧网考古含义

同一个用户的网络活动可能发生在：

```text
宿舍电脑
→ 学校机房
→ 校外网吧
```

所以：

> **“用户环境”不是一台固定电脑，而是一组可替换终端。**

这会影响我们解释：

- Cookie；
- 浏览器收藏；
- 下载文件；
- 客户端配置；
- 输入法词库；
- 本地聊天记录；
- 浏览历史。

它们都可能只覆盖一个人的网络生活碎片。

## 6. 后来的回忆支持“账号比手机号稳定”，但只能标 C

2019 年一篇对早期 QQ 用户的采访回忆：

- 受访者 2001 年上大学后在网吧使用 OICQ/QQ；
- 没有手机时，曾通过 QQ 约见同学，线下错过后又进入网吧登录 QQ 重新联系；
- 后来手机号码会因为套餐便宜而更换；
- QQ 号反而长期不变。

来源：

- 《不愿注销QQ的人：一本纪念册不能说扔就扔》，2019-04-15：<https://news.sina.com.cn/s/2019-04-15/doc-ihvhiewr5870847.shtml>

证据等级：**C，后来回忆。**

它适合说明一种生活机制：

> 网络账号可能成为跨住址、跨电话号码的长期联系人标识。

它不能单独确定 2001 年客户端的技术实现细节。

## 7. 海外对照：ICQ 账号被盗已经被理解成“电话号码被抢走”

1999 年 *Wired* 报道 ICQ 用户账号遭接管。

一名用户把账号失控比喻成多年电话号码被别人拿走，并表示该 ICQ 号连接着：

- 个人通信；
- 商务联系人；
- 美国多地联系人；
- 海外联系人；
- 多年积累的一百多名联系人。

来源：

- Chris Oakes, “ICQ Users Get Disconnected,” *Wired*, 1999-09-09: <https://www.wired.com/1999/09/icq-users-get-disconnected/>

### 这个海外材料不写进中文旧网主体历史，但可以帮助校准解释

它说明：

> **“账号 = 可携带社会地址”是即时通信系统的一般机制，不应写成 QQ 独有发明。**

中国案例更值得研究的是：

- 公共终端密度；
- 家庭电脑普及阶段；
- 网吧/校园/单位终端切换；
- 中文客户端本地化；
- OICQ 与 BP 机/手机的桥接；

如何让这种机制在中文互联网环境中形成独特使用习惯。

## 8. 以后处理旧电脑或软件包时，至少增加以下字段

建议在涉及账号/客户端的 case 或 evidence note 中加入：

```yaml
terminal_context: unknown
# household-owned / dorm-shared / school-lab / workplace / internet-cafe / unknown

account_identifier:
  type: numeric-id
  service: OICQ
  value_preserved: false

identity_linkage:
  real_person_known: false
  confidence: low

credential_model:
  observed: password
  evidence_grade: B

server_state:
  friend_list_sync: unknown
  profile_sync: unknown
  offline_message: unknown

local_residue:
  user_directory: documented
  friend_data: documented
  chat_log: documented
  password_residue: reported-risk

session_context:
  public_terminal_possible: true

privacy_action:
  redact_personal_identifier: true
```

### 原则

如果具体 QQ/OICQ 号码不是论证所必需：

> **不要为了“考古感”把普通人的历史账号重新公开。**

这既符合 `docs/METHOD.md` 的隐私最小化原则，也避免把仍可能存在、转让或关联现实人的账号重新暴露。

## 9. 文件系统取证时的常见误判

### 误判 A：发现 `OICQ/<号码>/`，所以电脑属于这个账号主人

错误。

网吧电脑可能一天产生多个用户目录。

安全写法：

> “该终端上存在某 OICQ 账号使用残留。”

除非另有证据，不写：

> “该电脑主人是某账号用户。”

### 误判 B：聊天记录存在，所以平台服务器当年保存了聊天历史

错误。

本地聊天日志不能证明服务器历史存储政策。

### 误判 C：好友数据存在本地，所以好友关系不在服务器

也错误。

客户端缓存与服务器同步可以并存。

### 误判 D：同一个 QQ 号在多个网页出现，所以一定是同一个现实人

不一定。

可能存在：

- 转让；
- 盗号；
- 共用；
- 冒充；
- 页面抄录；
- 号码输入错误。

需要其他身份线索交叉确认。

## 10. 页面上的联系方式现在要区分“地点地址”与“可携带地址”

1998—2003 的个人主页、论坛签名、站长页经常并列：

- 邮政地址；
- 固定电话；
- BP 机；
- 手机；
- Email；
- OICQ/QQ；
- ICQ；
- BBS ID。

这些字段不是同一种联系方式。

可以按可携带性粗分：

| 类型 | 是否强绑定地点 | 换终端后是否理论可继续 |
|---|---|---|
| 邮政地址 | 高 | 否，需要地址转移 |
| 固定电话 | 高 | 否 |
| BP 机号码 | 中 | 是，但需回拨设施 |
| 手机号 | 低 | 是 |
| Email | 低 | 是，只需下一台联网终端 |
| OICQ/QQ | 低 | 是，只需客户端/网络/凭据 |
| BBS ID | 低 | 通常是 |

这张表只是功能模型，不代表所有用户实际都能无障碍跨设备登录。

费用、软件安装、密码、网络策略、网吧环境仍可能阻止访问。

## 11. 账号是“连续标识”，不是“完整数字人格”

旧网研究很容易被今天的云账户经验影响，想象：

> 只要账号不变，过去的一切都跟着它。

早期系统并非如此。

可能出现：

```text
账号不变
但聊天日志换电脑就没了

账号不变
但下载文件只在某台网吧机器

账号不变
但收藏夹和浏览历史不跟随

账号不变
但好友关系部分同步、部分缓存
```

所以以后用“账号连续性”时，应明确它具体连续什么：

- identifier continuity；
- contact continuity；
- profile continuity；
- message continuity；
- file continuity；
- reputation continuity。

不能用一个 `same account` 把这些全部打包。

## 12. 历史可见性的反直觉

公共终端时代可能出现：

> 对当事人来说，账号比电脑更稳定；
>
> 对今天的档案研究者来说，电脑残留却比服务器账号历史更容易留下。

原因包括：

- 平台服务器后来关闭；
- 私信/聊天不进入公开 Web archive；
- 旧账号需要登录才能查看；
- 聊天记录本来就在本地；
- 网吧硬盘反而可能被某个旧镜像偶然保存；
- 公开网页上的 QQ 号比真正聊天内容更容易被抓取。

因此：

> **最容易留给后人的数据，不一定是当时人生中最重要的数据。**

这是旧网考古与普通生活史之间非常关键的交叉点。

## 13. 如果以后做 OICQ 客户端实验，实验边界必须这样写

可以做：

- 获取来源可说明的历史安装包；
- 在隔离 Windows 环境中安装；
- 记录创建的目录/文件；
- 比较首次启动前后文件系统；
- 创建虚构测试配置；
- 观察本地日志格式；
- 记录软件默认路径和 UI。

不可以把实验自动当成：

- 1999 年腾讯服务器真实行为复原；
- 当时账号还能正常认证的证明；
- 原始用户真实好友关系；
- 当年所有网吧配置。

实验必须标：

```text
historical binary behavior observed in modern reconstruction
```

而不是：

```text
this is exactly what a 2000 user experienced
```

## 14. 本轮最小 claim list

### 已证实

1. 2000 年 OICQ 教程记录服务器向注册者分配数字 OICQ 号。
2. 2001 年网吧用户现场采访显示，同一用户会在宿舍、机房、网吧等不同终端环境之间选择。
3. 2001 年同期 OICQ 安全教程明确把公共终端的本地用户目录、好友信息和聊天记录视为隐私/安全问题。
4. 海外 ICQ 用户 1999 年已经把长期账号失控理解成社会联系方式被夺走。

### 高概率但仍需原始产品材料确认

1. OICQ 早期设计比原始 ICQ 更强调跨电脑恢复联系人关系。
2. 中国公共终端环境提高了服务端账号/好友同步的实际价值。

### 仍不知道

1. OICQ 99a、99b、2000 各版本好友列表的精确本地/服务端字段划分。
2. 网吧系统还原软件何时大规模改变聊天记录留存。
3. 用户跨网吧迁移时通常怎样保存下载文件和聊天记录。
4. QQ 号何时从“临时玩具号码”大规模转成需要长期保护的社会资产。
