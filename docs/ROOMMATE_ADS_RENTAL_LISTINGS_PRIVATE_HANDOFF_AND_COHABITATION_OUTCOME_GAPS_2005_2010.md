# ROOMMATE_ADS_RENTAL_LISTINGS_PRIVATE_HANDOFF_AND_COHABITATION_OUTCOME_GAPS_2005_2010

## 目的

本文件建立 2005–2010 中文旧网中 **租房 / 合租 / 找室友** artifact 的最低证据合同。

它不写“中国合租史”，也不把仓库 scope 扩展成住房社会史。这里研究的是一个更窄的问题：

> 当中文 Web、地方门户、BBS 和分类信息页开始把房源与室友变成可远程发现的对象后，今天的 archive 究竟还能证明什么，又系统性丢掉什么？

与普通内容页相比，租房信息有一个特别严重的考古困难：

**真正成功的帖子往往最应该迅速失效。**

一套房找到租客以后，合理状态不是“永远公开”，而是：

```text
发布
→ 被看到
→ 私下联系
→ 看房
→ 已租 / 删除 / 过期
```

因此：

> **archive survival can be negatively correlated with transaction success**

这意味着“今天还能搜到很多旧租房页”不能直接说明当年市场里哪些信息最有效。

跨仓生活史解释见：

<https://github.com/tmzncty/how-people-lived/blob/main/topics/roommate-search-unrelated-coresidence-and-household-by-match-china-1990s-2025.zh-CN.md>

# 1. 研究单位：至少拆成九层

租房旧网最容易犯的错误，是把一个“租房网页”当成整个住房交易。

本仓要求至少区分：

1. **platform / site**  
   例如地方门户、房产网站、校园 BBS、分类信息站。
2. **board / category**  
   例如 `房屋出租`、`合租`、`求租`、校园 housing board。
3. **listing / post**  
   一条具体房源或找室友信息。
4. **poster identity / account**  
   房东、二房东、中介、现有租客或求租人。
5. **room / dwelling object**  
   整套房、一个房间、一个床位、被再分割的小间。
6. **contact handoff**  
   电话、短信、QQ、站内信、Email、线下中介。
7. **viewing**  
   是否实际看房。
8. **rental / co-residence outcome**  
   是否签约、入住、与谁一起住、住多久。
9. **later state**  
   续租、换室友、涨租、删除、过期、重新发布。

于是：

> **listing URL ≠ dwelling**

> **poster account ≠ landlord**

> **room described ≠ room inspected**

> **contact ≠ transaction**

> **transaction ≠ successful co-residence**

# 2. 当前已证实的 2005–2010 evidence baseline

本轮没有取得足够稳定、可验证的 2005–2010 原始普通用户租房帖 archive capture。

因此以下主体材料都按 **B — 同期/近同时代二手证据** 处理；不把媒体引用的帖子“升级”为 A。

这一限制本身应保留，因为它正说明租房旧网的 archive gap。

## 2.1 2005：网站、都市报、校园广告同时存在

### Evidence family B1

2005-03-18，《市场报》专题经中新网保存：

<https://www.chinanews.com.cn/news/2005/2005-03-18/26/552059.shtml>

报道引用了一条近期网站合租帖子。帖子中，一名男性发帖者用以下字段描述自己并筛选室友：

- 28 岁；
- 男；
- 北京某名校研究生毕业；
- 外企工作；
- 不抽烟、不喝酒；
- 希望与在校学生或有职业的女性合住；
- 一人一间；
- 另带有外貌要求。

报道同时说，在北京的一些：

- 都市报；
- 房产网站；
- 大学校园；

都能看到类似合租广告。

### 这能证明什么

可以证明：

- 2005 年同期媒体实际观察到网上合租帖；
- 网页不是唯一渠道，纸媒、校园广告与网站并存；
- 普通用户会在公开帖子里主动暴露职业、学历、生活习惯、性别偏好等筛选信息；
- 网站能够承担 stranger-discovery interface。

### 不能证明什么

不能证明：

- 原帖 URL；
- 原帖所在平台；
- 页面 HTML / CSS / charset；
- 回帖数量的精确状态；
- 发帖账号是否真实；
- 最终是否有人入住；
- 2005 年所有年轻租客普遍这样找室友。

因此：

> **quoted web post in press ≠ preserved web post**

## 2.2 2006：上海热线租房栏目被同期记者实际浏览，但数据库未被本轮恢复

### Evidence family B2

2006-09-07，《新闻晨报》经新浪保存：

<https://news.sina.com.cn/s/2006-09-07/02409954170s.shtml>

报道记录一名刚参加工作的上海女性因为独自承担一居室房租压力较大，在网上发布合租信息；帖子发布后，多名应征者上门看房，其中一人很快入住。

更重要的是，记者称自己当时浏览了**上海热线租房栏目**，观察到大量合租帖，并对帖子中的性别条件作了统计性描述。

### 证据等级

- 报道本身：**B**；
- 记者对 2006 当日/近日上海热线栏目状态的观察：仍为 **B**；
- 上海热线历史租房数据库：**未取得**；
- 具体 listing capture：**未取得**。

### 最小 claim

可以写：

> 2006 年同期记者明确观察并描述了上海热线租房栏目中的大量合租帖子。

不能写：

> “我们已恢复 2006 年上海热线合租数据库。”

也不能根据媒体摘要构造当时页面截图。

## 2.3 2006：网上低价房源与“群租”切割经营已经连接

### Evidence family B3

2006-07-19，《东方早报》经搜狐保存：

<https://news.sohu.com/20060719/n244327918.shtml>

同期报道讨论上海“群租”：有人先取得整套住宅，再切割成多个小间分别出租；一名刚到上海工作的人称自己是通过网上低价、好地段的合租信息进入此类住房。

### 对旧网考古的意义

`合租` 在 URL/category/text 里不一定对应同一种现实对象。

至少要区分：

```text
A. 几个租客共同承租完整住房
B. 主租客把空房间转租给室友
C. 二房东整租后按房间分租
D. 一间卧室多人入住
E. 整套住宅被切成大量小间/床位
```

所以：

> **category label ≠ dwelling topology**

如果未来建立 dataset，应增加：

- `rental_unit_type`；
- `whole_unit_or_room`；
- `bedspace`；
- `subdivision_observed`；
- `poster_role`。

## 2.4 2007：实体信息栏与 BBS 并不是瞬间替代，而是长期重叠

### Evidence family B4

2007 年《南方周末》关于北京大学“三角地”的同期报道：

<https://www.edu.cn/yiwujiaoyu_1074/20071109/t20071109_264480_2.shtml>

报道说，2001 年入学的受访者到 2007 年已很少把三角地当主要信息源，社团、讲座等信息基本转向校园 BBS；实体栏仍常见培训、宿舍铺位转让等生活广告。

同期《新京报》经新浪报道则明确称，三角地信息栏长期贴有租房、讲座、求职信息：

<https://news.sina.com.cn/c/2007-11-01/020614207298.shtml>

### 对中文旧网 scope 的意义

这不是要把 `old-web-archaeology` 扩展为“海报栏史”。

前史在这里仅用于解释：

> 中文 BBS / 网站中的分类信息页面继承了一个原本已经存在的 noticeboard function。

因此一条合理的边界链是：

```text
physical noticeboard / newspaper classified
→ campus BBS / local portal
→ classified website / housing vertical
```

必须避免：

> “Internet 出现前人们无法公开发布租房信息。”

## 2.5 2008：高校周边仍然可以通过墙上小广告、现场房源和人际接触找房

### Evidence family B5

2008-04-03，《北京日报》经中新网：

<https://www.chinanews.com.cn/edu/dxxy/news/2008/04-03/1211332.shtml>

报道包含“大学校园租房小广告”的现场材料，并通过记者实地找房描述床位、地下室、多人间、单间和整套住房的不同形态。

2008-08-26，《法制晚报》经搜狐：

<https://news.sohu.com/20080826/n259214033.shtml>

记者在高校附近的合租小广告前停留后，即被经营分租房源的人搭话。

### 这能纠正什么

到 2008 年，即使网络租房已经存在：

> **online availability ≠ offline disappearance**

墙贴、校园周边、人际搭话、中介与网站可以同时存在。

旧网研究不能只采集能被 Web archive 看见的渠道，然后误以为它们构成全部历史住房信息市场。

# 3. 租房网页必须增加的状态机

普通静态内容页可以围绕：

```text
publish → capture → later capture
```

建模。

租房页至少需要：

```text
created
→ pending / under review
→ visible
→ refreshed / bumped
→ edited
→ contacted
→ reserved? [often invisible]
→ rented? [often invisible]
→ expired
→ deleted
→ reposted
```

其中：

- `contacted` 常不在公开页面；
- `reserved/rented` 可能只存在内部数据库；
- `deleted` 可能意味着交易成功、用户撤回、违规、过期或平台清理；
- `reposted` 可能是同一个物理房间，也可能已经换租客/价格。

因此：

> **HTTP 404 after listing ≠ listing was false**

> **page survived for years ≠ room stayed available for years**

---

# 4. listing-state gap：网页 capture 很难恢复“当时到底还租不租”

定义：

> **listing-state gap** = archive 保存了页面内容，却无法可靠恢复 capture 时刻之外的真实库存状态。

例如：

- 页面原始发布日期是 2006-09-01；
- archive capture 是 2006-09-10；
- 房间可能 09-03 已经租出；
- 发帖人没有删帖；
- 或平台 cache 仍显示旧页。

所以：

> **page visible at capture time ≠ room available at capture time**

未来 evidence schema 应把：

- `page_publication_time`；
- `archive_capture_time`；
- `last_modified_claimed`；
- `availability_state_claimed`；
- `availability_state_verified`；

分开。

---

# 5. inventory-snapshot gap：动态搜索页不是“历史市场截面”

住房网站通常不是一本按月出版的目录。

一个搜索结果页可能依赖：

- 城市；
- 区域；
- 地铁；
- 租金；
- 整租/合租；
- 性别；
- 发布时间；
- 排序规则；
- 登录状态；
- cookie；
- 后台库存。

因此：

> **search form survived ≠ historical inventory survived**

> **one search-result capture ≠ full market inventory**

更不能拿今天的同路径页面结果推回 2006。

这类系统需要记录：

- query parameters；
- pagination；
- sort order；
- result count（若页面明确）；
- dynamic request dependency；
- login/session dependency；
- capture completeness。

---

# 6. bump-time / original-time collapse：租房帖的“日期”可能不是一个日期

分类信息和论坛租房常允许：

- 顶帖；
- 编辑；
- 刷新；
- 自动更新；
- 重新发布；
- “急租”置顶。

因此一个页面可能同时有：

```text
first posted
last edited
last bumped
platform refreshed
archive captured
```

如果未来只存一个 `date` 字段，会制造严重误判。

建议：

```yaml
first_seen_at:
claimed_posted_at:
claimed_updated_at:
bump_time:
capture_datetime:
```

未知时留空，不推断。

---

# 7. repost-duplication gap：多个 URL 不等于多个房源，也不等于多个证人

同一房间可能被：

- 房东发布；
- 二房东发布；
- 中介复制；
- 现租客发找室友帖；
- 抓取站转载；
- 搜索结果缓存；
- 多个平台重复发布。

所以：

> **many listing URLs ≠ many dwellings**

> **many reposts ≠ independent evidence families**

如果同一电话号码、地址、照片、面积、价格和文案高度重叠，应优先视为可能的同一 listing family，再寻找反证。

但出于隐私，本仓不应批量公开普通人的历史电话号码来做聚类；可以本地哈希/最小化处理，或只记录“contact field matched”而不提交明文。

---

# 8. contact-handoff gap：最关键的住房交易往往在网页离开后才开始

租房 listing 的典型 Web 生命周期很短：

```text
public post
→ phone / SMS / QQ / email / private message
→ offline viewing
→ negotiation
→ contract / cash / deposit
→ move-in
```

Web archive 最容易保存第一层。

其余层通常消失在：

- 电话；
- 短信；
- QQ；
- 私信；
- 站内账号后台；
- 纸合同；
- 现金/转账；
- 线下看房。

定义：

> **contact-handoff gap** = 公开页面只能证明“可以尝试联系”，不能证明后续联系真的发生。

因此必须固定：

> **phone number displayed ≠ call placed**

> **QQ displayed ≠ conversation occurred**

> **private-message function exists ≠ message exchanged**

---

# 9. verification gap：公开 profile 字段不是身份验证

2005 合租帖中已经能看到学历、职业、抽烟/喝酒、性别等自我描述。

2006 案例又说明，线上发帖和快速看房可以迅速导向共同居住。

因此旧网页上看到：

```text
名校毕业
外企工作
有正当职业
不抽烟
女生优先
```

只能编码为：

> **self-claimed screening attributes**

不能编码为：

> **verified identity**

验证层应拆开：

1. 昵称；
2. 电话可用；
3. QQ/Email 可达；
4. 姓名自报；
5. 身份证看过；
6. 房东/产权身份核验；
7. 租赁权利核验；
8. 平台实名/认证（若当时确有）；
9. 线下持续行为。

所以：

> **identity legibility ≠ identity verification ≠ housing authority verification**

---

# 10. room-topology gap：网页里的“合租”可能对应完全不同的物理空间

2006–2008 同期资料已经显示：

- 一人一间；
- 两人/多人一室；
- 一套房多个独立房间；
- 床位出租；
- 地下室小隔间；
- 整租后再分租；
- 房屋被进一步切割。

因此旧网页中的 `合租` category 不能直接编码成一个统一 dwelling type。

建议未来数据字段：

```yaml
listing_intent: roommate-seeking | room-rental | whole-unit-rental | bedspace | unknown
physical_unit_claimed: whole-flat | bedroom | subdivided-room | bed | unknown
co_resident_count_claimed:
poster_role: landlord | tenant | sublessor | agent | unknown
shared_facilities: kitchen | bathroom | living-room | unknown
```

没有证据就留 `unknown`。

---

# 11. cohabitation-outcome gap：最重要的结果几乎总在公开 Web 之外

即使获得完整 listing，也通常不知道：

- 谁最终入住；
- 是不是原应征者；
- 住了多久；
- 房租是否按约支付；
- 室友是否相处良好；
- 谁先搬走；
- 是否换了下一任室友；
- 是否因结婚/换工作/迁移退出；
- 是否发生纠纷；
- 房屋是否后来继续作为合租房。

定义：

> **cohabitation-outcome gap**

这意味着：

> **successful roommate search is often archaeologically invisible**

反而：

- 严重纠纷；
- 刑事案件；
- 法律争议；
- 媒体奇闻；

更容易留下新闻。

于是旧网样本会产生严重的 **conflict-survival bias（冲突存活偏差）**。

不能因为今天找到的“合租后续”大量是纠纷，就推断当时多数合租以纠纷结束。

---

# 12. success-deletion paradox：最成功的 listing 可能最早消失

住房分类信息与长期博客不同。

一个成功的租房帖的理想结局往往是：

```text
房已租
→ 不再接电话
→ 删除帖子 / 关闭联系方式
```

因此：

> **successful listing → shorter public lifetime**

而失败、无人问津、被抓取转载的帖子反而可能存在更久。

这可以称为：

> **success-deletion paradox（成功删除悖论）**

对 archive sampling 的含义：

- 幸存帖子可能偏向 stale inventory；
- 抓取频率低时，几小时/几天就成交删除的帖子可能从未进入 archive；
- 高频城市、热门板块与热门房源反而可能低存活。

未来做“2005–2010 合租帖样本”时，必须在 methodology 里写这项 survivorship bias。

---

# 13. historical contact privacy：旧租房页是高风险个人信息 artifact

租房页常包含：

- 真名或姓氏；
- 手机；
- QQ；
- Email；
- 精确地址；
- 工作单位；
- 学校；
- 性别；
- 作息；
- 单身/感情状态；
- 住房钥匙与看房时间。

这些信息即使 2005 年公开过，也不意味着 2026 年应重新聚合公开。

本仓应执行最小化：

### 可以保留

- 平台名；
- URL pattern；
- 字段类型；
- 城市/大区级位置；
- 证明功能所需的最少摘要；
- 媒体已公开且对 claim 必要的抽象信息。

### 默认不提交

- 普通人历史手机号；
- QQ 号；
- 精确住房门牌；
- 可重新识别普通人的跨平台拼接；
- 已删除私人沟通内容。

> **archaeological availability ≠ ethical republication**

---

# 14. 当前页面与历史页面不能混用

今天的 58、安居客、租房 App、豆瓣小组或其他仍存页面，可以用于：

- 观察 URL descendant；
- 理解今天的信息架构；
- 提供 candidate historical URL；

但不能证明：

- 2006 年页面布局；
- 当年字段；
- 当年排序；
- 当年登录要求；
- 当年联系方式展示；
- 当年 mobile/desktop 体验。

所以：

> **current descendant page ≠ historical interface**

如果某个 2008 URL 今天仍能打开，也必须判断是否属于：

- original historical document；
- current database render of old record；
- migrated CMS；
- SEO shell；
- redirect；
- reconstructed/imported archive。

---

# 15. 浏览器、编码与动态资源问题

2005–2010 中文房产/分类信息页面尤其需要检查：

- GB2312 / GBK / UTF-8；
- IE-only JS；
- table layout；
- iframe；
- popup 联系窗口；
- Flash 地图/楼盘展示；
- ActiveX（若存在）；
- 依赖动态 ASP/JSP/PHP query；
- 登录 cookie；
- 图片服务器；
- 站内短信 JS；
- 电话号码是否通过脚本加载。

现代浏览器打开一个 archive HTML 成功，不意味着历史交互功能仍可执行。

例如：

> **contact button rendered ≠ historical contact endpoint replayed**

# 16. 建议的证据 schema 扩展

# 17. Claim ladder

对旧网租房页建议使用以下 claim ladder：

### L1 — page exists

某历史 capture 证明一条租房/合租页存在。

### L2 — function/category exists

证明平台有合租/出租/求租分类或可发布对应信息。

### L3 — listing was publicly visible

证明某条具体信息在某 capture 时刻可公开访问。

### L4 — contact route was exposed

页面确实显示电话/QQ/站内信等联系入口。

### L5 — contact happened

需要私信/邮件/同期自述/新闻等额外证据。

### L6 — viewing happened

需要同期人物材料、帖子 follow-up 等。

### L7 — rental happened

需要合同、明确更新、双方/媒体同期记录等。

### L8 — co-residence happened

证明双方实际共同居住。

### L9 — duration/outcome

证明住了多久、后续更替/退租/冲突。

绝不能从 L1/L2 跳到 L8/L9。

# 18. 2005–2010 目前可写的最小历史结论

在现有证据门槛下，本仓可以较有信心地写：

1. **2005 年**同期媒体已观察到网站上的普通用户合租帖子，并明确说类似信息同时存在于都市报、房产网站与大学校园。
2. **2006 年**同期上海记者实际浏览过上海热线租房栏目，并描述大量合租帖；网上发布信息可以很快导向线下看房和入住。
3. **2006 年**低价/好地段的网上租房信息也可能连接到整租后切割分租等“群租”经营形态，因此网页 category 不能代替物理住房 topology。
4. **2007 年**校园 BBS 已承担过去实体信息栏的一部分生活信息功能，但实体 noticeboard 并未立即消失。
5. **2008 年**高校周边找房仍同时依赖墙贴、现场经营者、房产中介和网络；线上化不是单一路径替代。

这些结论全部不需要假装我们已经拿到原始数据库。

# 19. 目前不知道的关键事实

1. 2005《市场报》引用的原帖 URL、平台与 capture。
2. 2006 上海热线租房栏目当日的栏目 URL、分页规则与 listing schema。
3. 上海热线当时联系方式是明文 HTML、脚本加载、登录后显示还是其他方式。
4. 是否存在可验证的 Wayback / Common Crawl / 其他 WARC 覆盖。
5. 同一物理房源被多少平台重复转载。
6. listing 成交后是自动标记、用户删除还是自然过期。
7. 站内搜索是否可按性别、价格、地点、房型筛选室友/房源。
8. BBS 里的租房帖是否主要转电话/QQ，还是有站内回复形成可见后续。
9. 成功入住后是否存在“已找到/封帖/谢谢大家”一类 follow-up，以及它的保存率。
10. 多时点账号能否证明一个人连续换室友、换房或跨城。

# 20. 下一轮最高价值取证目标

优先级高于继续收集媒体专题的，是一个**可验证的 2005–2010 原生租房 artifact chain**。

理想目标：

```text
historical board/category capture
→ specific listing capture
→ later edit / repost / closed state
→ non-sensitive public follow-up indicating outcome
```

候选方向：

- 上海热线历史房产/租房 host；
- 2005–2010 校园 BBS 可公开 archive 的 housing board；
- 早期地方分类信息站；
- 公开、无需复原私人数据的 archived portal pages。

取证时必须：

1. 记录 original URL 与 memento URL；
2. 验证 capture，而不是只登记搜索结果 locator；
3. 检查字符集和动态资源；
4. 不公开普通人历史联系方式；
5. 区分媒体引用、原始页面和研究者推断；
6. 不用今天的分类信息页面补画 2006 界面；
7. 没有 outcome 就明确写 `unknown`。

# 21. 本专题给旧网方法增加的硬边界

```text
physical noticeboard ≠ web board
press-observed listing ≠ archived listing
listing URL ≠ dwelling
listing visible ≠ room available
category label ≠ dwelling topology
profile field ≠ verified identity
contact info displayed ≠ contact happened
contact happened ≠ viewing
viewing ≠ rental
rental ≠ move-in
move-in ≠ durable co-residence
many URLs ≠ many dwellings
page deleted ≠ listing was false
page survived ≠ transaction failed
current descendant interface ≠ historical interface
historical public contact info ≠ ethically republishable contact info
```

最重要的一条是：

> **旧网可能保存“有人在找室友”，却系统性无法保存“最后谁真的和谁一起生活”。**

对普通生活史而言，缺失的恰恰是最后那一段。
