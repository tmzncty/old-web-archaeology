# 租房分类信息、合租帖与现实入住：2002–2010 中文旧网的 vacancy / authority / tenancy state gaps

> 本文研究对象是约 2002–2010 年中文 Web 上的租房分类信息、租赁信息版与合租帖，重点不是写房地产史，而是回答：**一条“房屋出租/求租”网页证据，究竟能证明现实租住链条中的哪一步？**

生活史对应研究：

- `tmzncty/how-people-lived/topics/rental-housing-roommate-search-urban-footholds-and-residential-optionality-china-2002-2025.zh-CN.md`

本文件严格保持仓库约 1995–2015 中文旧网 scope。Web 以前的熟人、报纸、校园广告只作为必要的媒介前史，不把本仓扩成一般住房史或全球分类广告史。

---

## 1. 先固定研究单位：listing 不是 tenancy

租房旧网尤其容易把不同层级混成一个对象。至少要区分：

- **platform / service**：某分类信息服务、门户房产频道、地方信息版；
- **board / category**：例如某城市“房屋租赁信息版”；
- **listing / post**：一条具体招租、求租、转租、合租帖；
- **account / contact identity**：发布者账号、昵称、电话或即时通信身份；
- **dwelling / room**：现实中的房屋、床位、房间；
- **rental authority**：发布者是否真是业主、承租人、经纪人，是否有转租权；
- **transaction state**：联系、看房、付押金、签约、入住、续租、退出；
- **capture**：档案或当前网站留下的一次页面表示；
- **claim**：研究者从上述证据中能安全作出的最小结论。

因此：

> **`listing survived ≠ room survived ≠ room was vacant ≠ poster had authority ≠ tenant moved in`**

---

## 2. 最小执行状态机

建议以后任何租房 Web case 都按这条链做缺失检查：

```text
现实房间存在
→ 发布者掌握/声称掌握出租权
→ listing/post 发布
→ 被搜索/浏览/索引
→ 求租者看到
→ 联系信息当时仍有效
→ 房源当时仍空置
→ 电话/短信/QQ/站内信联系
→ 约定看房
→ 实际到场看房
→ 核验房屋与出租/转租权
→ 协商租金、押金、租期、费用
→ 付款
→ 合同/简单协议
→ 钥匙/门禁交接
→ 实际入住
→ 真实条件与网页描述核对
→ 后续交租/分摊水电
→ 续租或退租
→ 押金返还/纠纷/迁出
```

Web archive 通常只能覆盖这条链的前半段，而且连前半段也未必保存动态状态。

## 3. 2002：网络“房屋租赁信息版”已经进入混合找房栈，但成功结果不可见

《扬子晚报》2002-08-24 的同期报道（新浪存页）记录了两个并行找房者：[1]

- 一名本地居民为了装修过渡，连续跑五六家房产中介，又查看报纸分类广告；
- 一名外来求职者从 8 月中旬开始，连续在某网络的“南京房屋租赁信息版”发求租小套/单室帖，但一直没有得到回音。

报道还观察到：该版求租帖点击数往往很少，而小套、单室招租帖可有几十或上百次点击。[1]

这是一条很有价值的 **B 级近同时代二手证据**：它能证明 2002 年确实存在被普通求职者使用的网络租赁信息版，并且记者观察到了帖子与点击量差异。

但它不能证明：

- 该信息版的原始 URL；
- 服务器软件；
- 字符集；
- 浏览器兼容要求；
- 点击数统计逻辑；
- 发帖者是否通过站内消息或电话收到私下回应；
- 求职者后来是否通过别的渠道成功租房。

### 本轮负结果

本轮没有可靠恢复该 2002 年“南京房屋租赁信息版”的 A 级原始历史 capture，也没有找到足够证据确定其 original URL。

因此：

> **不得从新浪报道反推一个 guessed URL，再把 guessed URL 当作 historical original。**

这里的正确结论是：`board use exists (B)`, `original page not recovered`。

## 4. “网上信息更多”不等于“房源更容易得到”

同一篇 2002 报道非常适合建立一个动态状态缺口：

- 求租者可以连续发帖；
- 招租帖可以获得大量点击；
- 小户型现实供给仍然紧张；
- 最终匹配仍可能失败。[1]

因此必须新增：

### `vacancy-state gap`

一张招租页面只能证明某时刻发布者**声称**有房可租。

它不能自动证明：

- capture 时仍未出租；
- 页面价格仍有效；
- 房主尚未撤单但忘记删帖；
- 同一套房没有被多个中介重复发布；
- “求租”者后来没有线下成交。

对于租房页，**页面内容时间与现实 vacancy 时间可能以小时或天为单位快速分离。**

## 5. 分类信息必须放回线下媒介环境

2002 年另一篇南京同期报道明确说，当时学生一般通过熟人或校园广告找房，公司集体或工作不久的白领更可能通过“房屋银行”等中介渠道。[2]

2007 年《北京晨报》又在人大、北大等高校直接观察到大量“床位出租”纸质广告，带有按月/按日价格，联系电话被迅速撕走。[3]

因此旧网不能写成整齐的：

```text
报纸/广告 → Web → App
```

真实情况更接近：

```text
熟人
+ 校园/社区纸贴
+ 报纸分类广告
+ 中介门店/登记本
+ 电话
+ Web 分类信息/BBS
```

不同入口并存，而且成交经常迅速离开 Web 进入电话与线下。

这产生 **cross-channel outcome gap**：

> 一个帖子后来“没人回复”，可能是真的失败，也可能是电话成交后网页没有任何状态变化。

## 6. 2010 合租案例：listing → 简单协议 → 入住，仍不能证明转租权

2010-01-11 的同期报道保存了一条难得的较长 execution chain：[4]

1. 2009 年 7 月，一名租客在网上看到合租信息；
2. 觉得条件和价格合适；
3. 与发布合租信息的女孩签了简单协议；
4. 支付 3 个月房租和押金；
5. 实际入住并共同居住约半年；
6. 后来又支付未来 3 个月房租；
7. 真正房东随后上门，称与原承租人的合同已经到期，而且此前不知道这名合租者存在；
8. 发布者失联，合租者被迫搬走。[4]

这个案例最重要的不是“网上租房会被骗”，而是它证明：

> **甚至 `半年实际入住` 都不能倒推 `最初发布者拥有持续有效的转租权`。**

因此新增：

### `rental-authority gap`

需要分别验证：

- 所有人身份；
- 原始租赁合同；
- 是否允许转租；
- 原合同何时到期；
- 转租者是否仍有权收未来租金；
- 房东是否知情/同意。

`poster identity`、`room possession`、`rental authority` 是三个不同状态。

## 7. 合租 Web 还暴露一个很强的隐私边界

2010-01-20 成都同期案件报道显示，一名年轻女性为了找合租者，在多个网站发布出租信息，把具体楼层门牌和手机号直接公开；犯罪者利用这些信息约看房后实施犯罪。[5]

这个案例不能用来统计网络合租风险率，也不应猎奇化。但对旧网考古有一个直接结论：

### `contactability–privacy tradeoff`

早期分类信息常通过公开：

- 手机号；
- QQ/MSN；
- 性别；
- 大致甚至精确住址；
- 上班/看房时段；

来提高现实匹配效率。

但这也意味着历史页面如果今天仍可检索，可能重新暴露已经过期十余年的私人住宅与联系方式。

因此本仓的 stop condition 在租房材料上应更严格：

> **研究页面结构时优先抽象字段，不重新发布普通人的旧门牌、手机号、身份证明、室友私人情况。**

`historical public ≠ present-day ethical republication`。

## 8. 2010 的“合租热”证明 search abundance 与 real dwelling structure 也不能混写

2010 年《法制晚报》报道称，当时用搜索引擎检索“北京合租房”可以得到大量结果；记者同时实地看到两居室被重新分隔成多间出租，并记录到房间很快被订走的现场。[6]

这至少说明两层同时存在：

1. **information abundance**：线上可发现的合租信息很多；
2. **physical re-partitioning**：现实住房本身可能被二次分割，创造更多按间/按床可交易单元。

因此 listing 的“房间数”也不是天然的建筑属性。

新增：

### `unit-definition gap`

一个网页写“4 居”时，需要问：

- 原始户型真是 4 居？
- 客厅/餐厅是否被隔断？
- 是按整套、房间还是床位计价？
- 同一物理住宅是否被多个 listing 拆成不同商品？

如果没有现场/产权/户型证据，不能用 listing category 重建真实建筑结构。

## 9. 2002–2010 租房 Web 的主要 archive gaps

### 9.1 `listing-snapshot gap`

一份 capture 是某时刻的页面，不是整个出租周期。

### 9.2 `vacancy-state gap`

页面还在，不代表房还空着。

### 9.3 `duplicate / cross-post gap`

同一套房可能被业主、中介、二房东在多个站点重复发布；不能把页面数当房源数。

### 9.4 `ranking / discoverability gap`

知道 URL 存在，不代表普通用户当时通过站内搜索或搜索引擎能看到它。排序、置顶、刷新、付费推广通常很难保存。

### 9.5 `contact-handoff gap`

电话、短信、QQ、MSN、站内信通常不进入网页 archive；但真正成交往往从这里开始。

### 9.6 `viewing-outcome gap`

“约看房”与“实际看过”无法由 listing 本身证明。

### 9.7 `rental-authority gap`

发布者可能是房东、经纪人、原租客、二房东或没有有效权利的人。

### 9.8 `photo/reality gap`

图片即使保存，也不证明拍摄时间、朝向、装修现状和实际出租房间完全一致。

### 9.9 `contract/deposit gap`

合同、押金、服务费、违约约定往往属于私人执行层，公共页不会保存。

### 9.10 `tenancy-duration gap`

入住一天、半年、续租五年，在 listing archive 中可能完全不可区分。

### 9.11 `deposit-return / exit gap`

退租、押金返还、损坏争议通常发生在页面生命周期结束以后。

### 9.12 `success-deletion / stale-listing ambiguity`

帖子消失可能因为成交、过期、用户删除、平台清理、账号注销或整站消失；帖子仍在也可能只是忘记删除。

因此：

> **deleted listing ≠ successful rental**
>
> **surviving listing ≠ failed rental**

## 10. 旧租房页还可能系统性过度保存“招牌”，低度保存“真实生活”

这类 Web 有明显的证据不对称：

更容易留下：

- 分类频道首页；
- 房源标题；
- 价格；
- 区域；
- 平台帮助页；
- 中介广告；
- 媒体报道。

更难留下：

- 电话有没有接通；
- 房源当时是否已经租出；
- 实际看房感受；
- 房东是否真有权出租；
- 室友是否相处得来；
- 押金是否退还；
- 半年后人是否仍住在那里。

所以租房 Web 是典型的 **process web**：网页只是把陌生人送进一条私人现实流程。

## 11. Complaint-return bias：坏结果更容易重新回到公共 Web

顺利租住的路径经常是：

```text
看到帖子 → 打电话 → 看房 → 成交 → 帖子删除/过期
```

它可能几乎不留下后续公共文本。

而出现：

- 二房东失联；
- 押金争议；
- 虚假房源；
- 房东驱赶；
- 安全事件；

时，当事人才更可能报警、发帖或接受媒体采访。

因此幸存材料会出现 **complaint-return bias（投诉回流偏差）**。

这意味着 2010 年的欺诈/安全报道适合用来证明“这些执行状态可以失败”，但**绝不能拿报道数量估算网络租房失败率**。

## 12. 制度页面也不能替代实际执行

2004 年高校学生住宿管理规则经同期媒体广泛报道，2005 年教育部正式通知又继续引用 2004 年住宿管理要求。[7][8]

这能证明学生校外租住除了市场交易，还可能有学校备案、家长签字和住宿管理接口。

但同年、同后的同期报道也反复讨论执行困难。[9]

所以仍必须保持：

```text
policy exists
≠ school implemented identically
≠ each student registered
≠ off-campus renting disappeared
```

这与旧网方法中的 `exists / available / used / caused` 分离完全一致。

## 13. 与全球前史的边界：放到 how-people-lived，而不是扩张本仓 scope

跨国生活史材料显示，1992 年法国 FNAIM 已经通过 Minitel 提供可检索的小房间租赁信息；这证明“远程数字租房信息”早于 WWW。[10]

但这类全球互联网/前互联网比较只用于说明机制，不应把 `old-web-archaeology` 改造成全球租房网络史。

本仓仍只做：

> **1995–2015 中文旧网的页面、平台、社区习惯、浏览环境、存档缺失与执行状态证据。**

全球前史与普通生活意义放在 `how-people-lived`。

## 15. 这轮明确没有证明什么

本轮没有证明：

- 2002 年南京信息版的确切 URL；
- 该版是独立 BBS、门户分类频道还是其他技术形态；
- 原页面使用 GB2312、GBK 还是其他编码；
- 当时使用 IE/Netscape 的具体兼容差异；
- 2002 求租者最后是否租到房；
- 2009 合租原帖的 URL、账号或页面布局；
- 2010 合租安全案件原始 listing 的页面结构；
- 某个平台的 listing 数等于真实出租房源数；
- 网络租房比线下租房更安全或更危险。

这些都应继续保持 unknown，而不是用常识补齐。

## 16. 下一步：最值得找的不是更多新闻，而是一条可匿名化的多时点原生链

最高价值目标是 2002–2010 某个公开博客/BBS/个人记录中，能合法、最小化恢复：

```text
第一次发/看到租房帖
→ 电话/QQ 联系
→ 看房
→ 付押金/签约
→ 入住
→ 数月后换室友/搬家/续租
→ 再次使用另一个平台或渠道
```

理想情况下至少有两个独立历史时点，并能把：

- `post date`
- `contact handoff`
- `move-in date`
- `move-out date`

分开。

如果找到，仍应删除/抽象：旧手机号、门牌号、普通个人实名、身份证/合同编号及不必要的私人细节。
