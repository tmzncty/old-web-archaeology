# TRAVEL_FORUM_TRIP_REPORT_ITINERARY_COMPANION_AND_REAL_WORLD_JOURNEY_STATE_GAPS_1998_2015

## Scope

本说明研究约 1998–2015 中文旧网中的一个此前未单独建模的对象：**旅行论坛、游记/攻略、结伴帖与现实行程之间的状态差异**。

本仓 scope 仍保持中文旧网，不扩成全球旅行史。1980s CompuServe、1990s Thorn Tree 等海外材料只作为 `tmzncty/how-people-lived` 的前史和跨国对照；本文件只在必要处引用它们说明“在线旅行共同体早于中文大众 Web”。

对应生活史专题：

- `tmzncty/how-people-lived/topics/independent-travel-forums-gap-years-working-holidays-and-self-authored-mobility-china-1980-2026.zh-CN.md`

核心问题不是“穷游网什么时候成立”，而是：

> **一篇旧攻略、一个‘求同行’帖子、一个行程单或一页目的地论坛，究竟能证明什么？它们与真正买到票、拿到签证、见到同行者、完成路线之间隔着哪些已经消失的状态？**

---

## 1. 研究单位：不要把“攻略页”当成旅行

至少区分：

- **platform**：旅行门户、BBS、论坛、博客平台、SNS；
- **forum/board**：目的地版、结伴版、签证版、交通版；
- **account**：发布者账号/昵称；
- **post/thread**：结伴帖、问答、游记、攻略；
- **itinerary artifact**：公开写出的路线、日期、预算、交通计划；
- **reply / private handoff**：回帖、站内信、QQ、Email、电话等后续联系；
- **travel-companion relation**：现实中是否真正组成同行关系；
- **booking state**：交通、住宿、门票等是否真正预订；
- **document state**：护照、签证、通行证等是否实际有效；
- **journey state**：是否出发、到达、中断、改变路线、返回；
- **retrospective post**：旅行结束后重新写出的经验；
- **archive capture**：今天能看到的某一历史页面表示。

最基本硬规则：

```text
route described
!= route executable
!= route booked
!= route traveled
!= route completed as described
```

## 2. 关键状态链

### 2.1 攻略链

```text
real-world experience
→ author remembers/selects events
→ post drafted
→ post published
→ page indexed / linked
→ another user discovers it
→ user interprets it
→ user checks current validity (maybe)
→ user builds own itinerary
→ real-world execution
```

任一步都不能自动推出下一步。

### 2.2 结伴链

```text
poster intends trip
→ companionship post created
→ other user sees post
→ reply/private contact
→ identity/trust negotiation
→ dates/routes aligned
→ tickets/docs obtained
→ offline meeting
→ travel together
→ relationship survives / ends / changes
```

因此：

> **reply != companion**

> **companion agreed != departure**

### 2.3 游记链

```text
journey event
→ selected memory
→ text/photo production
→ upload
→ moderation/editing
→ public display
→ later archive capture
```

所以：

> **trip report = public narrative artifact, not raw journey log**

即使完全真诚，作者仍会省略失败、无聊、临时改道、私密冲突和大量普通时间。

## 3. 前史边界：Internet 没有发明自助信息，也没有发明在线旅行共同体

### 3.1 中国前 Web：纸质路线信息已经可以支持部分自编旅行

1980 年《全国铁路旅客列车时刻表》、1987 年《丝绸之路旅游指南》、1991 年《北京生活指南》等可核书目证明，在大众 Web 以前，时刻、地图、交通和服务信息已经通过纸质出版物流通。

证据：

- National Diet Library, 《全国铁路旅客列车时刻表 1980年10月》：
  https://ndlsearch.ndl.go.jp/books/R100000002-I024469462
- CiNii Books, 《丝绸之路旅游指南》，1987：
  https://ci.nii.ac.jp/ncid/BB13745616
- CiNii Books, 《北京生活指南：居京旅游必备》，1991：
  https://ci.nii.ac.jp/ncid/BD09685843

等级：**A-bibliographic**。只证明出版物存在，不证明普通家庭拥有、阅读或实际旅行比例。

这类材料属于本仓 `PREHISTORY_BOUNDARY` 的背景，不将 old-web 主研究对象前推到 1980s。

### 3.2 海外在线前史：1986 CompuServe Travel Forum

1986 年《TIME》同期报道记录一名用户拨号进入 CompuServe Travel Forum 获取牙买加信息，再查询电子 Official Airline Guide 的班次、票价和座位可用性。

证据：

- TIME, 1986-04-07：
  https://time.com/archive/6705857/computers-calling-up-an-on-line-cornucopia/

等级：**B/A-near-primary contemporaneous media**。

它说明“陌生人讨论 + 结构化旅行数据库”早于 Web；但本仓不继续研究 CompuServe 页面形态。

## 4. 1998–2004：中文旅行 Web 的考古对象不是一个统一“旅游网站”

到 2000s 初，中文 Web 的旅行信息至少可能出现于：

- 门户旅游频道；
- 航空公司/酒店网站 BBS；
- 城市生活 BBS；
- 专门旅行论坛；
- 个人主页/博客；
- OTA 的机票+酒店产品；
- 搜索引擎缓存/转载页。

同样写着“自助游”，其 authority 完全不同：

```text
forum advice
!= travel-agency product
!= OTA package
!= airline schedule
!= visa authority
!= actual seat inventory
```

因此旧页考古必须保存**是谁在说**，不能只保存内容文本。

## 5. 2005：航司 BBS 把在线帖子直接接到现实结伴与机票

2005 年《武汉晚报》经新浪报道一名徐姓用户登录港龙航空网站 BBS，看到招募香港—曼谷自助游同行者的消息，后来加入临时组团，利用多人同行取得机票价格，并收到酒店建议，完成约六日行程。

来源：

- 2005-04-11，同期媒体：
  https://finance.sina.com.cn/money/tz/20050411/13167105.shtml

等级：**B**。我们目前没有取得该 BBS 帖的 historical capture；因此可以证明“同期媒体记录了这种 workflow”，不能复原具体板块 URL、帖文结构或页面 UI。

由此新增状态：

```text
forum post exists
!= airline endorses poster
!= companion identity verified
!= group fare obtained
!= hotel booking confirmed
!= journey completed
```

并且：

> **hosted by an airline != transaction itself was airline-authoritative**

一个航司 host 上的社区内容可能只是用户生成内容。

## 6. 2006–2008：结伴帖子把陌生人变得可寻址，但现实责任与安全并不在帖子里

### 6.1 2006 南宁户外结伴案件：论坛组织 ≠ 旅行社组织

同期法律/媒体报道记录南宁生活类网站旅游 BBS 上的自组织户外活动遭遇山洪并发生人员死亡，随后出现组织者责任争议。

本文件只使用它证明结构，不复制个人敏感细节：

```text
forum organizer
!= licensed travel agency
!= professionally trained guide
!= insurer
!= emergency authority
```

证据等级：**B**，且同一案件多篇后续报道只算一个 evidence family。

这是一条重要 archive 边界：如果未来只找到原始招募帖，它最多能证明**出发前公开表达的计划与规则**，不能单独证明当天现场谁实际负责什么。

### 6.2 2008 常州：本地门户“求同行”

2008 年《常州日报》经新浪报道，一名银行职员因一直找不到徽州自助游同行者，在当地门户论坛发帖后找到同好并组团。同期报道还观察到结伴帖既可能只有“求同行”，也可能写具体时间、目的地和路线。

来源：

- 2008-09-25：
  https://news.sina.com.cn/o/2008-09-25/103814498769s.shtml

等级：**B**。

新增状态：

```text
post author location
!= actual departure location
planned date
!= actual date
stated budget
!= actual expense
reply count
!= companion count
thread closed
!= trip completed
```

## 7. 攻略/游记把现实经验转成可继承路线，但“可继承”有时间版本

### 7.1 route-version state

每一条攻略至少要记录：

```yaml
post_published_at:
journey_date_if_known:
destination_scope:
transport_claims:
lodging_claims:
price_claims:
visa_or_document_claims:
safety_claims:
external_urls:
contact_endpoints:
revision_or_edit_timestamp:
```

因为：

> **publication date != journey date**

> **page still online != advice still current**

### 7.2 价格、时刻与制度的衰变速度不同

同一篇旧游记可能同时包含：

- 长期稳定的地名/景观；
- 一两年即变化的旅馆；
- 几个月即变化的价格；
- 随季节变化的交通；
- 随政策变化的签证/边境规则；
- 随事故/工程变化的安全条件。

因此建议新增：

**`route-obsolescence vector`**，而不是一个简单 `is_outdated=true/false`。

## 8. 2006–2010：“间隔年”在旧网里是叙事标签，不是自动可验证的履历状态

孙东纯 2009 年新浪博客自述其 2006-12 出发、原计划约三个月但最终旅行约 13 个月，并参与志愿活动；同期《科学时报》围绕《迟到的间隔年》出版进行报道。

来源：

- 新浪博客，2009-08-16：
  https://blog.sina.com.cn/s/blog_572bd9fc0100edar.html

等级：

- 博客本人叙述：**A-personal primary for self-report**；
- 媒体采访/书讯：**B**；
- 后来将其描述为“中国间隔年文化起点”的文章：**C/B retrospective**，不得倒推。

考古上必须区分：

```text
author labels experience "gap year"
!= employer records career gap same way
!= school records leave same way
!= visa records purpose same way
!= whole period consisted of travel
```

一个公开博客只能证明作者怎样叙述自己的时间，不能替代制度履历。

## 9. 2008 Working Holiday：论坛里的“去新西兰”最终仍被国家级资格系统执行

新西兰外交贸易部条约数据库记录，中新 Working Holiday Scheme 于 2008-04-07 签署、2008-10-04 生效。

来源（A）：

- https://www.treaties.mfat.govt.nz/search/arrangement/404/220

因此旧网中的“新西兰打工度假攻略”至少必须与这些不同对象分开：

```text
forum claim about eligibility
!= current official eligibility
application submitted
!= quota slot obtained
slot obtained
!= visa issued
visa issued
!= traveler entered New Zealand
entry
!= work obtained
```

这与铁路/航空票务 state-gap 相似，但又多了年龄、资金、健康、语言/教育和年度名额等长期身份约束。

## 10. 2010：旅行博客/论坛已经明显承担“远方想象”的社会传播

中国驻泰国使馆网站 2010 年转载的一篇人物稿保存了几个重要对象：

- 退休夫妇准备半年后背包欧洲；
- 一名旅行者把自助穷游攻略持续写在新浪博客；
- 文章把 Go2eu/穷游网描述为聚合游客攻略、路线和经验的热门自助游网站；
- 26 岁白领李子然大学时会去首都机场看国际航班牌，想象以后飞往陌生城市，毕业工作后才逐步兑现。

来源（B）：

- 2010-10-04：
  https://th.china-embassy.gov.cn/ztbd/ddsds/201010/t20101004_1426784.html

注意：当前仍能访问的 2010 正文并不等于我们已经验证 2010 年当时的 HTTP、CSS、字符集、导航和子资源状态。它是**current legacy render with historical article date**，不能冒充 Memento。

同文对“穷游网自 2004 年成立以来”的陈述仍需用更早的独立来源与历史 capture 复核，不能据一篇 2010 媒体稿复原 2004 UI。

## 11. 2011–2015：Web 旅行共同体与 OTA/移动端重叠后，研究单位进一步碎裂

到 2010s 前半，用户可能同时使用：

```text
论坛/攻略：决定去哪、怎么玩
OTA：查价格/预订
地图：定位/路线
官方站：签证/交通/景点规则
QQ/Email：联系同行者或住宿方
手机 App：途中查询与改订
```

因此不能写：

`platform = travel website`

更适合的是：

```text
planning stack = multiple authorities + multiple channels
```

对于一次具体旅行，论坛往往只掌握**建议和社会协调**，而不掌握库存、证件或支付权威。

## 12. 必须永久保留的 state gaps

### 12.1 `thread-visible / trip-intent gap`

帖子可能是随口计划、征求意见、试探兴趣，并不等于已经决定出发。

### 12.2 `trip-intent / booked gap`

写好路线不代表票、房、签证已经取得。

### 12.3 `reply / offline-contact gap`

回帖不代表交换电话/QQ，更不代表实际见面。

### 12.4 `offline-contact / co-travel gap`

见面后可能发现时间、预算、性格不合，最终不同行。

### 12.5 `itinerary / actual-route gap`

天气、延误、费用、体力、临时兴趣都会改变路线。

### 12.6 `trip-report / complete-experience gap`

游记是选择后的叙事，不是连续日志。

### 12.7 `posted-price / executable-price gap`

旧帖写 50 元旅店不能证明另一日期仍是 50 元，更不能证明当时每个人都能订到。

### 12.8 `visa-advice / authoritative-rule gap`

论坛经验只能证明某次/某人经历；签证制度必须回到官方来源。

### 12.9 `platform-account / legal-identity gap`

昵称和头像不等于护照/身份证身份。

### 12.10 `forum-popularity / traveler-population gap`

论坛活跃用户不是全国旅行者样本。

### 12.11 `archived-thread / surviving-social-graph gap`

正文和回帖可能保存下来，真正转入 QQ、Email、电话后的关系链却消失。

### 12.12 `guide-survival / route-executability gap`

HTML 活着不等于现实路线活着。

## 13. Archive 偏差一：`guide-text survival / route-state loss asymmetry`

旅行攻略特别容易产生一种“保存得很好”的错觉。

静态正文可能保留：

- 地名；
- 作者叙述；
- 路线顺序；
- 当时写下的价格；
- 图片 URL；
- 联系方式。

但真正决定执行的短寿命状态往往已经消失：

- 某班车当时是否仍开；
- 某青旅某晚有没有床；
- 某航班价格库存；
- 某签证窗口临时规则；
- 某边境是否开放；
- 某联系电话当时由谁使用。

所以 archive 能很好保存“**一个人当时怎样想象可走的世界**”，但不一定能保存“**那一刻现实世界究竟允许什么**”。

---

## 14. Archive 偏差二：`public-plan / private-execution inversion`

最容易被 crawler 保存的是：

- “十一想去徽州，求同行”；
- “曼谷六天路线”；
- “某青旅推荐”；
- “预算 3000”。

真正能证明旅行完成的材料却经常在：

- 私信；
- QQ/Email；
- 个人票证；
- 护照出入境记录；
- 酒店订单；
- 私人照片；
- 付款记录。

这些更强的执行证据又往往属于不应公开再传播的私人状态。

因此：

> **privacy minimization intentionally limits transaction/journey reconstruction.**

这是研究伦理边界，不是等待“补齐数据”的缺陷。

---

## 15. Archive 偏差三：`successful-trip visibility bias`

旅行论坛精华、博客首页、媒体人物稿倾向留下：

- 完成长线旅行的人；
- 路线复杂、照片漂亮的人；
- 辞职、间隔年、跨国旅行等戏剧性人生。

更难保存：

- 计划后没钱去；
- 家里不同意；
- 单位不批假；
- 签证失败；
- 同行临时退出；
- 走两天觉得太累回家；
- 普普通通参加两日旅行团。

因此不得根据 old-Web 可见性把 2000s 描述成“年轻人都在辞职远行”。

## 16. 2019 反例为什么应进入 old-Web 的解释层，而不进入主 scope

2019 年中国旅游研究院相关报告经中新网报道，2018 年出境团队游客比例仍为 55.24%，调查里 50.65% 受访者表示未来愿意跟团。

来源：

- https://www.chinaqw.com/hqly/2019/08-05/227997.shtml

它超出本仓主要年代，只用作解释性反例：2000s 旅行论坛和攻略并没有沿一条单向路径“淘汰旅行社”。

这提醒我们不要把 old-Web 的自助游内容高可见性误解成整个旅行人口的行为结构。

## 17. 推荐 transaction/state schema

对于旅行论坛/攻略对象建议至少记录：

```yaml
platform_name:
board_or_channel:
page_url:
page_type:
  - question
  - trip_report
  - guide
  - companion_request
  - visa_advice
  - lodging_advice
  - transport_advice
post_datetime:
journey_datetime_if_known:
author_account_type:
legal_identity_verified: unknown|yes|no
route_scope:
planned_or_retrospective:
reply_state:
private_handoff_observed:
companion_outcome_observed:
booking_outcome_observed:
journey_outcome_observed:
price_claims_time_bound:
official_rule_dependencies:
external_contact_channels:
external_transaction_channels:
archive_source:
capture_url:
original_url:
capture_datetime:
charset_if_verified:
browser_assumptions:
dynamic_dependencies:
missing_subresources:
evidence_grade:
confidence:
privacy_minimization_notes:
```

其中 `journey_outcome_observed` 不应默认从“游记存在”推导。如果是回程后写的游记，只能对游记明确叙述过的阶段提高置信度。

## 18. 历史页面核验：本轮没有达到 M1 capture 门槛

本轮主动搜索了：

- `go2eu.com` / 穷游早期页面线索；
- 2005 港龙航空 BBS 自助游报道所描述的社区；
- 2008 地方门户“求同行”类页面；
- 2009 新浪博客 Gap Year 原帖。

并尝试定位 Internet Archive / Wayback 的历史 capture。当前工作环境没有取得一个能够同时核验以下字段的合格对象：

```text
original_url
capture_url
capture_datetime
HTTP/replay state
charset/content-type
DOM/thread structure
reply pagination
external contact handoff
subresources
second historical time point
```

因此当前状态严格记为：

> **M1 verified historical Chinese travel-forum / itinerary / companion-thread capture: NOT ACHIEVED IN THIS SLICE**

这不等于：

> `Wayback did not preserve it`

可能仍受 URL 不明确、robots、动态论坛参数、登录、编码、域名迁移、搜索引擎索引不足等因素影响。

## 19. 浏览器与编码：全部保持 unknown，除非取得原件

没有 historical capture 前，不从“2005 中文论坛常见形态”推断：

- IE6-only；
- GB2312/GBK；
- frameset；
- table layout；
- Discuz!/phpWind 版本；
- Flash 广告；
- JS 弹窗；
- cookie/session 行为。

媒体今天还能打开一篇旧报道，只证明**当前服务器能返回这篇历史正文**，不是当年的浏览体验。

本文件不是以下已有对象的重复：

- `ONLINE_HOTEL_*`：研究房态/预订；
- `ONLINE_MAP_*`：研究路线计算和地理状态；
- `INTEREST_GROUP_EVENT_*`：研究一般兴趣群体的线下聚会；
- `DATING_*`：研究关系匹配；
- `TRANSACTIONAL_TRAVEL_WEB_*`：研究 12306 等交易型旅行 Web。

这里的独立对象是：

> **ordinary users publish partially structured experience, and later strangers reuse it to author a different physical journey.**

即“用户经验怎样成为下一位用户的路线基础设施”。

---

## 21. 本轮结论

### 已证实

1. 1986 年 CompuServe 已有 Travel Forum + 电子航班数据库这种前 Web 旅行规划组合；
2. 2005 年中国同期媒体已经记录航司 BBS 招募陌生旅伴并完成现实自助旅行的 workflow；
3. 2008 年地方门户论坛存在按目的地寻找同行者的同期使用证据；
4. 2009 年个人博客把长期旅行公开叙述为“间隔年”；
5. 2008 年中新 Working Holiday 制度为“旅行 + 临时劳动”提供正式国家级资格接口；
6. 2010 年主流人物报道已把旅行博客、穷游类论坛和个人路线传播放进自助旅行生活中。

### 高概率但仍需更强证据

1. 2004–2010 专门旅行论坛逐渐形成可重复使用的路线知识库；
2. 目的地板块、签证板块、结伴板块之间存在稳定的用户 workflow；
3. 博客/论坛的搜索引擎可见性显著扩大了旧攻略的时间寿命和传播半径。

### 仍不知道

1. 2005 港龙 BBS 原帖 exact URL / UI / charset；
2. 2008 常州结伴帖原件和后续回复状态；
3. go2eu 2004–2008 可按 METHOD 完整核验的至少两个历史时点；
4. “求同行”帖中有多少最终形成真实旅行；
5. 旧攻略有多少被第二位用户真正执行，而非只是阅读。

## 22. 它改变了什么

中文旧网不只是把“旅行信息”搬到屏幕上。更关键的是，它让**一名普通人的一次性经验获得了下一次被陌生人执行的可能性**。

一张纸质地图可以被许多人读；旅行论坛更进一步：前一个人写“这班车几点开、这家店怎么找、我在这里走错了、十一有没有人一起去”，后一个人可能把这些碎片拼成自己的路线。

因此旧网旅行考古的核心单位不应该只是 pageview 或网站目录，而应是：

```text
experience
→ public artifact
→ discovery
→ trust/evaluation
→ plan reuse
→ private handoff
→ physical journey
```

archive 往往只能保存中间的 `public artifact`。真正值得警惕的是，把这一块幸存的页面误认成整趟人生已经被保存下来。
