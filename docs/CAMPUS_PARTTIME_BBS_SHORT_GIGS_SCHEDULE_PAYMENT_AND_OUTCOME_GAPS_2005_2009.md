## 0. 为什么兼职 BBS 不能直接并入一般网络招聘

本仓已经有：

`ONLINE_RECRUITMENT_RESUME_DATABASES_APPLICATION_STATES_AND_RESPONSE_GAPS_2000_2004.md`

它主要研究：

```text
vacancy
→ resume/application
→ recruiter screening
→ interview
→ offer
→ onboarding
```

校园兼职/短工有另一种明显不同的执行结构：

- 申请人往往仍是学生，主身份没有退出；
- 工作只有一天、周末、寒暑假或某个活动周期；
- 帖子本身经常写明“马上”“做到春节前”“双休日”“每天 8 小时”；
- 性别、身高、健康证、学生身份等可成为即时筛选字段；
- contact 很快从 BBS 转到电话、短信、QQ 或线下；
- “录取”之后不一定有正式 onboarding，而可能第二天直接去商场、家庭、培训点或出版社工作；
- 真正需要恢复的是 **是否到场、实际干了什么、做了多久、最后有没有按约拿钱**。

因此本条目的核心边界是：

> **part-time listing survived ≠ worker was still needed ≠ contact happened ≠ person showed up ≠ stated task was the real task ≠ work was completed ≠ promised pay was paid**

## 3. 2005：高校 BBS 已经承载具体的短工信息

### Claim OWR-PARTTIME-2005-01

**2005 年 3 月，《中国青年报》记者称打开北大未名、水木清华、南大小百合等高校 BBS 的“兼职工作版”，可以反复看到招聘学生作者、编书等帖子。**

来源：

- 《大学生“攒书”：满纸拼凑句 一把辛酸泪》
- 2005-03-16
- https://zqb.cyol.com/content/2005-03/16/content_1049616.htm
- 等级：B（同期记者页面观察）

它直接支持：

- 这些 BBS 当时存在与兼职相关的功能空间；
- 至少一类校外雇主/中介把学生写作劳动放进 BBS 信息流；
- BBS 不只是讨论社区，也可以充当本地/群体化 classified board。

它不支持：

- 兼职版覆盖全国大学生；
- 每个帖子都真实；
- 这些工作最后都有人承接；
- 帖子标价等于实付；
- BBS 是当年唯一或主导的兼职渠道。

### Claim OWR-PARTTIME-2005-02

**2005 年另一份同期报道把“各学生论坛上的兼职工作信息版”描述为暑假前明显活跃的空间。**

来源：

- 《近六成大学生参与各类经济活动 兼职热引发忧思》
- 2005-07-16
- https://edu.sina.com.cn/y/i/2005-07-16/164639452.html
- 等级：B（同期报道 + 调查转述）

报道中的调查比例只能描述其调查样本；不能用来推全国兼职率。

### 考古意义：BBS 兼职版是一个有强时间节律的页面群

兼职信息与：

- 寒假；
- 暑假；
- 春节促销；
- 展会；
- 招生活动；
- 周末；

高度相关。

因此，抽一个随机月份的 capture 很可能严重误判平台用途。

固定新规则：

> **off-season board snapshot ≠ annual activity level**

> **one busy capture ≠ year-round popularity**

以后抽样校园兼职版时应把学期/节假日日历写入 capture metadata。

## 4. 2005 本身还是 BBS audience topology 发生变化的一年

2005 年前后，多所高校 BBS 调整校外访问/发言权限。2006 年的同期回顾性报道明确记录水木清华、北大未名、南大小百合等在 2005 年发生从开放型向更校内化访问模式变化，水木清华的校外用户可访问能力发生显著变化。

来源：

- 《高校BBS蜕变为“娱乐风月场” 思想交锋转战博客》
- 2006-07-03
- https://news.sina.com.cn/c/edu/2006-07-03/15389360675s.shtml
- 等级：B（近同时代平台史报道）

这对兼职史非常重要，因为同一个“兼职版”可能在两个时点拥有完全不同的潜在 audience：

```text
开放访问时期：
本校学生 + 校友 + 外校/社会用户（具体权限依站点而异）

校内化之后：
可见/可发帖/可注册人群缩窄，且不同身份权限可能不同
```

不能把 2004 的公开可见性自动投射到 2006，也不能把 2006 的访问限制倒投到更早时期。

新 gap：**audience-boundary gap**。

> **board name survived ≠ same people could see/post throughout its lifetime**

## 5. 2006：兼职帖子本身已经是一张“时间 + 身体 + 证件”的小表格

### Claim OWR-PARTTIME-2006-01

2006 年南京同期报道转述某“大学生兼职论坛”上的春节前促销招聘，字段包括：

- 每日工作时长；
- “做到过年前”；
- 双休日；
- 立即上岗；
- 日薪/月薪；
- 销售提成；
- 性别；
- 年龄；
- 身高；
- 健康证。

来源：

- 《临时促销员节前俏起来》
- 2006-01-23
- https://news.sina.com.cn/s/2006-01-23/09118057577s.shtml
- 等级：B（同期媒体对论坛帖子字段的直接转述）

### 考古意义：part-time vacancy 是短时效 state

一般职位可能挂几周甚至更久；春节促销帖却可能只有几天有效。

真实状态更接近：

```text
employer decides headcount
→ post published
→ event deadline approaches
→ some slots filled
→ remaining headcount changes
→ recruitment closes
→ event starts
→ listing becomes historically stale even if URL remains
```

因此新增：

- **deadline-state gap**；
- **headcount-fill gap**；
- **schedule-compatibility gap**；
- **eligibility-state gap**。

固定边界：

> **listing visible on t2 ≠ vacancy open on t2**

> **advertised headcount ≠ unfilled headcount**

> **user fits job title ≠ user fits date/height/certificate constraints**

## 6. Web/BBS 发现之后，真正的交易很快离开公开页面

校园兼职通常不是完整在线交易。

更现实的状态机是：

```text
post/listing exists
→ student discovers it
→ student interprets wage/time/location/requirements
→ phone / QQ / SMS / BBS mail / in-person contact
→ employer confirms or rejects
→ schedule agreed
→ worker travels to site
→ worker actually shows up
→ actual task becomes known
→ work performed for N hours/days
→ employer accepts/counts work
→ wage calculated
→ payment made / delayed / reduced / disputed
→ repeat job / complaint / silence
```

公开 BBS 通常最多稳定保存到 `post`。

后面的状态则分散在：

- 站内信；
- QQ；
- 手机短信；
- 电话；
- 面试地点；
- 商场；
- 私人家庭；
- 培训机构；
- 工资表；
- 现金支付。

新增：**contact-handoff gap** 与 **execution-outside-web gap**。

这不是“网页没存好”可以完全解决的问题，因为后续本来就不一定发生在 Web。

## 7. 2008：工资争议显示“工作完成”仍然不是最后状态

### Claim OWR-PARTTIME-2008-01

2008 年《中国青年报》同期报道记录了学生兼职中：

- 实际工作内容超出预期；
- 拖欠或少付工资；
- 无补偿加班；
- 未签合同后难以处理工资争议。

其中一名学生回忆寒假到网络公司做网络编辑，招聘时约定的月薪与最后拿到的工资存在明显差异；她后来后悔没有签订劳动合同。

来源：

- 《调查显示赚钱并非大学生兼职首要动机》
- 2008-07-07
- https://zqb.cyol.com/content/2008-07/07/content_2252696.htm
- 等级：B（同期采访；调查比例仅代表该样本）

因此短工状态机必须继续穿过：

```text
performed work
→ employer's calculation of payable work
→ deductions / interpretation
→ actual payout
→ worker accepts / disputes / gives up
```

新增：

- **task-scope drift gap**；
- **pay-calculation gap**；
- **payment-completion gap**；
- **dispute-resolution gap**。

硬边界：

> **worked ≠ paid as advertised**

> **advertised day wage ≠ effective hourly wage**

> **payment dispute ≠ recoverable loss**

## 8. 2009：罕见地看到执行失败又“回流”到 BBS

### Claim OWR-PARTTIME-2009-01

2009 年 7 月 13 日，一篇题为《外地复习班的惨痛经历》的帖子出现在北大未名 BBS，并在当天进入热帖榜。事件发生约一周后的《中国青年报》追踪称：

- 4 名高校学生此前被招去河北一处暑期培训班做教师；
- 到达后对实际教室/居住/施工条件非常不满；
- 3 天后提前回到北京；
- 发帖者在 BBS 叙述经历；
- 组织者约 8 小时后也在同一讨论中回应；
- 报道时已有 200 多条跟帖。

来源：

- 《大学生创业闯入暑训市场获65.7％民调支持》
- 《中国青年报》2009-07-21
- https://zqb.cyol.com/content/2009-07/21/content_2765261.htm
- 等级：B（非常接近事件时点的媒体重构，并采访组织者）

### 为什么这个案例特别重要

大多数兼职执行会在离开 BBS 后彻底消失。

这次却形成：

```text
BBS / recruitment
→ offline travel
→ worksite observation
→ early exit
→ return to BBS
→ public counter-account
→ community replies
```

可以称为 **execution-return loop / 执行回流环**。

它让原本私下的 `worksite outcome` 再次变成公共网络 artifact。

### 但仍不能过度复原

本轮搜索了精确标题及北大未名相关域名线索，没有可靠恢复原线程的 A 级历史 capture。

因此当前不知道：

- 原帖 original URL；
- 完整发帖时间到秒；
- 完整楼层顺序；
- 是否有编辑/删除楼层；
- 当时 Web/Telnet 两种访问是否呈现相同内容；
- 具体 charset / HTML 结构；
- 今日是否仍有可验证 archive memento；
- 200 多回复的精确数量与后续变化。

同时，报道中组织者曾公开个人姓名和联系方式。本仓不为证明状态机而重新复制联系方式；隐私处理遵循“研究必要最小化”。

## 9. 一套专门适用于短工 BBS 的 execution-state model

以后分析兼职、短工、临时促销、家教、展会、暑期培训等旧网 artifact，至少拆成：

```text
S0  underlying task/employer need exists
S1  listing drafted
S2  listing published
S3  listing visible to this audience
S4  worker discovers listing
S5  worker satisfies visible eligibility fields
S6  worker contacts employer / intermediary
S7  employer responds
S8  slot/headcount still available
S9  time/location/duty/pay verbally or textually agreed
S10 worker travels/shows up
S11 actual worksite/task conditions become observable
S12 worker starts work
S13 worker completes some/all promised period
S14 employer calculates accepted work
S15 wage becomes due
S16 payment fully/partially arrives or does not arrive
S17 repeat / referral / complaint / dispute / abandonment
S18 listing deleted, expires, sinks, or survives as stale artifact
```

任何历史证据只能声明它实际支持到哪一层。

例如：

> 一条 2006 年“45 元/天”的论坛帖，最多支持 `S2` 的 advertised wage；不能自动支持 `S16` 的实际支付。

## 10. 本对象新增的 archive gaps

### 10.1 deadline-state gap

帖子仍在，但活动日期已过；URL 生存时间远长于职位有效期。

### 10.2 headcount-fill gap

“招 20 人”是初始需求还是当前剩余名额，capture 通常不知道。

### 10.3 schedule-compatibility gap

公开帖知道班次，却不知道某个看到它的人是否能在课表/主业/照护之外腾出时间。

### 10.4 contact-handoff gap

电话、QQ、短信、站内信把关键协商带出公开页面。

### 10.5 actual-work gap

答应去 ≠ 到场；到场 ≠ 开始；开始 ≠ 干完。

### 10.6 task-scope drift gap

“网络编辑”“促销”“家教”等标签不足以证明实际工作内容和强度。

### 10.7 payment-completion gap

 advertised pay / negotiated pay / calculated pay / received pay 是四个状态。

### 10.8 dispute-state gap

公开投诉可能出现，但最终是否补发、退款、和解或放弃常不可见。

### 10.9 event-expiry bias

短工天然过期快，成功完成以后双方都缺乏继续维护帖子的理由。

### 10.10 complaint-return bias

反而是出现问题时，参与者更可能重新回 BBS 发长帖。

因此：

> **surviving narrative may overrepresent unusually bad or unusually interesting outcomes.**

这与二手交易中的 success-deletion bias 不同：兼职市场还存在一种 **complaint-return bias**，坏结果更可能产生新的公共文本。

### 10.11 cross-post duplication

同一个雇主可以同时发在多个校园 BBS、论坛、QQ群或纸质海报。

所以：

> **many listings ≠ many distinct jobs**

### 10.12 audience-boundary gap

高校 BBS 在 2005 年前后权限变化明显。一条没被公共 archive 抓到的帖子，不代表校内用户当时看不到。

## 11. 页面形态与社区习惯：为什么校园 BBS 对短工特别合适

这里不做无证据的技术决定论，但可以提出几个由同期材料支持的窄机制。

### 11.1 高密度目标人群

同一站点集中大量学生，对：

- 家教；
- 校园写作/编辑；
- 促销；
- 展会；
- 暑期培训；

这种需要年轻、可短期调度劳动力的雇主很有吸引力。

### 11.2 帖子时间性强

职位和活动 deadline 让“新帖/旧帖”本身非常重要；旧帖即使文本仍正确，也可能已经没有执行价值。

### 11.3 社区可以形成事后声誉文本

2009 望都案例说明，线下结果如果足够异常，可以重新回流到同一 BBS，引发组织者回应和群体讨论。

但不能据此假定每份兼职都有评价系统。早期 BBS 的“跟帖声誉”与后来结构化星级评价是不同机制。

## 12. 2005 高校 BBS 访问变化对 archive 的额外影响

旧网考古如果只依赖公开 HTTP archive，容易产生一种误判：

> “后来的公共抓取较少，所以这个版面后来不活跃了。”

但在高校 BBS 场景里，抓取减少还可能来自：

- 校外 IP 访问限制；
- 登录要求；
- 注册边界变化；
- Web 入口权限变化；
- robots / session；
- 帖子本身快速下沉或删除。

所以此类平台必须单独保存：

```text
content activity
!= public-web observability
!= archive capture density
```

这是本轮对中文旧网保存机制的一个实质新增。

## 13. 隐私与伦理边界

兼职旧帖可能带有：

- 手机号码；
- QQ；
- 真实姓名；
- 学校/院系；
- 性别/身高/健康证要求；
- 工资争议中的具体个人指控。

本仓研究目标是恢复**平台机制与生活执行状态**，不是建立二十年前学生联系方式数据库。

因此：

- 不批量重新公开旧手机号/QQ；
- 不因搜索引擎还能检索到就复制个人敏感字段；
- 争议个案优先引用同期媒体，不重新发布不必要的当事人身份；
- 若未来找到原线程 capture，保存 locator/provenance 优先于镜像完整个人内容；
- 已删除私人信息不以“历史研究”为理由重新聚合。

## 14. 已证实 / 高概率 / 不知道

### 已证实

- 2005 年同期记者观察到多个著名高校 BBS 的兼职工作版中存在具体学生劳动招聘帖；
- 2006 年“大学生兼职论坛”招聘可以公开时间、日薪、提成、性别、身高、健康证等条件；
- 2008 年同期采访存在实际工资与招聘时约定不一致、无合同后难以追索等案例；
- 2009 年北大未名出现一次“从线下执行结果返回 BBS”的公开争议，并有双方叙述与大量回复的同期媒体记录；
- 2005 前后高校 BBS 的校外访问边界发生过重要变化，不能把不同年份的 audience 当成不变。

### 高概率 / D 级机制解释

- 季节性兼职版的 capture density 不等于全年真实活动；
- 成功而普通的短工比冲突性短工更不容易留下长篇后续；
- 同一个职位可能跨平台重复发布；
- 公开页面保存会系统性缺少电话/QQ 协商、真实到场、工时与最终工资。

### 不知道

- 2009《外地复习班的惨痛经历》的可靠 original URL 与 A 级 capture；
- 2005 兼职版中某一天的完整 inventory；
- 某一条普通兼职帖最终对应了几个真实申请人；
- 某一条“日薪 45 元”的帖子最后是否按 45 元结算；
- 兼职成功后没有再发帖的人占多少；
- Web、Telnet、站内信在具体站点/年份的执行分工比例。

## 15. 与生活史的交叉结论

`how-people-lived` 侧关心的是：

> 一个人如何在上学或主业之外，维持第二条收入/职业路线？

本仓能补上的是：

> 我们今天为什么经常只能看见“当年有人发了一个兼职帖”，却看不见这份工作究竟有没有进入那个人的一周？

校园兼职旧网把这种断裂展示得非常完整：

```text
公共可保存层：
版名 / 帖子标题 / 招聘条件 / 标价 / 发布时间 / 少数公开跟帖

半私人层：
站内信 / QQ / 手机 / 面试 / 地址确认

现实执行层：
跨城 / 到场 / 工作环境 / 工时 / 临时变更 / 离开

财务结果层：
工资计算 / 扣款 / 现金 / 转账 / 欠薪 / 追索
```

真正“活过”的经历集中在后面三层，恰恰最难被 Web archive 保存。

因此本轮固定一条旧网史原则：

> **一个旧兼职帖是一次生活可能性的公开入口，不是那段生活本身。**

---

## 16. 下一步

最高价值的下一步不是再堆几十条兼职招聘，而是尽量找到一个可复核的 **multi-time execution chain**：

```text
2005–2010 某条原始兼职帖
→ 同账号/同事件后续更新
→ 私下联系已发生的公开证据
→ 到场 / 开工
→ 完成 / 提前退出
→ 工资支付或争议
→ 数周/月后的后续
```

优先寻找：

1. 北大未名 / 水木 / 小百合等已有公开 archive、转载或引用链；
2. 论坛原帖与同期博客复盘的可交叉匹配事件；
3. 不需要重新公开普通人敏感信息的公共争议或公开组织活动；
4. 至少两个历史时点，而不是后来一次性回忆。

若只能找到同期媒体重构而始终找不到原帖，应把“原生执行链未恢复”保留为正式负结果，而不是补造历史页面。
