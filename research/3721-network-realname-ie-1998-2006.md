# 3721 网络实名（1998–2006）：IE 地址栏、客户端状态与“网页之外”的浏览环境

> 状态：**research note，不是完整 M1 case**。本轮获得了多个相互独立的同时代证据 family，可以确认 3721 网络实名并非单纯的服务器端网站服务，而是与 IE 地址栏、本地安装软件、注册表/本地组件和安装提示共同构成使用环境。尚未直接核验历史 Wayback capture、安装包或 CAB/ActiveX 元数据，因此不能声称已完成插件机制、页面编码或历史浏览体验的复原。

## 1. 研究对象与边界

- 对象：**3721 网络实名（Network Real Name）**，而不是把 3721 公司旗下所有产品混成一个对象。
- 时间范围：1998–2006。
- 研究单位：browser-adjacent addressing service / local client + IE address-bar integration。
- 主要历史域名线索：`3721.com`。
- 本轮问题：
  1. “网络实名”究竟只是一个网站，还是依赖本地浏览器状态的软件/服务组合？
  2. 同一时期的 IE 地址栏行为受到哪些本地组件与竞争软件影响？
  3. 2002–2006 的微软 IE 合作能否由同时代来源确认？
  4. 3721 品牌消失时，服务是直接消失，还是进入 Yahoo/阿里巴巴产品谱系？
  5. 为什么现代 Wayback/Chromium 回放即使能看到 `3721.com` 页面，也不足以证明当年的实际浏览体验？

### 明确排除

本笔记暂不把以下对象视为与“3721 网络实名”完全等同：

- “3721 上网助手”及其后续 Yahoo Assistant；
- 3721 的全部工具栏、反弹窗、修复 IE 等产品；
- 后来所有以“中文上网”“中文网址”为名的竞争产品。

它们可能共享组件、品牌或渠道，但在没有版本级证据时不能合并推断。

## 2. 当前最小结论

### 已证实

1. **至少从 1998 年起，3721 网络实名被作为需要下载安装到本地的“地址栏搜索软件”描述，而不只是一个网页。**
   - 现可访问的 2004 年二审判决书转载记载：1998 年三七二一公司推出地址栏搜索软件“3721网络实名”，供用户免费下载、安装，之后持续升级。
   - 当前可访问的是 2011 年对原判决文本的转载，不是法院官网原始数字件，因此本仓把“当前 locator”按 B 级处理；其底层文书属于 2004 年形成的第一手司法记录，但在找到官方/同期扫描件前不把转载本身升级为 A。

2. **2002 年的同时代媒体可独立确认：微软与 3721 的合作使 IE 地址栏直接接受中文词组或拼音，并把输入映射到相应网址/信息。**
   - 2002-12-01 新华社稿（新浪转载）明确称 IE 浏览器支持 3721 网络实名，并解释地址栏关键词通过对照/解析找到对应网址。
   - 该证据能够证明“IE 地址栏集成”的存在；不能单凭该稿件证明具体客户端实现是 ActiveX、BHO、某个 CAB 文件或某个固定版本 DLL。

3. **2002–2004 年的司法事实记录表明，3721 网络实名与其他 IE 地址栏软件发生的是本地软件/注册表层面的冲突，而非普通网页之间的竞争。**
   - 判决转载记录：3721 网络实名与百度 IE 搜索伴侣同时安装时会出现功能冲突；后安装者会改变或替换相关注册表项。
   - 2003 年 6 月版本包含名为 `cnsminkp` 的文件；2003-10-17 的测试记录中，安装 3721 后该文件出现，随后百度 IE 搜索伴侣的下载/安装受到影响。
   - 2005 年的同期知识产权周讯再次转述法院查明的这些事实，可作为独立的近同时代二手来源核对，而不是把一个后来转载页面当成唯一证据。

4. **访问 `3721.com` 本身曾与本地安装状态发生可观察交互：在特定测试环境中会弹出“3721网络实名”软件安装提示框。**
   - 判决转载记录：2002-12-23，在未安装百度 IE 搜索伴侣时访问 `http://3721.com` 会出现 3721 网络实名安装提示；已安装百度 IE 搜索伴侣时则不出现。2003-11-17 仍记录到同类现象。
   - 这说明“页面是否弹出安装提示”至少在法院记录的环境里取决于本地软件状态。
   - 因此，未来即使找到同一日期附近的 HTML capture，也不能直接把现代浏览器无提示的回放等同于历史用户体验。

5. **3721 与微软 IE 的网络实名合作存在一个可定位的 2002–2006 生命周期。**
   - 2002-12 新华社稿确认合作已经存在。
   - 2006-08-03 搜狐报道引述微软方面确认双方因合同到期终止网络实名业务合作，并回溯称 2002 年 10 月达成战略合作。
   - 两个时间点来自不同年份的同时代媒体，能够支持“合作存在并在 2006 年终止”，但不能自动证明合同中未公开的技术细节。

6. **3721 品牌的消失不是简单的“服务突然关站”。2003–2006 间存在明确的收购与改名链。**
   - 2003-11 人民网/人民日报系报道记录 Yahoo 香港与 3721 签署收购协议，并把中文母语上网/关键词搜索技术列为交易对象。
   - 2006-01 的同期报道记录原“3721网络实名”改名为“阿里巴巴网络实名”，并称网络实名、实名网址、实名搜索等产品进入新品牌体系。
   - 这更适合写成 **brand/service lineage**，而不是“3721 在 2006 年彻底不存在”。

### 高概率，但本轮不升级为“已证实”

1. **3721 的自动安装链可能在某些版本/时期使用了 ActiveX 式浏览器控件机制。**
   - 多年后的周鸿祎回忆把早期 3721 插件安装思路与 Flash 插件的 Yes/No 安装提示相联系，并称用户点击确认即可自动安装。
   - 这是 C 级回忆；它与 2002–2004 法院记录中的“访问网站出现安装提示框”相容，但后者没有在当前已核验文本中给出 CLSID、CAB、`<object>`、`codebase` 或签名信息。
   - 因此本轮只保留为进一步寻找历史 HTML/安装包的线索，**不写“3721 网络实名已被证明使用 ActiveX”**。

2. **后来被称为“3721 上网助手/Yahoo Assistant”的 IE 插件谱系可能与网络实名共享部分技术或分发路径。**
   - 当前证据不足以完成版本、组件、产品名之间的一一映射。
   - 在获得安装包版本号、文件清单或官方说明前，不把“网络实名”“上网助手”“Yahoo Assistant”当作同一二进制产品。

### 不知道 / 尚缺证据

- 1998、2000、2002、2004、2006 各关键版本的原始安装包哈希、数字签名与文件清单；
- `3721.com` 安装页在各时期的原始 HTML、HTTP header、`Content-Type` 和字符集声明；
- 是否以及何时存在可核验的 ActiveX CLSID、CAB URL、BHO 注册项；
- `cnsminkp` 的准确文件类型、版本、哈希和在不同产品版本中的生命周期；
- 微软合作究竟通过 IE 默认配置、预装、搜索/地址栏 provider、下载控件还是多种机制共同实现；
- Windows 98/2000/XP 与 IE5/IE6 各版本的兼容矩阵；
- 在没有任何本地 3721 组件的“干净机器”上，`3721.com` 页面本身能完成什么；
- Wayback/Common Crawl 对安装页脚本、CAB/DLL/EXE 子资源的保存程度；
- 2006 改名后旧 `3721.com` URL 的 HTTP 跳转与产品页面迁移链。

## 4. 来源冲突本身也是史料

3721 是一个很适合训练本仓“厂商声称 ≠ 已验证事实”的对象。

2002–2003 的报道经常引用 3721 对用户覆盖率、每日使用量、营收利润等数据的自述；与此同时，2003-11 的《21世纪经济报道》直接查阅工商年检资料，指出部分财务数字与公司此前公开说法不一致。

因此本仓对 3721 的规模数据采用以下规则：

- “3721 当时宣称 X”可以作为历史事实记录；
- “3721 实际覆盖 X% 用户 / 每日有 X 万次使用”不能在没有独立测量或审计时直接写成已证实；
- 与浏览器技术有关的窄结论优先依赖可复核的软件行为、司法记录和独立媒体描述，而不是市场宣传数字。

## 5. 为什么这是一个浏览器环境案例，而不是普通“网站史”

当前证据已经支持一个重要的结构判断：

```text
用户输入中文关键词
        ↓
IE 地址栏
        ↓
本地网络实名软件 / 本地配置状态
        ↓
关键词解析 / 地址映射
        ↓
目标 URL / 搜索结果
```

而且 2002–2004 的司法记录进一步说明，本地状态并不是抽象假设：

```text
是否安装 3721
是否安装百度 IE 搜索伴侣
安装先后顺序
注册表项是否被替换/删除
本地 cnsminkp 是否存在
        ↓
会改变地址栏功能、安装提示与竞争软件能否安装
```

所以对这一对象，**浏览器本身就是史料环境**。

现代浏览器里打开一个保存下来的 `3721.com` HTML，只能回答“今天的回放系统能呈现什么”。它不能自动回答：

- 当年 IE 地址栏是否已经挂接网络实名；
- 当地机器上是否已经安装客户端；
- 页面是否会触发安装提示；
- 竞争地址栏软件是否改变注册表；
- 重启后哪些设置仍在；
- 安装控件是否被旧 IE 的安全策略允许。

## 6. 一个重要的 D 级推断：HTML-only archive 会系统性低估此类体验

**D 级推断：** 对 3721 网络实名这类对象，只保存主 HTML/图片而不保存可执行控件、安装包、注册表状态和旧浏览器环境，会系统性丢失一部分历史行为。

推断依据：

1. B 级同时代来源确认 IE 地址栏直接参与网络实名；
2. 近同时代司法记录确认本地安装状态、注册表与文件会改变行为；
3. 同一记录确认访问 `3721.com` 时是否出现安装提示受本地软件状态影响。

替代解释/限制：

- 某些时期可能存在无需本地软件的服务器端 fallback；本轮尚未验证；
- 不同 IE/Windows 版本可能表现不同；
- Wayback 本身可能保存了部分 CAB/EXE，只是本轮未直接核验；
- 当前不能把所有缺失交互都归因于 ActiveX。

因此这一推断可以进入未来 M3 实验设计，但不能伪装成已经完成的实验结果。

## 7. “ActiveX”边界：本轮故意不越线

旧网回忆里常把 3721 与“ActiveX 插件”“流氓软件”“IE 插件”直接画等号。对于历史研究，这几个词必须拆开。

当前证据可以直接支持：

- 有本地可下载安装的软件；
- IE 地址栏功能与之耦合；
- 访问网站曾出现安装提示；
- 有本地文件与注册表层面的软件冲突。

当前证据**不能直接支持**：

- 每个时期的“3721网络实名”都通过 ActiveX 安装；
- 某个具体 CLSID/CAB/控件名在 1998–2006 全程不变；
- “上网助手”的所有技术性质都可反推到“网络实名”；
- 所有用户都经历同一种安装提示或同一种安全策略。

后续只有在历史 HTML 中找到明确 `<object classid=...>` / `codebase=...`，或取得带可信 provenance 的原安装包/官方说明后，才应把具体 ActiveX 机制升级为已证实。

## 8. 品牌与服务失踪链

当前可写的最小谱系是：

```text
1998：3721 网络实名作为地址栏搜索软件推出（司法记录转载）
  ↓
2002：微软 IE 地址栏合作可由同期媒体确认
  ↓
2003：Yahoo 与 3721 签署收购协议
  ↓
2006-01：原“3721网络实名”更名为“阿里巴巴网络实名”
  ↓
2006-08：微软确认网络实名合作合同到期、不再续约
```

这个链条的意义是：**品牌名、浏览器合作关系、底层产品、网站 URL 的生命周期不是一回事。**

目前不能声称：

- `3721.com` 在 2006-01 当天立即停止服务；
- 所有客户端自动更新为阿里巴巴品牌；
- 旧网络实名数据库在某个确定日期彻底删除；
- 微软合作终止等于网络实名服务终止。

要把它升级成“页面与域名失踪链”，还需补 2005-12、2006-01、2006-08、2007 等时点的历史 HTTP/capture 证据。

## 9. Archive reconnaissance：本轮的负结果与下一步

本轮重点先建立 claim/evidence family，没有把搜索结果里出现的 Wayback locator 当作已验证 capture。

尚需逐项完成：

1. Internet Archive/CDX：
   - `http://3721.com/`
   - `http://www.3721.com/`
   - 1998–2000、2002-10 至 2003-01、2004、2006-01、2006-08；
2. 寻找历史安装页，而不只首页；
3. 记录主 HTML 的 `Content-Type`、meta charset 与 archive rewrite；
4. 检查 HTML 是否出现 `object` / `classid` / `codebase` / CAB / EXE / DLL URL；
5. 对任何发现的二进制只记录 archive metadata、长度、哈希（若可安全取得）和签名信息，不在仓库重新分发；
6. Common Crawl 仅用于补 host/URL/文本存在性，不把命中等同于高保真回放；
7. 查 ArchiveTeam 是否存在相关 collection/project；“未找到”不得写成“不存在”。

## 10. 可复原程度

当前评级：**结构性/行为性复原：中等；像素级与可执行环境复原：低。**

### 目前可以复原

- 网络实名与 IE 地址栏结合的基本交互模型；
- 1998–2006 若干公司/产品谱系时间点；
- 2002–2004 软件冲突和安装提示的法院记录行为；
- 哪些本地状态变量会改变历史体验的候选清单。

### 目前不能可靠复原

- 原安装页面视觉与 DOM；
- 安装提示框由哪一个精确控件/脚本触发；
- 完整 ActiveX/BHO/注册表实现；
- 当年普通用户的“典型”机器配置；
- 原始安装包行为；
- 页面字符集与旧字体/编码表现。

### 安全实验边界

即使未来获得历史 EXE/CAB/DLL，也不应在日常主机或联网环境直接运行。

如进入 M3 实验，只能在一次性隔离 VM 中：

- 保存来源、哈希、文件长度与时间戳；
- 默认断网或使用受控假网络；
- 快照前后比对文件/注册表变化；
- 不使用真实账号或个人数据；
- 实验输出明确标 `reconstruction` / `experiment`，不称为历史原件。

## 11. C 级回忆与同时代证据的比较

多年后，周鸿祎回忆早期 3721 插件的安装思路受 Flash 插件的 Yes/No 提示启发，并强调自动安装路径非常短。

这段回忆与同时代/近同时代证据之间的关系应写成：

- **相容之处**：法院记录确实表明访问 3721 网站在特定机器状态下会出现网络实名安装提示；
- **不能倒推的部分**：法院文本并未给出 Flash、ActiveX、CAB、CLSID 等实现细节；
- **时间风险**：2018 的回忆距离 1998–2002 已十余年，不能独立确定具体版本和年份；
- **研究用途**：把回忆用作寻找原安装页/二进制的关键词，而不是用来填补缺失技术证据。

这是一个典型例子：C 级记忆可以帮助生成检索假设，但不能替 A/B 级证据完成技术定案。

## 12. 隐私、版权与安全边界

### 隐私

本对象主要涉及公司、产品和公开司法/媒体记录，本轮没有必要复制普通用户账号、浏览记录、联系方式或个人页面。

### 版权

- 不提交 3721、Yahoo、微软或百度的历史安装包、DLL、CAB、页面整包或大段新闻正文；
- 只保存 URL、日期、文号、文件名、技术事实摘要和研究分析；
- archive 可访问不等于允许重新分发历史二进制。

### 安全

历史浏览器插件/安装器属于不可信可执行代码。任何未来二进制分析都视作恶意样本处理，不因“历史软件”身份降低隔离要求。

## 14. 本轮不能声称已经证明的内容
