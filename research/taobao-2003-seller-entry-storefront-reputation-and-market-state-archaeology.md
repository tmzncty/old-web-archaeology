# 淘宝 2003 卖家入口、店铺状态、信用与市场状态考古

> Scope：中文 Web / C2C marketplace，2003–2014；核心历史页面集中在 2003。  
> 与 `how-people-lived` 交叉：个体经营、兼职网店、平台化微型生意和双轨生计。  
> 目标：不是复原“淘宝长什么样”，而是回答一个普通卖家当年如何从首页进入账号、发布商品、拥有店铺、被搜索、积累信用，以及哪些关键状态今天无法从 HTML 恢复。

## 0. 去重

仓库已有：

- `page != transaction`；
- 登录态 / 私有状态缺失；
- 婚恋平台的 `population-state loss`；
- 自考系统的纵向账号状态丢失；
- 电话 / Web / 寻呼等跨协议事务链。

本 note 不再重复这些抽象命题，而聚焦一种此前没有单独处理的对象：

> **一个旧 C2C marketplace 的“市场本身”是一组持续变化的卖家、商品、库存、价格、搜索排序、评价、竞价、余额和交易状态。即使页面壳还在，那个历史市场也可能已经消失。**

本轮新增的领域化概念是：

- `storefront-as-state / 店铺作为状态`；
- `seller-state loss / 卖家状态丢失`；
- `market-state loss / 市场状态丢失`；
- `reputation-schema drift / 信用模式漂移`；
- `visibility-rule drift / 可见性规则漂移`；
- `online-offline transaction hybrid / 线上发现—线下成交混合`。

---

## 1. 研究单位

依照 `docs/METHOD.md`，这里严格区分：

1. **platform**：淘宝 Marketplace；
2. **site / host**：`www.taobao.com`、`member.taobao.com`、`aucpost.taobao.com` 等；
3. **page**：首页、注册页、卖家入口、具体店铺、具体商品；
4. **account**：某个历史用户 / 卖家账号；
5. **storefront**：账号下可被买家发现的店铺状态；
6. **listing**：一条商品 / 求购 / 海报信息；
7. **market state**：某一时点全部可见 listing、搜索结果、买卖双方、价格、信用、竞价与库存状态；
8. **capture**：Internet Archive 保存的一份回放；
9. **claim**：本 note 可被证据直接支持的窄结论。

不能把“2003 首页被保存”写成“2003 淘宝市场已经复原”。

## 3. Capture B — 2003-08-02 卖家发布入口

- `archive_source`: Internet Archive
- `original_url`: `http://aucpost.taobao.com/sellstart.php`
- `capture_url`: https://web.archive.org/web/20030802061525/http://aucpost.taobao.com/sellstart.php
- `capture_datetime`: **2003-08-02 06:15:25**
- `collector`: Alexa Crawls
- `accessed_at`: 2026-09-13
- `evidence_grade`: A

页面标题区为“发布宝贝 - 浏览求购信息”。

页面首先建议卖家去“求购集市”看是否已经有人需要自己想卖的东西；又说明家中闲置书籍、手机、VCD 等可以放到淘宝出售，同时将有进货需要的卖家导向阿里巴巴寻找货源。

更重要的是，它列出四种不同的卖法。

### 3.1 拍卖

卖家设定起始 / 底价等拍卖条件，由买家竞价。

### 3.2 一口价

卖家给出固定价格，买家接受即进入交易。

### 3.3 讨价还价

交易允许买卖双方围绕价格进一步协商。

### 3.4 “贴张海报”

页面说明可以把联系方式让别人知道，再约时间面谈。

这条证据尤其重要，因为它直接否定一种后见式想象：

```text
淘宝从一开始就是
页面 → 平台支付 → 快递 → 平台内闭环
```

2003 年实际可观察的交易逻辑至少包括：

```text
Web 发现商品 / 卖家
→ 获取联系方式
→ 约定时间
→ 线下面谈 / 当面交易
```

因此新增：

**`online-offline transaction hybrid / 线上发现—线下成交混合`**。

旧 Web 考古不能把后来成熟电商的闭环支付 / 物流习惯倒投到早期 C2C。

## 4. Capture C — 2003-08-01 免费开户与服务条款

- `archive_source`: Internet Archive
- `original_url`: `http://member.taobao.com/register.php`
- `capture_url`: https://web.archive.org/web/20030801080124/http://member.taobao.com/register.php
- `capture_datetime`: **2003-08-01 08:01:24**
- `collector`: Alexa Crawls
- `accessed_at`: 2026-09-13
- `evidence_grade`: A

这是本轮最重要的 artifact 之一，因为它不是后来新闻对注册流程的描述，而是历史网页本身。

页面首先说，在淘宝买卖“要先开个户口”，随后保存了大量当时服务条款。

可直接观察到的条款结构包括：

- 注册意味着用户登录淘宝、按要求填写信息并确认协议；
- 用户拥有用户名和交易密码；
- 用户可以查询物品、发布交易信息、竞买、与其他用户订立交易并评价信用；
- 用户需要提供真实资料，并保证电子邮件、联系电话、联系地址、邮编等信息有效；
- 用户不得通过不正当方式提高自己或降低他人的信用；
- 淘宝把网站界定为用户寻找交易对象、协商商品与服务交易的“地点”，而不是每笔买卖的买方或卖方；
- 网站提醒用户自行判断商品、信息及交易方的真实性和履约能力。

### 4.1 重要方法结论：注册页比首页更接近“制度接口”

首页告诉我们：

```text
这里可以开店
```

注册 / 条款页则告诉我们：

```text
谁可以成为账号
账号需要承担什么责任
平台认为什么叫交易
哪些身份 / 联系字段必须存在
信用评价在系统里是什么权利与义务
```

因此，对 marketplace 的考古不能只截首页。

## 5. Capture D — “我要卖”动作跳转到登录

从 2003-08-02 的卖家页进一步点击具体发布方式后，Wayback 保存了一个 302：

- original URL: `http://aucpost.taobao.com/sell.php?atype=b`
- crawl timestamp: **2003-08-02 11:22:21**
- HTTP: **302**
- redirect target: `member.taobao.com/login.php?...`

可核验 capture：

https://web.archive.org/web/20030802112221/http://aucpost.taobao.com/sell.php?atype=b

这条“失败页面”本身反而很有价值。

它证明：

> **看到卖家发布说明不等于已经进入发布商品事务。真正发布需要登录账号。**

这也说明 archive 为什么经常只能保存：

```text
公开说明层
+ 登录门槛
```

而保存不了：

```text
登录后的卖家表单
→ 草稿
→ 库存
→ 订单
→ 交易记录
→ 余额
```

这里称为：

**`archive-visible shell / archive-hidden seller state`**。

## 6. 店铺是一组状态，而不只是一个 URL

一个历史卖家的“店”至少可能由以下状态组成：

```text
account id
+ 身份 / 联系资料
+ 店铺名称与装修
+ 商品 listing
+ 当前库存
+ 商品状态（在售 / 下架 / 结束）
+ 价格 / 拍卖状态
+ 买家询问
+ 成交记录
+ 支付 / 余额
+ 发货状态
+ 买卖双方评价
+ 信用等级
+ 搜索 / 推荐位置
```

因此新增：

**`storefront-as-state / 店铺作为状态`**。

一个 HTML 页面只能是这个状态系统在某一时刻的一张投影。

即使某个店铺首页被 Wayback 保存：

```text
storefront HTML captured
!= current inventory captured
!= seller account state captured
!= buyer messages captured
!= transaction state captured
!= balance captured
!= reputation history captured
```

## 7. 信用是历史市场的核心数据结构

2003 注册条款已经明确写到用户可以评价其他用户的信用，并禁止恶意或不正当提高 / 降低信用。

到 2006 年，淘宝调整评价显示 / 计算方式。同期报道记录，有卖家发现信用等级因此下降，并担心生意受到影响。

来源：

- 新浪转载同期报道，2006-01-23，《评价变动橇动“淘友”神经 淘宝：此举保护买家利益》：  
  https://news.sina.com.cn/o/2006-01-23/08358056859s.shtml

**证据等级：B。**

因此历史上的“一个皇冠 / 几颗心 / 一个分数”不能脱离当时算法解释。

这叫：

**`reputation-schema drift / 信用模式漂移`**。

同一批历史交易在不同规则下可能得到不同显示结果。

未来若复原历史店铺，至少需要记录：

- 当时评价是买卖合并还是区分；
- 正 / 中 / 差评如何计分；
- 同一交易是否允许双方分别评价；
- 重复交易如何计分；
- 退款 / 纠纷是否影响；
- 显示等级与原始分数如何映射；
- 规则生效日期；
- 是否回溯影响旧交易。

**不能用今天的信用解释表去解释 2003 / 2006 的历史徽章。**

## 8. “免费开店”与“免费被看见”不是同一件事

### 8.1 2006 “招财进宝”提供了一个极强的同期案例

2006 年 5 月淘宝推出“招财进宝”，卖家可以为推荐位置付费；同期报道描述关键词搜索中出价和成交等因素会影响推荐商品位置。

来源：

- 东方早报 / 新浪，2006-05-30：  
  https://news.sina.com.cn/c/2006-05-30/02459061654s.shtml
- 新京报 / 搜狐，2006-06-02：  
  https://news.sohu.com/20060602/n243524414.shtml
- 上海青年报 / 新浪，2006-06-12：  
  https://tech.sina.com.cn/i/2006-06-12/1032985201.shtml

**证据等级：B。**

同期卖家抗议后，这项服务最终被投票取消。

对于 old-Web archaeology，这比“淘宝曾经有一个收费产品”更重要，因为它证明：

```text
一个 listing 在不在数据库里
```

和

```text
普通买家搜关键词时能不能在前面看到它
```

是两个不同状态。

于是新增：

**`visibility-rule drift / 可见性规则漂移`**。

一个历史搜索结果需要至少知道：

- 索引中有哪些商品；
- 默认排序因素；
- 是否有付费推荐位；
- 推荐位怎样与自然结果混合；
- 是否受成交量 / 信用 / 发布时间影响；
- 是否按地区 / 类目 / 个性化过滤；
- 当天平台规则版本。

只保存一个搜索框，不能恢复历史搜索市场。

## 9. 2013–2014 第一方监管材料：平台状态栈已经非常明确

阿里巴巴 2014 年提交 SEC 的 F-1 对 2013 年淘宝 Marketplace 有详细第一方描述。

来源：

- Alibaba Group Holding Limited, Form F-1, 2014：  
  https://www.sec.gov/Archives/edgar/data/1577552/000119312514184994/d709111df1.htm

其中明确说明：

- 淘宝在 2003 年作为免费平台推出；
- 卖家主要是个人和小企业；
- 卖家需要身份验证；
- 要通过淘宝规则在线考试；
- 要签署诚信承诺；
- 通过个人在线 storefront 发布商品并和买家完成交易；
- 2013 年有约 800 万 active sellers；
- 店铺和 listing 创建免费；
- 平台收入包括卖家购买 P4P、展示广告等营销服务，以及部分店铺软件工具。

**证据等级：A-。** 第一方监管披露适合证明 2013–2014 平台制度结构，不应用来反推 2003 每个字段都相同。

这带出一个很清晰的变化：

```text
2003：开户 + 发布 + 信用规则已经存在
→ 2013：身份验证 + 规则考试 + 诚信承诺 + 店铺工具 + 流量购买形成更完整卖家资格栈
```

`open to everyone` 仍然不能读成：

```text
任何人点一下就能立刻成为可见、可成交卖家
```

## 10. 新的保存缺口：market-state loss

婚恋平台研究里已有 `population-state loss`：恢复搜索表单不等于恢复当时真实候选人群。

Marketplace 有一个相关但更动态的版本：

**`market-state loss / 市场状态丢失`**。

历史市场状态包括：

```text
当时有哪些活跃卖家
哪些 listing 正在出售
剩余库存
当时报价
正在进行的竞拍
搜索结果排序
付费推荐位
卖家信用
买家反馈
成交历史
支付 / 退款 / 纠纷状态
卖家是否在线
```

即使我们恢复：

- 首页；
- 注册页；
- 商品发布说明；
- 搜索表单；

也仍然没有恢复：

> **一个 2003 年用户在那个具体下午真正面对的市场。**

所以：

**`historical marketplace UI recovered != historical marketplace reconstructed`**。

## 11. seller-state loss 与 longitudinal state

对一个卖家而言，最重要的历史不是一张店铺截图，而是长期状态：

```text
2003-08：注册
→ 发布第一件商品
→ 第一次成交
→ 积累评价
→ 店铺分类增加
→ 某次纠纷
→ 评价规则变化
→ 商品排名变化
→ 店铺暂停
→ 重新开店
```

Wayback 很可能偶尔保存某个公开店铺页，却几乎不可能完整保存：

- 卖家后台；
- 每次库存变化；
- 每笔订单；
- 私信 / 旺旺对话；
- 支付余额；
- 评价的时间序列；
- 搜索曝光量；
- 规则变化前后的同一账号状态。

这叫：

**`seller-state loss / 卖家状态丢失`**。

它与自考专题的“纵向账号状态丢失”同属账号状态考古，但这里的状态不仅记录一个人过去做过什么，还会直接改变下一次交易被别人看见和信任的概率。

## 12. 平台规则本身可以重新估值历史劳动

卖家花几个月积累信用、做店铺、获得成交后，平台若改变：

- 信用计算；
- 搜索排序；
- 推荐位收费；
- 类目规则；
- 店铺等级；

则相同的过去交易历史可能得到新的商业价值。

因此：

**`past transaction history != fixed future commercial value`**。

这也是 old-Web 研究为什么应该保存规则版本，而不只是页面视觉。

## 13. 浏览器 / 编码 / 回放假设

本轮已经能在现代 Wayback 文本回放中读取主要中文内容，但以下仍是 unknown：

- 2003 原始 HTTP headers；
- 原始 `Content-Type` / charset 是否在每个 host 一致；
- 当年 IE5/IE6 与其他浏览器布局差异；
- 图片、CSS、JS 是否全部保存；
- Wayback rewrite 是否改变部分 form action；
- 原页面是否依赖 cookie / session；
- 登录后页面是否使用不能被 crawler 取得的参数；
- 表单提交实际服务端校验逻辑。

因此现代回放不能标注为“2003 用户原样看到的页面”。

## 14. 隐私与再发布边界

2003 首页和卖家页会链接到普通用户店铺、商品和联系方式。

本 note 的目标是研究平台结构，所以遵循最小化原则：

- 不批量列出普通历史卖家 ID；
- 不重新发布个人电话、地址、邮箱；
- 不复制完整个人店铺内容；
- 只记录支持平台 claim 所需的字段类型和流程；
- 如未来研究具体店铺，优先使用公开人物 / 机构账号或经去标识的结构信息。

尤其是“贴张海报”模式可能把历史联系方式公开在页面上；archive 可访问不等于今天有研究必要重新放大。

## 15. 已证实 / 高概率 / 不知道

### 已证实

- 2003-07-30 首页可见“免费开户”“创建网上店铺”“搜索店铺”“我要卖”等入口；
- 2003-08-01 注册页保存服务条款；
- 条款明确存在用户名 / 密码、联系方式、交易信息发布和信用评价；
- 2003-08-02 卖家入口提供四种交易方式；
- 其中至少一种明确允许线上发布联系方式、再约线下面谈；
- 具体发布动作可以 302 到登录；
- 2006 年信用规则变化与付费推荐位争议有同期媒体证据；
- 2013 年卖家身份验证、规则考试、诚信承诺以及营销服务有 2014 SEC 第一方证据。

### 高概率，但本轮不继续提高措辞

- 2003 普通卖家实际发布流程包含多个登录后表单；
- 店铺 / 商品搜索已经依赖动态数据库；
- 商品、店铺、信用等公开状态由后台关系数据库或同类服务生成，而非静态 HTML；
- 部分交易在 2003 已经开始从“分类广告式联系”向更平台化成交迁移。

### 不知道

- 2003 创建店铺完整表单字段；
- 2003 身份验证是否、何时强制；
- 2003 信用分具体算法；

## 16. 与 HPL 的交叉解释

对应研究包：

`how-people-lived/sources/individual-business-stalls-online-shops-and-platform-microbusiness-china-1980-2025.zh-CN.md`

两仓交叉后出现一个重要解释：

> **“开网店”是一种生命路线，但它是否真正可执行，取决于 old-Web 层的一组非常具体的状态：账号能否注册、商品能否发布、买家能否搜到、信用如何显示、规则是否改变、交易是否能闭环。**

所以平台研究与生活史不能分开：

```text
页面技术状态
→ 市场可见性
→ 交易机会
→ 收入
→ 是否辞职 / 是否继续副业
→ 家庭空间和未来计划
```

## 19. 本轮新增的最小方法结论

这一轮最值得写进 OWA 的不是“淘宝 2003 长这样”，而是：

> **电子市场的历史对象不是一张网页，而是一个不断变化的市场状态。网页可以被保存，账号、库存、竞拍、信用、排序、余额和买家群却未必被保存。**

因此必须坚持：

```text
homepage captured
!= seller workflow captured

seller workflow captured
!= seller state captured

search form captured
!= historical search result recovered

storefront captured
!= historical market reconstructed
```

对于旧电商，真正消失的常常不是“网页壳”，而是**让那个网页当年具有商业意义的整片活市场**。
