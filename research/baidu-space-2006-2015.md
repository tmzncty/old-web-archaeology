# 百度空间（Baidu Space）2006–2015：首轮考古侦察

> 状态：**research note，不是完整 case**。本轮已获得多个独立 evidence family，可确认上线、主域名、部分 URL/使用形态、移动化与关停迁移；但尚未直接检查足够的 Wayback/Common Crawl capture，因此不能声称已经完成页面级复原。

## 1. 研究对象

- 对象：百度空间（Baidu Space）
- 类型：平台托管博客 / 个人空间，后期带明显 SNS/应用平台特征
- 主要历史 host：`hi.baidu.com`
- 时间范围：2006-07 至 2015-05
- 本轮问题：
  1. 何时上线，`hi.baidu.com` 是否可被同时代证据确认？
  2. 平台如何控制用户 URL？
  3. 2006–2015 间能否确认若干形态变化？
  4. 关停时内容发生了什么？
  5. 目前可以复原到什么程度，缺什么？

## 2. 当前最小结论

### 已证实

1. **2006-07-13，百度官方宣布百度空间正式发布。**
   - 百度现存的 2006 年官方新闻动态明确给出发布日期，并称此前已测试两周。
   - 证据等级：A（平台当时的官方发布材料）。

2. **`hi.baidu.com` 在正式上线前已被同期报道为百度空间域名。**
   - 2006-06-26 的计世网报道（新浪科技转载）记录内测已开始，并明确写出 `HI.baidu.com`，同时预告 7 月 13 日上线。
   - 证据等级：B（近同时代独立媒体）。
   - 与 7 月 13 日百度官方发布材料形成两个不同 evidence family。

3. **百度空间允许用户获得平台控制下的个性化空间 URL，且官方强调 URL 可使用汉字。**
   - 2006-07-13 百度官方发布材料明确提到注册个人空间网址时可以使用汉字。
   - 同期媒体把 `hi.baidu.com` 描述为产品主域名。
   - 因此可安全写成：用户身份 URL 属于百度控制的 `hi.baidu.com` 命名空间，而不是用户自有域名。
   - 不能仅凭这些材料断言所有历史阶段、所有账号都使用完全相同的 path 规则。

4. **2009 年的同时代用户链接表明文章 URL 至少曾存在形如 `http://hi.baidu.com/<account>/blog/item/<id>.html` 的路径结构。**
   - 2009 年百度知道页面中，多名用户直接引用百度空间文章 URL，可用于确认 URL pattern 的存在。
   - 为避免无必要传播普通用户标识，本仓只记录抽象 pattern，不复制账号名。
   - 证据等级：B（同时代用户操作痕迹；非官方规范）。

5. **2010-05-06，百度官方宣布“掌上百度空间版”上线，证明空间服务已进入移动客户端/移动互联网使用场景。**
   - 官方材料称该版本支持登录空间、表达内容、插入表情与个性图标。
   - 证据等级：A。

6. **2013 年仍可由同时代操作教程确认 `http://hi.baidu.com` 是未登录情况下的百度空间首页入口。**
   - 百度经验 2013-11-13 教程直接给出该入口，并描述新版空间的浏览量查看位置。
   - 证据等级：B。

7. **2015-04-07，百度空间宣布关停；4 月 21 日起停止发布/更新，内容于 5 月 7 日迁移到百度云，迁移后博文只对本人可见。**
   - 当天搜狐财经综合报道与天极网等媒体分别记录公告内容；两者可能部分依赖同一官方公告，因此不能简单按 URL 数量当作完全独立的两份事实来源。
   - 2015-04-09/10 的百度经验操作文进一步记录用户在关停窗口内看到迁移提示、进入百度云查看文章的路径，可作为另一类同时代使用痕迹。
   - 证据等级：B。

### 高概率，但本轮不升级为“已证实”

1. **2012 年存在一次显著改版。**
   - 2015 年关停时的多篇回顾都把 2012 改版视为关键节点；但本轮尚未找到并直接核验 2012 当时的官方说明或页面 capture。
   - 证据等级：B/C 边界。
   - 可写“多篇 2015 回顾称 2012 有显著改版”，不能把“失败改版导致关停”写成已证实因果。

2. **2009 年存在 APP 平台/SNS 化扩展。**
   - 2015 同期关停报道与后续资料均提及 2009 APP 平台；但本轮未直接取得 2009 官方发布页或已验证 capture。
   - 暂不把用户规模、峰值在线数等数字纳入硬结论。

### 不知道 / 尚缺证据

- 2006、2009、2012、2015 四个关键时点的首页 DOM/CSS/JS 是否完整保存；
- 2006 早期页面实际声明的字符集（GB2312/GBK/UTF-8 等）与跨页面是否一致；
- 用户自定义 CSS 的权限边界在不同版本如何变化；
- 是否存在 IE-only、ActiveX、Flash 或特定脚本依赖，以及它们对历史呈现的具体影响；
- 2012 改版前后 URL 是否发生稳定、可概括的迁移规则；
- 关停后公开 URL 的 HTTP/跳转行为在 2015–2016 间如何变化；
- Internet Archive、Common Crawl 对静态子资源的保存完整率。

## 5. 平台形态意义

百度空间是一个适合进入 `platform-genealogy` 的案例，因为现有证据已经能看到至少三层变化：

```text
2006：平台托管个人空间 / 博客
  ↓
2009–2010：APP / 社交与移动扩展（部分时点仍待 A 级补证）
  ↓
2015：公开托管空间关闭，用户内容迁入个人云存储并转为仅本人可见
```

这条链条真正值得研究的不是“博客衰落”这种宏大叙事，而是 **URL 与公开性的所有权**：

- 用户可以拥有一个可记忆、可被搜索与外链的 `hi.baidu.com/...` 身份 URL；
- 但 host、页面模板、可见性与最终生命周期仍由平台控制；
- 2015 迁移把原本公开 Web 上可链接的内容转入“只对本人可见”的云端内容，这构成一个明确的 **public URL → private storage** 失踪链候选。

最后一点目前有 2015 同期报道支持，但要写成完整“失踪链”仍需补：关停前 capture、关停后 HTTP 行为、迁移后公开 URL 的返回/跳转证据。

## 6. 浏览器 / 编码 / 插件假设

本轮没有做旧浏览器实验，因此只登记待验证项，不做技术复原：

- 2006 版本可能受到当时 IE 主流环境、中文字体和字符编码影响；
- 2009 年用户教程证明存在明显 CSS 自定义实践，但不能据此推出平台允许任意 CSS 或脚本；
- 若历史页面包含 Flash/ActiveX/特定 JS，现代 Chromium/Wayback replay 可能与当年表现不同；
- 在取得原 HTML/header 前，不猜具体 charset。

建议把百度空间作为 M3 浏览器实验的候选之一，但只有在找到主 HTML + 关键子资源足够完整的 capture 后再执行。

## 7. 可复原程度

当前评级：**结构性复原 2/5；页面级复原 1/5。**

可以较可靠复原：

- 产品存在与时间边界；
- 主 host；
- 一类文章 URL pattern；
- 部分功能/形态变化；
- 关停与“公开空间 → 私有云文章”的迁移政策。

暂时不能可靠复原：

- 2006/2009/2012/2015 各版本的完整视觉页面；
- DOM/CSS/JS 行为；
- 当时真实浏览器渲染；
- 页面资源保存率；
- 2012 改版的具体技术差异。

## 8. 不能声称已经证明的内容

- “2012 改版导致百度空间死亡”；
- “百度空间曾是国内最大 SNS”或任何未取得原始统计口径支持的排名；
- “所有百度空间文章都完整迁移到百度云”；
- “Wayback 已完整保存百度空间”；
- “百度空间主要依赖 IE/ActiveX/Flash”；
- “某种 CSS/URL 规则贯穿 2006–2015 全生命周期”；
- “关停原因是某一单一商业/产品因素”。

## 9. 隐私与版权边界

- 不抓取、提交或重新公开普通用户的历史博文、照片、联系方式；
- 为研究 URL 结构，只记录抽象 pattern，不复制不必要的账号标识；
- 百度官方新闻与媒体报道只保存 citation/metadata/摘要，不镜像全文；
