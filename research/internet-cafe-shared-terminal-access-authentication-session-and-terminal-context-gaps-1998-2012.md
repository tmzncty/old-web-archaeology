# 网吧共享终端：接入地点、实名计费、临时会话与历史浏览环境缺口，1998—2012

## 定位

本笔记属于中文旧网的**访问环境 / runtime context research note**，不是一个 M1 完整平台案例。

它研究的问题不是“某个网站长什么样”，而是：

> **1998—2012 年一个普通用户在网吧里打开旧 Web 时，浏览器之前和浏览器之外还存在什么历史系统？**

与 `how-people-lived` 的生活史交叉研究见：

- <https://github.com/tmzncty/how-people-lived/blob/main/sources/from-internet-cafes-to-pocket-internet-shared-terminal-access-and-terminal-independence-china-1996-2026.zh-CN.md>

本仓 scope 仍保持约 1995—2015 中文互联网；美国 Free-Net 等海外前史只放在 HPL 比较，不把 OWA 扩成全球公共终端史。

---

## 一、为什么旧 Web 不能默认发生在“用户自己的电脑”上

旧网页考古常隐含一个错误模型：

```text
历史用户
→ 自己的 PC
→ 浏览器
→ 网站
```

对于大量 2000s 中国用户，更真实的路径可能是：

```text
历史用户
→ 到网吧
→ 前台 / 身份登记 / 计费
→ 被分配一台共享机器
→ 进入网吧本地桌面 / 菜单 / 管理软件环境
→ 打开浏览器 / QQ / 游戏客户端
→ 再进入网站或平台
```

因此 archive 保存到的 Web 页面只是整套访问系统最后几层之一。

我把这一缺口记作：

## `access-location provenance / 接入地点 provenance`

一个页面 capture 通常无法回答：

- 当年的用户是在家、学校、单位还是网吧打开它；
- 机器是谁的；
- 哪个浏览器/输入法/插件已经预装；
- 用户能否保存文件；
- 是否允许 USB / 软驱 / 光驱；
- 是否存在网吧管理菜单；
- 使用前是否经过前台身份和计费系统；
- session 结束后本地状态是否被清除。

这些差异会直接改变“历史浏览体验”。

## 二、1998：网吧计费软件本身就是旧网运行环境的一层

2003 年 ChinaByte 对飞宇网吧历史的回顾称：

- 飞宇网吧创建于 1997 年；
- 1998 年 8 月成立飞宇软件公司；
- 4 名大学生参与开发网吧计费软件；
- 软件不仅给飞宇加盟店使用，还通过网络销售给其他网吧。

来源：

- ChinaByte / 新浪科技，2003-03-19：
  - https://tech.sina.com.cn/i/c/2003-03-19/1438172614.shtml
  - **B/C：2003 年对 1997—2001 企业历史的近时回顾；可证明计费软件被企业明确当作产品和基础设施，但没有取得原 binary / manual。**

这说明最晚在 1998 年，商业网吧已经存在一类 Web 浏览器之外的本地软件层：

## `pre-browser gate / 浏览器前置门禁`

用户并不一定坐下就直接看到 Windows 桌面或 IE。

一次上机可以先涉及：

```text
顾客身份 / 临时身份
→ 机器号
→ 开始时间
→ 费率
→ 余额 / 现金
→ 结束时间
→ 结算
```

这些状态属于网吧经营系统，不属于访问的网站。

所以：

> **archived website != preserved access transaction**

## 三、2004 南京：一次“上网”被拆成可记录的实名 session

2004 年 9 月南京实名刷卡制的同期报道给出了一条极具体的状态链：

1. 用户到网吧前台；
2. 凭身份证办理上网卡；
3. 每次上网前刷卡；
4. 系统读取身份证信息；
5. 工作人员将持卡人和身份证信息比对；
6. 核验通过才可以使用机器；
7. 外地用户可以凭身份证使用临时卡；
8. 系统记录身份证资料、上网时间和机器号码。

来源：

- 《扬子晚报》，2004-09-30（新浪存续页）：
  - https://tech.sina.com.cn/i/2004-09-30/1119434480.shtml
  - **B：同时代流程报道。**

这使一次网吧访问至少包含两套身份：

### `venue identity / 场所身份`

由身份证、实名卡、临时卡、机器号、上机时间等构成。

### `platform identity / 平台身份`

由 QQ、邮箱、BBS 昵称、游戏账号、博客账号等构成。

二者不能混成一个 identity state。

一个人可以：

```text
以实名卡 A 进入机器 38
→ 在机器上登录匿名 BBS 昵称 B
→ 再登录 QQ 号 C
→ 再访问无需登录的网页 D
```

OWA 以后研究普通用户页面时，不应因为平台上是匿名昵称，就推断当时整个访问路径是匿名的；也不能因为网吧实名，就推断网站自身拥有实名身份。

## 四、2006 合肥：实名、储值、计费和机器使用已经被同一系统联动

2006 年合肥的同时代报道称，全市 659 家网吧安装安全管理和计费软件；上网人员可以使用实名登记卡或临时卡。

实名登记卡：

- 凭有效身份证件办理；
- 可在全市网吧通用；
- 收工本费；
- 具有储值功能。

临时卡：

- 由工作人员刷卡；
- 管理软件弹出登记界面；
- 工作人员核验并录入身份；
- 一张临时卡一次只对应一人次；
- 会话结束后卡可回收复用。

来源：

- 新华网稿 / 新浪科技，2006-11-16：
  - https://tech.sina.com.cn/i/2006-11-16/16331241190.shtml
  - **B：同时代制度与系统流程。**

因此可以建立一个比“打开 IE”更完整的状态模型：

```text
person
↓
credential / ID
↓
venue card or temporary card
↓
front-desk verification
↓
management / billing session
↓
machine assignment
↓
local terminal image
↓
browser / client
↓
remote platform account
↓
logout / session end / payment
```

我把其中不能从 Web archive 恢复的部分称为：

## `venue-session state loss / 场所会话状态丢失`

## 五、制度文本也不能冒充真实使用：实名接口存在执行差异

同一时期媒体已经记录实名制的执行问题。

南京 2004 年报道自身就提到经营者担忧：

- 用户可能借别人的卡；
- 一些经营者可能为了生意放松核验；
- 严格网吧与“黑网吧”之间可能形成执行差异。

2006 年南京媒体走访也记录了实名制度在部分网吧被规避的现象。

来源：

- 2004 南京报道：
  - https://tech.sina.com.cn/i/2004-09-30/1119434480.shtml
- 2006 南京执行调查（新浪新闻存续页）：
  - https://news.sina.com.cn/o/2006-11-11/070710468355s.shtml

证据意义是：

> **documented access rule != observed enforcement**

因此将来如果恢复一个实名管理客户端或政策说明页，只能证明制度/软件设计存在，不能自动证明每次用户 session 都按设计执行。

## 六、共享终端的浏览环境不是一张“干净 Windows + IE6”快照

OWA M3 计划比较 modern Chromium、IE5/IE6、Netscape、Flash/插件环境。

网吧案例提示：这还不够。

一台历史网吧机器的实际环境可能包括：

- Windows 版本；
- IE / 其他浏览器版本；
- 中文输入法；
- QQ / OICQ；
- 游戏客户端；
- Flash / Java / ActiveX；
- 网吧菜单 / launcher；
- 计费客户端；
- 实名/安全管理客户端；
- 恢复卡 / 还原软件；
- 本地代理、缓存或网络策略；
- 特定桌面壁纸 / 广告；
- 分辨率；
- 耳机、摄像头等外设；
- 文件保存和外接存储权限。

所以需要新增：

## `terminal-context loss / 终端环境丢失`

Wayback 可以保存页面，却通常不会保存“这台公共电脑为什么是这个样子”。

## 七、本地 launcher / 菜单意味着“发现网站”之前还有一层场所界面

存续的软件目录记录显示，2006 年存在面向网吧的本地“全系列菜单”软件，提供类似资源管理器的分类菜单，用于组织游戏、工具等本地入口。

来源：

- 中关村在线软件下载目录，`网吧全系列菜单 v2.4`，标注更新时间 2006-03-28：
  - https://xiazai.zol.com.cn/detail/13/122105.shtml
  - **B/C：当前存续的软件目录元数据；可证明软件产品记录存在，不证明普及率。**

2007 年同期商业报道还记录，网吧管理软件公司把电脑桌面壁纸、屏保等位置做成广告资源。

来源：

- 2007 年网吧桌面广告/管理软件行业报道：
  - https://tech.sina.com.cn/i/2007-05-12/09281503642.shtml
  - **B：同时代行业报道。**

这说明历史用户在浏览器之前看到的内容可能已经由场所经营者或管理软件决定。

我把它记作：

## `venue-controlled discovery layer / 场所控制的发现层`

历史 Web 的“入口”可能不是：

```text
Windows desktop → user types URL
```

而是：

```text
网吧本地菜单 / 桌面快捷方式 / 广告 / 默认主页
→ 浏览器
→ 网站
```

这会影响：

- 哪些网站更容易被发现；
- 默认打开什么；
- 用户是否手动输入 URL；
- 广告曝光；
- 游戏/门户/聊天工具的优先级。

archive page 本身无法保存这个上游发现环境。

## 八、共享终端还会把“账号历史”暴露给本地安全环境

2005 年央视相关报道（新浪存续）曾记录金华部分网吧感染窃取游戏账号和密码的恶意软件。

来源：

- CCTV / 新浪新闻，2005：
  - https://news.sina.com.cn/s/2005-06-07/18476873142.shtml
  - **B：同时代安全事件报道。**

这提醒 OWA：一个持久网络账号的历史不能只看服务器端平台。

共享终端可能留下：

- 浏览器 cache；
- cookie；
- history；
- 下载文件；
- 本地聊天记录；
- 自动登录状态；
- 恶意键盘记录；
- 被下一位用户看到的残留信息。

因此：

## `persistent account / transient terminal asymmetry`

网络账号可能连续存在多年，但每一次访问它的本地机器都是临时的、不同的、甚至不可信的。

### 隐私边界

这类历史尤其不应通过寻找真实旧机器残留密码、cookie、QQ 号等方式“复原”。

本仓只研究：

- 软件机制；
- 同时代安全报道；
- 菜单/管理系统；
- synthetic account / synthetic session；
- redacted screenshots / manuals。

**不收集、不测试、不重新公开普通人的历史真实凭证。**

## 九、还原卡 / 系统恢复会改变“本地状态是否能活到下一次”

2007 年面向网吧场景的硬件/恢复卡产品报道把快速还原、数据保护和降低维护成本作为卖点。

来源：

- 太平洋电脑网，2007 年网吧环境恢复卡/数据保护产品介绍：
  - https://diy.pconline.com.cn/cpu/product/0701/950463_1.html
  - **B：同期产品可得性证据；不证明所有网吧都使用。**

如果这种机制存在，一次历史 Web session 的本地状态就可能在重启后被整体抹去。

这产生一个很重要的考古区别：

```text
server-side persistence
和
client-side persistence
不是同一件事
```

BBS 帖子可以一直留在服务器；本地下载、浏览历史、临时文件、用户安装的小工具却可能在机器重启后消失。

所以共享终端环境天然会造成一种：

## `client-side memory discontinuity / 客户端记忆断裂`

它可能影响普通人怎样保存：

- 下载；
- 草稿；
- 网页；
- 联系方式；
- 书签；
- 软件配置。

具体普及程度仍未知，不能把产品存在外推为所有网吧常态。

## 十、Web archive 很容易保存“网站”，却丢掉“为什么这个人能在这里看到它”

对一张 2005 年网页 capture，我们也许能恢复：

- HTML；
- CSS；
- 部分 JS；
- 图片；
- URL；
- charset。

但用户当时的一次真实访问还可能依赖：

```text
网吧营业执照 / 场所存在
→ 用户有资格进入
→ 身份核验
→ 账户余额 / 现金
→ 空闲机器
→ 网吧计费 session
→ 本地 Windows image
→ 本地浏览器 / 插件 / 输入法
→ 外网连通
→ 网站在线
→ 平台账号仍可登录
```

这是一条跨多个系统的 execution chain。

任何一个 archive 都很难完整保存。

因此本轮新增：

## `access-chain invisibility / 接入链不可见`

一个保存很好的网页，并不等于保存了当时普通人取得这张网页的完整条件。

## 十一、对 M3 浏览器实验的直接修改建议

以后如果选择一个 2003—2008 中文站点做旧浏览器复原，建议不要只比较：

```text
modern Chromium
vs
WinXP + IE6
```

至少增加一个“shared-terminal profile”实验假设：

### Profile A — 家庭 PC

- 个人 Windows 用户；
- 可以长期保留 cookie / 文件；
- 自己决定桌面和软件；
- 无前台计费层。

### Profile B — 网吧共享机器

- 计费/管理层先于浏览器；
- 本地软件由经营者预装；
- 可能有 launcher；
- 可能有限制写盘/安装；
- 可能有还原机制；
- 浏览结束后本地状态不可靠；
- 用户必须反复输入持久网络账号。

然后比较同一站点：

- 是否需要安装控件；
- 是否能保存文件；
- 是否能持久保存 cookie；
- 是否能添加书签；
- 登录是否依赖本地组件；
- 中文输入是否一致；
- 下载后的文件能否在下次 session 找回；
- 页面是否被本地安全软件/代理影响。

这比简单“IE6 页面截图”更接近历史访问条件。

## 十二、2008—2009：为什么 OWA 还必须记录“共享终端使用率”

CNNIC 青少年报告显示：

- 2008 年青少年网民过去半年在网吧上网比例 57.5%；农村青少年为 65.4%；
- 2009 年该比例仍有 49.4%；
- 同时 2009 年手机上网比例已经达到 74%。

来源：

- CNNIC 2008—2009 青少年报告：
  - https://www.cnnic.cn/n4/2022/0401/c116-890.html
- CNNIC 2009 青少年报告：
  - https://www.cnnic.cn/n4/2022/0401/c116-907.html
  - **A/Measured：机构调查摘要。**

这意味着 2008—2009 的旧 Web 用户环境不是一个简单年代标签。

同一年里可以同时存在：

- 家庭台式机；
- 学校机房；
- 网吧 WinXP 机器；
- 单位 PC；
- 手机上网。

所以“2009 年用户看到的页面”没有唯一客户端形态。

更准确的研究单位应是：

> **site × time × access context × client environment**

而不只是 `site × time`。

## 十三、平台账号和场所实名卡具有不同寿命

对旧平台来说，还需要加入一个生命周期模型：

```text
场所 session：几十分钟 / 几小时
实名卡：可能重复使用一段时间
网吧会员：可能持续数月 / 数年
QQ / 邮箱 / BBS account：可能持续多年
网站 / 平台：可能持续多年
域名：可能迁移或失效
archive capture：只保存其中某一瞬间
```

所以同一个历史用户连续十年的数字身份，可能穿过数百次彼此完全无关的临时终端 session。

这会改变“个人主页 / SNS 账号”的考古想象：

> 一个长期账号不一定意味着背后有一台长期稳定的个人电脑。

---

## 十四、对旧 Web 统计的一个提醒：访问者的硬件不能从站点硬件要求反推

如果历史站点写：

> “建议使用 IE6 / 1024×768”

它只能证明站点如何规定/建议客户端，不代表用户实际拥有这样的家庭 PC。

共享终端可能让一个买不起高配置电脑的人仍然使用高配置浏览器环境。

反过来，家庭有电脑的人也可能因为：

- 网速；
- 游戏配置；
- 社交；
- 下载速度；
- 需要某个客户端；

选择网吧。

因此：

## `client capability != household ownership`

这是 HPL 的 adoption distinction 在 OWA 客户端史里的直接对应。

## 十五、archive / artifact probe 本轮结果

本轮重点不是建立飞宇的完整平台 case，而是确认“共享终端管理软件这一历史层”是否有足够证据值得进入方法框架。

### 已取得

- 2001—2003 多个同时代/近同时代来源确认飞宇网吧大规模共享终端的存在；
- 2003 近同时代来源明确记录 1998 年飞宇软件公司开发并销售网吧计费软件；
- 2004、2006 同时代报道保存实名卡、临时卡、机器号、上机时间和计费/管理界面的流程；
- 2006 存续软件目录保存网吧本地菜单软件产品 metadata；
- 2007 同时代报道保存桌面/屏保被管理软件用于广告分发的商业结构；
- 2005 同时代安全报道保存共享终端恶意软件窃取持久账号的风险。

### 本轮没有取得

- 一个已核验的 1998—2003 飞宇计费软件 binary；
- 原始 manual；
- 明确稳定的历史软件产品 URL；
- 能实际打开并核验 `capture_datetime + replay/HTTP + DOM + charset + subresources` 的飞宇软件 historical memento；
- 一套已经 provenance-verified 的典型网吧完整 disk image；
- 可证明某一恢复卡/launcher 在全国网吧普及率的材料。

搜索历史飞宇网站/软件域名时，本轮只得到企业/软件存在的文字证据，没有确认一个足以进入 capture probe 的稳定历史 product URL。

因此准确状态是：

```text
historical shared-terminal context: ACHIEVED
contemporaneous billing/auth workflow evidence: ACHIEVED
venue software layer existence: ACHIEVED
verified original management-software artifact: NOT ACHIEVED
verified historical café-software Web capture: NOT ACHIEVED
full terminal image provenance: NOT ACHIEVED
M1 complete case: NOT ACHIEVED
```

## 十七、已证实 / 高概率 / 不知道

### 已证实

- 2000s 网吧访问可以存在独立于 Web 平台的前台身份、计费和机器分配层；
- 一些城市的实名系统记录身份证、上机时间和机器号；
- 网吧本地菜单、桌面广告、计费/安全软件等客户端环境真实存在；
- 同一长期网络账号可以在共享终端上反复登录；
- 2008—2009 共享终端仍是大规模青少年 Internet 接入方式。

### 高概率，但仍需 artifact 验证

- 典型网吧机器的浏览器体验经常受到场所统一镜像、管理软件、输入法/插件预装和本地权限控制影响；
- 恢复卡/还原系统会造成 client-side state 的周期性清除；
- 网吧桌面入口和 launcher 会影响普通用户发现哪些网站/客户端。

### 不知道

- 2003、2005、2008 不同城市“典型网吧机器”的精确软件栈；
- 飞宇 1998 计费软件的产品名、版本号、文件 hash、协议和 UI；
- 不同实名系统是否在浏览器层注入组件或只运行在经营管理层；
- 还原卡、无盘工作站、缓存代理等技术的真实采用率；
- 典型网吧是否允许用户长期存书签、下载、cookie 和聊天日志；
- venue launcher 对 Web 流量/站点发现的实际影响有多大。

## 十八、下一步最有价值的 artifact 任务

不是再写一篇“网吧兴衰史”，而是寻找一套能进入 M3 的、provenance 足够清楚的历史客户端环境：

1. 一张有原始介质/可靠 hash 的 2003—2008 网吧管理或菜单软件；
2. 同时期 Windows XP / IE6 + 常见中文输入法 + QQ / Flash 等版本证据；
3. 一个具有至少两个已核验历史 capture 的中文站点；
4. 在 synthetic account 下比较家庭 PC profile 与 shared-terminal profile。

如果最终找不到完整网吧镜像，也可以正式记录：

> **页面保存得比访问它的公共电脑环境好得多。**

## 本轮方法结论

中文旧 Web 的历史用户并不总是“在自己的电脑上浏览一个网站”。

在网吧里，她首先进入的是一套现实场所：前台、证件、余额、机器号、计费软件、桌面菜单、输入法、浏览器和本地权限；然后才进入 QQ、论坛、邮箱、游戏和网页。

因此历史浏览体验至少要写成：

```text
person
× venue
× access rule
× session
× terminal image
× browser/client
× platform account
× page/capture
```

Wayback 通常只保存最后一两层。

所以未来看到一张完好的 2005 年页面时，我们还应该继续问：

> **当年普通人究竟坐在哪一台机器前，经过什么门槛，才真的看见了它？**
