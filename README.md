# Old Web Archaeology · 中文旧网考古

> 不是再造一个 Wayback Machine，而是研究旧互联网留下了什么、为什么会消失、怎样在证据允许的范围内复原它。

## 项目目标

本项目聚焦约 1995–2015 年的中文互联网，建立可复核的旧网站、平台、页面形态与网络文化考古记录。

重点不是“收集怀旧截图”，而是回答：

- 一个站点/平台在什么时间存在？
- 它依赖什么技术栈、托管方式和浏览器环境？
- 页面、链接结构、交互和社区习惯如何变化？
- 关站、改版、平台迁移后，哪些东西还能从多个档案源拼回来？
- 哪些结论来自原始抓取，哪些来自截图、转述、回忆或后来的复原？

## 明确不做

- 不自研通用网页抓取/回放引擎；
- 不复制 Internet Archive、Webrecorder、ArchiveTeam 已经解决的基础设施；
- 不把“复原页面”伪装成原始页面；
- 不把私人内容、已删除个人信息批量重新公开；
- 不把后来的记忆与当年的一手证据混在一起。

## 研究对象

初期优先：

1. 个人主页与免费主页托管；
2. BBS / 论坛 / Discuz! / PHPWind；
3. 门户网站与频道页；
4. 博客时代：BlogCN、博客大巴、MSN Spaces、门户博客等；
5. 贴吧、早期 SNS、校内/人人式关系网络；
6. Flash、Java Applet、ActiveX、表格布局、帧页面等已经退出主流的网页技术；
7. 域名、ICP备案、镜像站、二级域名和跳转链条形成的“站点谱系”。

## 一条记录至少要有什么

建议每个案例使用 `cases/<slug>/`：

```text
cases/<slug>/
├── README.md          # 人类可读案例说明
├── evidence.yaml      # 证据索引
├── timeline.md        # 时点与版本变化
├── reconstruction.md  # 复原边界、缺失项、推断
└── media/             # 仅保存有权保存的自有/许可素材
```

`evidence.yaml` 建议字段：

```yaml
subject: example.com
observed_at: 2004-06-12
archive_source: internet-archive
capture_url: "..."
original_url: "..."
evidence_type: archived-page   # archived-page / screenshot / manual / recollection / secondary-source
browser_assumption: ie6-win98
confidence: high
notes: "..."
```

## 方法原则

### 1. 证据分层

至少区分：

- **A：原始/同时代证据**：WARC、网页快照、同时代软件/手册、DNS/WHOIS 记录等；
- **B：近同时代二手证据**：新闻、教程、站长文章、论坛讨论；
- **C：后来回忆**：访谈、个人回忆、怀旧文章；
- **D：研究者复原/推断**：必须显式标注。

### 2. 不只存截图

截图能说明视觉，但不能独立证明 DOM、链接、脚本、字符集、请求链或交互行为。

### 3. 浏览器也是史料环境

同一网页在 Netscape、IE5/6、现代 Chromium 下可能完全不同。复原记录应注明浏览器/系统假设。

### 4. 允许“不知道”

旧网存在大量断裂。缺页、图片丢失、脚本缺失、域名复用都应被记录，而不是自动补齐。

## 第一阶段产物

- [ ] `docs/PRIOR_ART.md`：已有保存/回放/旧网博物馆工具盘点；
- [ ] `docs/METHOD.md`：证据等级、引用格式、复原规范；
- [ ] `datasets/sites.csv`：最小站点索引；
- [ ] 3 个完整案例，至少包含两个不同档案源的交叉核验；
- [ ] 一条“个人主页 → 论坛 → 博客 → SNS”的平台形态时间线；
- [ ] 一篇“为什么现代浏览器看到的旧网页，不一定是当年的旧网页”。

## 项目定位

这里最终应更像一个**中文互联网遗址调查队的工作台**：保存证据链、案例、失踪点和复原边界，而不是做一个新的网页存档服务。
